  3. 객체 목록은 vector<Unit>일까요, vector<unique_ptr<Unit>>일까요? 그리고 vector · list · deque 중 무엇일까요?

왜 이걸 하나요

HW2에서는 구조체와 함수로 프로그램 하나를 세웠습니다. 그 뒤 다섯 번의 수업에서 클래스 · 상속과 다형성 · 스마트 포인터 · 컨테이너 · STL 알고리즘을 배웠습니다. 그런데 이것들은 문법을 아는 것만으로는 쓸 수가 없습니다. 어느 자리에 무엇을 쓸지 고르는 일이 남기 때문입니다.

코드는 AI가 몇 초 만에 써 줍니다. 그러면 여러분이 할 일은 무엇일까요? 「메모리를 안전하게 관리해 줘」라고만 하면 AI는 대개 shared_ptr을 줍니다. 돌아가고 새지도 않지만, 11회 ⑤절에서 봤듯이 대부분은 필요 없는 선택입니다. 무엇을 쓸지는 여러분이 정하고, AI에게는 그 결정을 프롬프트로 지시하는 것 — 이것이 이 과제의 알맹이입니다.

이 과제에서 여러분이 하는 일 — 고르고, 고른 것을 프롬프트로 시키고, 이유를 적는 것

프로그램 하나에 설계를 두 단계로 입힙니다. 1단계는 클래스와 상속으로 객체를 세우고, 2단계는 STL(스마트 포인터·컨테이너·알고리즘)을 적용합니다. ① 그 자리에 무엇이 맞을지 고르고, ② 그 선택을 담아 AI에게 시키고, ③ 받은 코드가 시킨 대로인지 확인합니다. 보고서에는 왜 그렇게 골랐는지와 무엇이 바뀌었는지를 적습니다.

무엇을 골라야 할지 모르겠으면 AI에게 먼저 물어봐도 됩니다. 「이 자리에는 무엇이 맞을까? 이유와 함께 추천만 해 줘. 코드는 아직 고치지 마」처럼 물어서 선택지를 받아 보고, 그중 무엇을 고를지는 여러분이 정하면 됩니다. 그렇게 알아 가는 과정도 이 과제의 일부입니다.

2단계 — STL 적용 (C · D · E)

2-1 스마트 포인터는 포인터·참조가 쓰이는 자리마다 먼저 하나를 묻습니다 — 이 자리는 객체를 소유하나, 잠깐 빌려 쓰나? 11회 ⑤절의 고르는 순서를 그대로 쓰면 됩니다.

그 자리는고를 것함수에 넘길 때
소유자가 하나이고, 만든 곳과 갖는 곳이 다르다std::unique_ptr + std::make_unique소유권을 넘기면 f(std::unique_ptr<T> p) + 부르는 쪽 std::move
소유자가 여럿이고, 누가 마지막까지 쓸지 모른다std::shared_ptr + std::make_shared값으로 넘기면 소유자가 하나 는다
소유하지 않고 잠깐 쓴다 — 반드시 있다참조 T & · 읽기만 하면 const T &f(*p)
소유하지 않고 가리킨다 — 없을 수도 있다원시 포인터 T * + nullptr 검사f(p.get())

2-2 컨테이너는 12회 ⑥절의 기준대로 그 자리에서 무슨 일을 자주 하는지로 고릅니다.

그 자리에서 자주 하는 일고를 것
뒤에 넣고, 처음부터 끝까지 돌고, [i]로 꺼낸다std::vector — 기본값. 고민되면 이것
앞에서 뺀다 (뒤에 넣고 앞에서 빼는 대기열)std::deque
중간에 자주 넣고 뺀다 ([i]는 필요 없다)std::list

원소를 값으로 담을지(vector<T>), 포인터로 담을지(vector<unique_ptr<T>>)도 고릅니다. 한 목록에 같은 타입만 담는다면 값으로 담는 쪽이 더 단순하고 빠르니 vector<T>를 씁니다. 파생 클래스 여러 종류를 한 목록에 담을 때만 포인터가 필요합니다 — 왜 그런지는 예시 2단계에서 직접 확인합니다.

#있어야 하는 것수업의 어디
C-1소유하는 자리는 unique_ptr(소유자가 여럿이면 shared_ptr)로, make_unique(make_shared)로 만든다. new·delete를 직접 쓰지 않는다11회 ④
C-2소유권을 넘기는 곳이 하나 이상 있고 거기서 std::move를 쓴다11회 ④
C-3빌려 쓰는 자리는 참조(&·const &) 또는 원시 포인터. 원시 포인터는 nullptr을 먼저 본다11회 ④의 표 · 7회 ⑨
C-4shared_ptr을 썼다면 소유자가 누구누구인지, 안 썼다면 왜 필요 없었는지를 보고서에 적는다. 소유자가 하나뿐이면 안 쓰는 것이 맞는 답이다11회 ⑤
D-1컨테이너를 쓰는 자리 둘 이상. 자리마다 vector·list·deque 중 무엇을 골랐고 다른 둘을 왜 안 골랐는지 적는다. 앞에서 빼거나 중간에서 넣는 자리가 없으면 그런 상황을 하나 더해도 된다12회 ②·⑥
D-2원소 타입 — 값(vector<T>)으로 담았나 포인터(vector<unique_ptr<T>>)로 담았나, 그 이유를 적는다12회 ② · 10회 ③
D-31단계에서 객체마다 한 줄씩 적던 동작을 컨테이너를 도는 for문으로 바꾼다. 범위 for는 const auto &, 돌면서 지우면 it = v.erase(it);12회 ⑤·⑧
E-1STL 알고리즘을 쓰는 곳 둘 이상 — 원래 있던 코드를 바꾼 곳이거나, 쓸 만한 상황을 새로 더한 곳13회 한 장 요약
E-2바꾼 곳은 바꾸기 전 코드를, 더한 곳은 무슨 상황인지를 보고서에 적는다13회 ①~④

2-3 알고리즘은 먼저 지금 코드에서 찾아봅니다. 「가장 가까운 것 찾기」 「조건에 맞는 개수 세기」 「합계 내기」가 이미 있을 가능성이 큽니다. 찾아도 없으면 쓸 만한 상황을 더합니다 — 매 턴 전체 점수의 합을 찍는다, 끝나고 순위를 매긴다처럼요.

1단계 · 클래스와 상속으로 객체화

1-1 요구하는 기능. HW2 예시에는 마린과 질럿뿐이었고 둘의 차이는 능력치 숫자뿐이었습니다. 상속을 쓸 만하게 때리는 방식이 다른 종류를 더하고, 코드 없이 정리만 받았습니다.

HW2에서 만든 마린·질럿 전투를 클래스로 업그레이드하려고 해. 아직 코드는 쓰지 말고 아래 내용을 「객체 구성 / 단일 동작 / 상호 작용」 표로 정리만 해 줘. 등장하는 것은 테란의 마린·파이어뱃, 프로토스의 질럿. 단일 동작은 목표 쪽으로 한 칸 움직이기와 피해를 받아 체력이 주는 것. 상호 작용은 가장 가까운 적에게 다가가 사거리 안이면 공격하는 것인데, 때리는 방식이 종류마다 달라 — 마린은 총 한 발(6), 파이어뱃은 화염(16, 사거리 1), 질럿은 칼 두 번(8×2).
정리된 것내용
객체 구성마린 · 파이어뱃(테란) · 질럿(프로토스) — 셋 다 「유닛」이다
단일 동작목표 쪽으로 한 칸 이동 · 피해를 받아 체력이 준다 — 종류와 상관없이 같다
상호 작용가장 가까운 적에게 다가가 사거리 안이면 공격 — 때리는 방식만 종류마다 다르다

「종류와 상관없이 같다」는 기반 클래스로, 「종류마다 다르다」는 가상 함수로 갑니다. 1-2 클래스 상속 구조는 그대로 시켰습니다.

위 정리대로 HW2 코드를 클래스로 바꿔 줘. Unit을 기반 클래스로 두고 Marine·Firebat·Zealot이 public으로 상속해. 때리는 방식(attack)만 종류마다 다르니까 Unit에 순수 가상 함수로 두고 파생 클래스에서 override 해. 이동·피해 받기·사거리 판단(engage)은 모두 같으니 Unit에 한 번만 둬. Unit의 소멸자는 virtual로. 멤버 변수는 전부 private, 생성자는 멤버 초기화 리스트로, 값을 안 바꾸는 멤버 함수는 const로 해 줘. 클래스 선언은 units.hpp, 함수 내용은 units.cpp에. 유닛은 main의 지역 변수로 하나씩 만들고, 전투도 유닛마다 한 줄씩 적어 줘. 두 유닛 중 가까운 쪽을 고르는 nearer 함수를 만들어 써. 컨테이너와 스마트 포인터는 다음 단계에서 할 거니까 아직 쓰지 마.

Unit * nearer(const Unit & me, Unit * a, Unit * b)
{
  const bool a_ok = a != nullptr && a->is_alive();
  const bool b_ok = b != nullptr && b->is_alive();
  if (!a_ok) return b_ok ? b : nullptr;
  if (!b_ok) return a;
  if (distance(me.pos(), b->pos()) < distance(me.pos(), a->pos())) return b;
  return a;
}

Unit * nearest_enemy(const Unit & me, const Army & enemies)
{
  if (enemies.empty()) return nullptr;
  const auto it = std::min_element(enemies.begin(), enemies.end(),
      [&me](const std::unique_ptr<Unit> & a, const std::unique_ptr<Unit> & b) {
        return distance(me.pos(), a->pos()) < distance(me.pos(), b->pos());
      });
  return it->get();                            // 주소만 빌려준다. 소유권은 진영에 그대로
}

int total_hp(const Army & army)

      [](int sum, const std::unique_ptr<Unit> & u) { return sum + u->hp(); });

#define UNITS_HPP_
#include <deque>
#include <memory>

namespace starcraft {

struct Point {                  // 2차원 위치
  float x;
  float y;
};

// 모든 유닛에 공통인 것. attack 이 순수 가상이라 Unit 으로는 객체를 만들 수 없다
class Unit {
public:
  Unit(const std::string & name, int hp, float range, float speed, Point pos);
  virtual ~Unit();                          // 기반 클래스로 지워도 파생 클래스까지 정리되게

  const std::string & name() const;
  int hp() const;
  bool is_alive() const;
  const Point & pos() const;

  void move_toward(const Point & target);   // 단일 동작 — 목표 쪽으로 한 칸
  void take_damage(int amount);             // 단일 동작 — 체력이 준다
  void engage(Unit * target);               // 상호작용 — 사거리 밖이면 다가가고, 안이면 attack
  virtual void attack(Unit & target) = 0;   // 때리는 방식은 종류마다 다르다

private:
  std::string name_;
  int hp_;                                  // 체력
  float range_;                             // 사거리
  float speed_;                             // 한 프레임에 움직이는 거리
  Point pos_;
};

public:
  Marine(const std::string & name, Point pos);
  void attack(Unit & target) override;
};

public:
  Firebat(const std::string & name, Point pos);

public:
  Zealot(const std::string & name, Point pos);
  void attack(Unit & target) override;
};

// units.cpp — 함수의 내용
#include "units.hpp"
#include <algorithm>
#include <cmath>
#include <iostream>
#include <numeric>

namespace starcraft {

float distance(const Point & a, const Point & b)
{
  const float dx = a.x - b.x;
  const float dy = a.y - b.y;
  return std::sqrt(dx * dx + dy * dy);
}

// ---- Unit — 모든 유닛에 공통인 부분 ----
Unit::Unit(const std::string & name, int hp, float range, float speed, Point pos)
  : name_(name), hp_(hp), range_(range), speed_(speed), pos_(pos)
{
}

Unit::~Unit()
{
  std::cout << "  [" << name_ << " removed]\n";
}

const std::string & Unit::name() const { return name_; }
int Unit::hp() const { return hp_; }
bool Unit::is_alive() const { return hp_ > 0; }
const Point & Unit::pos() const { return pos_; }

void Unit::move_toward(const Point & target)
{
  const float dist = distance(pos_, target);
  if (dist < 0.01f) return;                    // 이미 도착했다
  const float step = std::min(speed_, dist);   // 목표를 지나치지 않는다
  pos_.x += (target.x - pos_.x) / dist * step;
  pos_.y += (target.y - pos_.y) / dist * step;
  std::cout << "  " << name_ << " -> (" << pos_.x << ", " << pos_.y << ")\n";
}

void Unit::take_damage(int amount)
{
  hp_ -= amount;
  if (hp_ < 0) hp_ = 0;
}

void Unit::engage(Unit * target)
{
  if (!is_alive()) return;                     // 죽은 유닛은 아무것도 안 한다
  if (target == nullptr) return;               // 공격할 상대가 없다
  if (!target->is_alive()) return;
  if (distance(pos_, target->pos()) > range_) {
    move_toward(target->pos());                // 사거리 밖이면 다가간다
    return;
  }
  attack(*target);                             // 실제 종류(Marine·Zealot …)의 attack 이 불린다
  if (!target->is_alive()) std::cout << "  " << target->name() << " is KILLED\n";
}

// ---- 파생 클래스 — 능력치와 때리는 방식만 다르다 ----
Marine::Marine(const std::string & name, Point pos) : Unit(name, 40, 4.0f, 1.0f, pos)
{
  std::cout << name << ": You wanna piece of me, boy?\n";
}

void Marine::attack(Unit & target)
{
  target.take_damage(6);
  std::cout << "  " << name() << " shoots " << target.name() << " (hp " << target.hp() << ")\n";
}

Firebat::Firebat(const std::string & name, Point pos) : Unit(name, 50, 1.0f, 1.0f, pos)
{
  std::cout << name << ": Need a light?\n";
}

void Firebat::attack(Unit & target)
{
  target.take_damage(16);
  std::cout << "  " << name() << " burns " << target.name() << " (hp " << target.hp() << ")\n";
}

Zealot::Zealot(const std::string & name, Point pos) : Unit(name, 100, 1.0f, 1.0f, pos)
{
  std::cout << name << ": My life for Aiur!\n";
}

void Zealot::attack(Unit & target)
{
  target.take_damage(8);                       // 칼 두 번
  target.take_damage(8);
  std::cout << "  " << name() << " slashes " << target.name() << " twice (hp " << target.hp() << ")\n";
}

// ---- Barracks ----
Barracks::Barracks(Point rally) : progress_(0), made_(0), rally_(rally)
{
}

void Barracks::train(const std::string & kind)
{
  queue_.push_back(kind);
}

std::unique_ptr<Unit> Barracks::tick()
{
  const int build_frames = 3;                  // 한 기를 만드는 데 걸리는 프레임
  if (queue_.empty()) return nullptr;
  if (++progress_ < build_frames) return nullptr;
  progress_ = 0;
  const std::string kind = queue_.front();     // 맨 앞 것이 먼저 나온다
  queue_.pop_front();
  ++made_;
  const std::string name = kind + "#" + std::to_string(made_);   // 증원은 marine#1 처럼 # 을 붙인다
  if (kind == "firebat") return std::make_unique<Firebat>(name, rally_);
  return std::make_unique<Marine>(name, rally_);
}

// ---- 진영을 다루는 함수 ----
void deploy(Army & army, std::unique_ptr<Unit> unit)
{
  army.push_back(std::move(unit));             // 소유권이 매개변수에서 진영으로 간다
}

void remove_dead(Army & army)
{
  for (auto it = army.begin(); it != army.end(); ) {
    if (!(*it)->is_alive()) {
      it = army.erase(it);                     // unique_ptr 가 사라지며 유닛도 지워진다
    } else {
      ++it;
    }
  }
}

Unit * nearest_enemy(const Unit & me, const Army & enemies)
{
  if (enemies.empty()) return nullptr;
  const auto it = std::min_element(enemies.begin(), enemies.end(),
      [&me](const std::unique_ptr<Unit> & a, const std::unique_ptr<Unit> & b) {
        return distance(me.pos(), a->pos()) < distance(me.pos(), b->pos());
      });
  return it->get();                            // 주소만 빌려준다. 소유권은 진영에 그대로
}

int total_hp(const Army & army)
{
  return std::accumulate(army.begin(), army.end(), 0,
      [](int sum, const std::unique_ptr<Unit> & u) { return sum + u->hp(); });
}

void sort_by_hp(Army & army)
{
  std::sort(army.begin(), army.end(),
      [](const std::unique_ptr<Unit> & a, const std::unique_ptr<Unit> & b) {
        return a->hp() > b->hp();
      });
}

}  // namespace starcraft

// main.cpp — 테란 셋(마린 둘 · 파이어뱃 하나)과 질럿 둘이 만날 때까지 프레임을 돌린다
#include "units.hpp"
#include <iostream>

int main()
{
  using namespace starcraft;
  std::cout.precision(2);
  std::cout << std::fixed;

  // 유닛은 진영(Army)이 소유한다. 만들자마자 진영에 넘긴다
  Army terran;
  Army protoss;
  deploy(terran, std::make_unique<Marine>("marine1", Point{0.0f, 0.0f}));
  deploy(terran, std::make_unique<Marine>("marine2", Point{0.0f, 2.0f}));
  deploy(terran, std::make_unique<Firebat>("firebat", Point{0.0f, 1.0f}));
  deploy(protoss, std::make_unique<Zealot>("zealot1", Point{8.0f, 0.5f}));
  deploy(protoss, std::make_unique<Zealot>("zealot2", Point{8.0f, 1.5f}));

  // 배럭에 증원 셋을 예약해 둔다 — 3프레임마다 하나씩 나온다
  Barracks barracks(Point{-2.0f, 1.0f});
  barracks.train("marine");
  barracks.train("marine");
  barracks.train("firebat");

  const int max_frames = 30;                 // 이보다 오래 끌면 무승부
  for (int frame = 1; frame <= max_frames; ++frame) {
    std::cout << "--- frame " << frame << "  terran " << terran.size() << " (hp " << total_hp(terran)
              << ") vs protoss " << protoss.size() << " (hp " << total_hp(protoss) << ")\n";
    std::unique_ptr<Unit> fresh = barracks.tick();
    if (fresh != nullptr) deploy(terran, std::move(fresh));   // 배럭에서 진영으로 소유권이 간다
    for (const auto & u : terran) {
      u->engage(nearest_enemy(*u, protoss));
      remove_dead(protoss);                  // 죽은 적은 바로 빠진다
    }
    for (const auto & u : protoss) {
      u->engage(nearest_enemy(*u, terran));
      remove_dead(terran);
    }
    if (terran.empty() || protoss.empty()) break;
  }

  std::cout << "terran " << terran.size() << " alive, protoss "
            << protoss.size() << " alive\n";
  sort_by_hp(terran);                        // 살아남은 쪽을 체력 순서로 찍는다
  for (const auto & u : terran) std::cout << "  " << u->name() << " hp " << u->hp() << "\n";
  return 0;
}

AI와 함께 만들 때

코드를 에이전트에게 받아도 됩니다. 1회차의 규칙은 그대로입니다 — 설명하지 못하는 코드는 내지 않습니다. 보고서의 「이유」 칸은 여러분의 말로 적고, 퀴즈는 그 이유에서 나옵니다.

물어보고, 정하고, 시키고, 확인한다

  1. 물어본다 (선택) — 「이 자리에 무엇이 맞을까? 추천만 해 줘. 코드는 아직 고치지 마.」 선택지와 이유를 받아 봅니다.
  2. 정한다 — 받은 추천을 수업 내용과 맞춰 보고 여러분이 고릅니다. 의심스러우면 예시의 vector<Unit>처럼 직접 돌려 확인합니다. 추천과 다르게 골라도 됩니다. 이유가 있으면 됩니다.
  3. 시킨다 — 고른 것을 프롬프트에 이름으로 적습니다. 「안전하게」·「효율적으로」 대신 「unique_ptr로」·「deque로」·「min_element로」. 세부 단계마다 따로 보내도, 한 번에 보내도 됩니다.
  4. 확인한다 — 빌드하고 돌려 보고, 받은 코드가 시킨 대로인지 봅니다. 시키지 않은 것을 바꿨으면 되돌리라고 합니다.

받은 코드에서 먼저 볼 자리

  • 기반 클래스의 소멸자에 virtual이 있는가 — 빠져도 오류가 안 나서 놓치기 쉽습니다 (10회 ⑤)
  • 재정의한 함수에 override가 붙어 있는가 (10회 ④)
  • 파생 클래스 여러 종류를 vector<기반>에 값으로 담지 않았는가 — 잘림은 오류 없이 일어납니다
  • 시키지 않았는데 shared_ptr을 쓰지 않았는가 — 쓰였다면 소유자가 정말 여럿인지 묻습니다 (11회 ⑤)
  • new·delete가 남아 있지 않은가 (11회 ④)
  • 돌면서 지우는 곳에서 erase의 반환값을 받는가 (12회 ⑧)
  • 헤더에 함수 본문이 들어 있지 않은가 — 클래스 안에 짧은 함수를 적어 주는 경우가 많습니다 (9회 ⑦)
