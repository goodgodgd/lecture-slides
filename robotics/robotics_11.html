복사와 이동 — 값을 넘길 때 무슨 일이 일어나나

오늘 답할 질문
  1. 함수에 값을 넘길 때 정확히 무슨 일이 일어나나?
  2. 「복사가 비싸다」는 말은 얼마나 비싸다는 뜻인가?
  3. std::move는 무엇을 옮기나? 옮기고 난 원본은 어떻게 되나?
  4. 반환할 때도 move를 붙이면 더 빨라지나?

실제 회사의 C++ 코드 1천만 줄을 1년간 추적한 연구가 있다. 거기서 나온 항목 중 1위가 오늘 다루는 것이다. AI가 짠 코드는 사람이 짠 코드보다 복사·할당 오버헤드가 1.39배 많았다. 같은 연구에서 정확성·안전성 문제는 오히려 사람의 0.94배였다. 두 숫자를 나란히 놓으면 이 회차의 논지가 나온다. AI는 틀린 코드를 더 많이 만들지 않는다. 둔한 코드를 만든다. 둔한 코드는 컴파일되고, 실행되고, 맞는 답을 낸다. 그래서 아무도 지적하지 않는다.

오늘은 용어 여섯 개를 다룬다. 절마다 먼저 그 문법이 무엇이고 왜 생겼는지를 설명하고, 그다음에 라이다 콜백 하나짜리 작은 프로그램에 그것을 적용한다. 말로 하면 뻔해 보이는 것이라 복사 횟수와 시간을 실제로 잰다. 눈에 안 보이는 차이를 보이게 만드는 장치를 파일에 하나씩 붙여 간다.

한 장 요약 — 학기가 끝나도 이 표만 남으면 된다 🔴 사람이 한다

무엇을 먼저 볼지: 둘째 줄 하나가 오늘의 결론이다. 나머지는 전부 그 줄의 예외다.

용어코드에서 이렇게 보인다이것만 알면 된다
값 전달 (pass by value)void f(T x)함수가 사본을 받는다. 어차피 사본이 필요할 때, 또는 8바이트 이하의 작은 값일 때만
참조 전달 (pass by reference)void f(const T & x)기본값. 읽기만 할 때는 이것. 사본이 안 생기고 원본을 못 고친다는 것이 적혀 있다
복사 생성자T(const T & o)객체가 복사될 때 자동으로 불리는 생성자. 여기에 세는 줄을 넣으면 복사가 보인다
이동 생성자 · 우측값 참조T(T && o) noexcept사본을 새로 만들지 않고 알맹이를 넘겨받는 생성자. &&는 「곧 버려질 값」을 받는 참조다
std::move(x)T b(std::move(a));아무것도 옮기지 않는다. 「a는 이제 안 쓴다」는 표시일 뿐이고, 그 표시를 보고 이동 생성자가 불린다. 표시한 뒤 a를 읽지 않는다
복사 생략 (copy elision)return s;함수 안에서 만든 것을 돌려줄 때 사본도 이동도 안 생긴다. return std::move(s)는 오히려 이것을 막는다
해석: 받은 코드에서 함수 인자를 보고 「이거 왜 const &가 아니지?」를 물을 수 있으면 이 회차는 성공이다. 마지막 줄은 AI가 자주 하는 실수라 따로 넣었다. 좋은 뜻으로 붙인 move가 손해가 되는 유일한 자리다.

① 오늘 만들 것 — 라이다 콜백, AI가 준 그대로 🔴 사람이 한다

무엇을 만드나

라이다가 준 거리 값을 받아 정면 거리를 꺼내는 함수 하나다. 터틀봇3의 라이다는 한 바퀴를 돌면서 360개의 거리 값을 한 묶음으로 보내고, 이 묶음이 초당 5번 이상 들어온다. 중요한 사실이 하나 있다 — 우리는 그 값을 읽기만 한다. 고치지도 않고 보관하지도 않는다.

읽는 법

  • 먼저 AI에게 시켜서 받은 콜백을 그대로 돌린다. 맞는 값이 나온다.
  • ②절부터는 절마다 「개념」이 먼저 온다 — 그 문법이 무엇이고 어떤 문제를 풀려고 생겼는지. 그다음 「예제에 적용」에서 지금 프로그램의 어디가 불편한지를 보고, 그 문법으로 고치거나 재는 장치를 몇 줄 더한다.
  • 고치는 자리는 고치기 전(붉은 테두리)과 고친 뒤(푸른 테두리)를 따로 놓는다. 더하기만 하는 단계는 더한 뒤의 모양만 보인다.
  • 그 아래 📄 「전체 코드」 상자를 누르면 그 단계의 main.cpp 전체가 나온다. 첫 줄 주석에 버전(v1, v2, …)이 있다. 어느 버전을 펼쳐도 그대로 빌드되고 돌아간다.
  • 「실제로 나온 출력」에는 그 절이 새로 찍는 줄만 보인다. 전체 출력은 실습 「성공 화면」에 한 번 있다.
  • 빌드는 CMake다. 오늘은 CMakeLists.txt에 두 줄이 더 있다 — 시간을 재니 최적화를 켜고, ⑤절에서 볼 경고를 켠다.

1단계 (v1) — 값으로 받고, 안에서 또 복사한다

라이다 메시지를 흉내 낸 구조체 ScanMsg와, 「정면 거리를 꺼내 달라」고 AI에게 시켜서 받은 콜백이다. 실제 ROS 2에서는 ScanMsg 자리에 sensor_msgs::msg::LaserScan이라는 긴 이름이 오고, 모양과 성질은 같다.

struct ScanMsg {
  std::vector<float> ranges;   // 거리 값 360개가 들어 있다
};

// AI가 보통 주는 모양 — 값으로 받고, 안에서 또 복사한다
float scan_callback(ScanMsg msg)                       // ① 값으로 받음
{
  std::vector<float> ranges = msg.ranges;              // ② 또 복사
  return ranges.at(0);                                 // 정면 거리
}

int main()
{
  ScanMsg msg;
  msg.ranges = std::vector<float>(360, 1.0f);          // 라이다 한 바퀴를 흉내낸다. 전부 1.0 m
  std::printf("정면 거리 = %.1f m\n", scan_callback(msg));
  return 0;
}

🆕 이 코드에서 처음 나오는 것

원소가 360개이고 전부 1.0으로 채워진 vector다. 여기서는 라이다 한 바퀴의 거리 값이 전부 1.0 m라고 치고 메시지를 채우는 데 썼다.

② 값 전달과 참조 전달 — 읽기만 할 인자는 const &로 받는다 🔴 사람이 한다

개념 — 함수는 인자를 두 가지 방식으로 받는다

값 전달(pass by value)은 void f(T x) 모양이다. 함수가 시작될 때 넘긴 것의 사본이 하나 만들어지고 함수는 그 사본을 쓴다. 부른 쪽의 원본은 그대로다. 7회 ⑤절에서 본 그것이다. 참조 전달(pass by reference)은 void f(T & x) 모양이다. 사본 없이 원본에 다른 이름을 붙여 쓴다. 앞에 const를 붙이면 「원본을 못 고친다」는 약속까지 함수 이름 옆에 적히는 셈이다 — 7회 ⑥절이다.

사본을 만드는 이유는 보통 원본을 건드리지 않고 고치기 위해서다. 읽기만 하는 함수에는 그 이유가 없다. 그러면 언제나 참조가 답인가 — 아니다. 참조도 결국 8바이트짜리 주소를 넘기는 일이라, int·float처럼 그보다 작은 값은 그냥 값으로 넘기는 편이 싸다.

무엇을 먼저 볼지: 첫 줄이 기본값이고 나머지 두 줄은 예외다.

이렇게 받는다언제왜
const T &기본값. 함수가 값을 읽기만 할 때사본이 안 만들어진다. const가 원본을 못 고친다는 것을 보장한다
T (값)어차피 사본이 필요할 때 (보관하거나, 받아서 고쳐 쓸 때).
또는 int·float·bool처럼 8바이트 이하의 값		작은 값은 참조로 받는 것이 오히려 손해다
T &원본을 고쳐야 할 때결과를 인자에 써 넣는 함수다. 부르는 쪽이 값이 바뀔 수 있다는 것을 알아야 하므로 함부로 쓰지 않는다

예제에 적용 — 표시한 두 자리가 전부 사본이다

v1의 이 자리여기서 실제로 일어나는 일
① ScanMsg msg함수가 시작될 때 float 360개짜리 사본이 하나 만들어진다
② std::vector<float> ranges = msg.ranges;그 사본에서 또 360개를 복사한다. 이름을 짧게 쓰려고 한 줄인데 값이 통째로 복제됐다
둘을 합치면메시지 하나가 들어올 때마다 값 720개를 새로 만든다. 초당 5번이면 3,600개다. 그리고 이 함수는 아무것도 고치지 않는다 — 비용만 있고 목적이 없다

2단계 (v2) — 두 자리를 const &로

고치기 전 (v1)
float scan_callback(ScanMsg msg)                       // ① 값으로 받음

// 11회 복사와 이동 — v2 (2단계: const 참조로 받는다)
#include <cstdio>
#include <vector>

struct ScanMsg {
  std::vector<float> ranges;   // 거리 값 360개가 들어 있다
};

// 고친 모양 — 참조로 받고, 별명만 잡는다
float scan_callback(const ScanMsg & msg)               // ① 참조로 받음 — 사본이 없다
{
  const std::vector<float> & ranges = msg.ranges;      // ② 이름표만 하나 더 붙였다
  return ranges.at(0);                                 // 정면 거리
}

int main()
{
  ScanMsg msg;
  msg.ranges = std::vector<float>(360, 1.0f);          // 라이다 한 바퀴를 흉내낸다. 전부 1.0 m
  std::printf("정면 거리 = %.1f m\n", scan_callback(msg));
  return 0;
}
해석: 출력이 v1과 글자 하나 다르지 않다. 7회의 fill_missing은 원본을 고치는 함수라 &가 빠진 것이 출력에 드러났지만, 읽기만 하는 함수는 그렇지 않다. 고친 것이 맞는지 출력으로는 확인할 수 없다. 그래서 이 회차의 나머지는 전부 눈에 안 보이는 차이를 보이게 만드는 장치를 붙이는 일이다.

3단계 (v3) — 기준선 8바이트를 실제로 재 본다

표의 「8바이트」가 어디서 나왔는지 sizeof로 찍는다. 맨 위에 #include <string>을 더하고 main의 정면 거리 줄 아래에 일곱 줄을 넣는다.

  std::printf("\n포인터 하나            : %2zu 바이트\n", sizeof(void *));
  std::printf("int                    : %2zu 바이트\n", sizeof(int));
  std::printf("float                  : %2zu 바이트\n", sizeof(float));
  std::printf("double                 : %2zu 바이트\n", sizeof(double));
  std::printf("std::string            : %2zu 바이트 (+ 글자는 따로)\n", sizeof(std::string));
  std::printf("std::vector<float>     : %2zu 바이트 (+ 값 360개는 따로 %zu 바이트)\n",
              sizeof(std::vector<float>), 360 * sizeof(float));
  std::printf("ScanMsg                : %2zu 바이트 (+ 값 360개는 따로)\n", sizeof(ScanMsg));

🆕 이 코드에서 처음 나오는 것

sizeof(int) · sizeof(void *)
그 타입 하나가 메모리를 몇 바이트 차지하는지다. 컴파일러가 정하는 값이다. void *는 「무엇이든 가리키는 주소」라는 뜻으로, 포인터 하나의 크기를 재는 데 썼다.
%2zu
sizeof가 돌려주는 값(size_t)을 찍는 서식이다. %d가 아니라 %zu를 쓰고, 가운데 2는 두 칸에 맞춰 찍으라는 뜻이다.

③ 복사 생성자 — 복사가 일어날 때 불리는 함수에 세는 줄을 넣는다 🔴 사람이 한다

개념 — 복사도 생성자가 한다

9회에서 생성자는 객체가 만들어질 때 자동으로 불리는 멤버 함수라고 했다. 객체가 다른 객체의 사본으로 만들어질 때 불리는 생성자가 따로 있다 — 복사 생성자(copy constructor)다. 모양은 T(const T & o), 즉 같은 타입을 const 참조로 받는 생성자다. 직접 안 써도 컴파일러가 「멤버를 하나씩 복사하는」 것을 만들어 준다. 손으로 쓰면 그 안에 무엇이든 넣을 수 있다 — 예를 들어 세는 줄 하나.

복사 생성자가 불리는 자리는 세 곳이다. 이 중 첫째가 오늘의 주제다.

④ 이동 — 사본이 정말 필요한데 원본은 다시 안 쓸 때 🔴 사람이 한다

개념 — 이동 생성자와 우측값 참조

const &로 해결되지 않는 경우가 있다. 사본이 정말로 필요한 경우다. 콜백에서 받은 스캔을 클래스 안에 보관해 두고 다음 콜백에서 비교하려면 함수가 끝나도 값이 살아 있어야 한다. 참조는 원본이 사라지면 같이 못 쓴다. 그런데 넘겨주는 쪽이 그 값을 다시 안 쓸 거라면, 알맹이를 새로 만들 이유가 없다. 있는 알맹이의 주인만 바꾸면 된다. 이것이 이동(move)이다.

이동은 이동 생성자(move constructor)가 한다. 모양은 T(T && o)다. &&는 우측값 참조(rvalue reference)로, 「곧 버려질 값」을 받는 참조다. 복사 생성자가 o의 값을 새로 만들어 담는 자리에서, 이동 생성자는 o가 들고 있던 것을 가져오고 o는 비워 둔다. std::vector·std::string은 이동 생성자를 이미 갖고 있어서, 안에 든 값이 360개든 백만 개든 이동은 쪽지(24바이트)만 바꿔 끼우는 일이다.

그러면 컴파일러는 언제 이동 생성자를 고르나. 넘기는 것이 「곧 버려질 값」일 때다. 함수가 돌려준 임시 값이 그렇고, 이름 있는 변수는 아니다 — 변수는 뒤에서 또 쓸 수 있으니까. 이름 있는 변수를 「이제 안 쓴다」고 표시하는 것이 std::move(x)다. 이름과 달리 아무것도 옮기지 않는다. x를 우측값 참조로 바꿔 주는 표시일 뿐이고, 그 표시를 보고 이동 생성자가 불린다. 표시한 뒤의 x는 이동된 객체(moved-from object)다. 부서진 것은 아니지만 무엇이 들어 있는지 정해져 있지 않으므로, 다시 값을 넣기 전에는 읽지 않는다.

무엇을 먼저 볼지: 오른쪽 열의 「원본을 다시 쓰나」가 판단 기준이다.

⑤ 복사 생략 — 반환할 때는 move를 붙이지 않는다 🔴 사람이 한다

개념 — 돌려주는 값은 부른 쪽 자리에 처음부터 만들어진다

함수 안에서 만든 객체를 return하면 복사가 한 번 날 것 같다. 그런데 컴파일러는 그것을 부른 쪽이 받을 자리에 처음부터 만든다. 만들어 놓고 옮기는 것이 아니라 애초에 그 자리에서 만든다. 이 규칙을 복사 생략(copy elision)이라고 하고, 지역 변수를 돌려주는 경우를 특히 반환값 최적화(return value optimization, RVO)라고 부른다. C++17부터 임시 값을 돌려주는 경우에는 표준이 이것을 의무로 정했다.

여기서 AI가 자주 틀린다. 「복사를 피해야 하니까 move를 붙이자」는 판단은 얼핏 ④절과 같아 보이는데, return std::move(s)라고 쓰면 돌려주는 것이 「곧 버려질 임시 값」으로 바뀌면서 복사 생략의 조건에서 벗어난다. 복사가 이동으로 바뀌는 것이 아니라, 없어도 될 이동이 하나 생긴다.

  std::printf("\nstd::move 로 넘기면\n");
  g_copy = g_move = 0;
  ScanMsg tmp;
  ScanMsg taken(std::move(tmp));                       // "가져가라" — 알맹이의 주인이 taken 으로 바뀐다
  std::printf("  복사 %d회, 이동 %d회\n", g_copy, g_move);
  std::printf("  넘겨준 쪽 tmp.ranges.size()   = %zu  ← 껍데기만 남았다. 이제 tmp 를 읽으면 안 된다\n", tmp.ranges.size());
  std::printf("  받은 쪽   taken.ranges.size() = %zu\n", taken.ranges.size());

  std::printf("\n함수에서 만들어 돌려주면\n");
  g_copy = g_move = 0;
  ScanMsg a = make_plain();
  std::printf("  return s;            : 복사 %d회, 이동 %d회  (ranges %zu개)\n", g_copy, g_move, a.ranges.size());

  g_copy = g_move = 0;
  ScanMsg b = make_moved();
  std::printf("  return std::move(s); : 복사 %d회, 이동 %d회  (ranges %zu개)\n", g_copy, g_move, b.ranges.size());
  return 0;
}

📝 연습문제 — 복사가 12회 나는 코드를 0회로 만든다 🟡 맡기되 검사

아래는 스캔을 만들어 정면 값을 찍고 보관하는 프로그램이다. 오늘 배운 것은 하나도 안 들어 있고, 대신 ③절의 세는 장치는 들어 있다. 이대로도 돌아간다 — 다만 마지막 줄에 복사 12회가 찍힌다.

연습문제 — 오늘 문법이 없는 원본 (main.cpp + CMakeLists.txt)

빌드해서 돌리는 법: cmake -S . -B build && cmake --build build && ./build/scan_keeper

main.cpp
// 11회 연습문제 — 최근 스캔 보관기. 오늘 배운 것을 하나도 안 쓴 코드
#include <cstdio>
#include <vector>

int g_copy = 0;   // ScanMsg 가 복사된 횟수

struct ScanMsg {
  std::vector<float> ranges;
  ScanMsg() : ranges(360, 1.0f) {}
  ScanMsg(const ScanMsg & o) : ranges(o.ranges) { ++g_copy; }   // 복사될 때마다 하나 센다
};

// 스캔을 하나 만들어 돌려준다. 정면 값만 v 로 바꾼다
ScanMsg make_scan(float v)
{
  ScanMsg s;
  s.ranges[0] = v;
  return s;
}

// 정면 거리를 꺼낸다
float front_of(ScanMsg msg)
{
  std::vector<float> r = msg.ranges;
  return r.at(0);
}

// 최근 스캔을 보관한다
class Keeper
{
public:
  void add(ScanMsg m) { history_.push_back(m); }
  int size() const { return static_cast<int>(history_.size()); }
private:
  std::vector<ScanMsg> history_;
};

int main()
{
  Keeper keeper;
  for (int i = 0; i < 3; ++i) {
    ScanMsg scan = make_scan(0.5f + 0.1f * i);
    std::printf("정면 %.1f m\n", front_of(scan));
    keeper.add(scan);                    // 이 뒤로 scan 은 다시 쓰지 않는다
  }
  std::printf("보관 %d개, ScanMsg 복사 %d회\n", keeper.size(), g_copy);
  return 0;
}

할 일

이 코드를 오늘 프로그램이 v1에서 v7로 간 것과 같은 길로 고친다. 출력의 앞 세 줄과 「보관 3개」는 같아야 하고, 복사 횟수가 0회가 되어야 한다. 받은 코드에서 아래 항목이 전부 됐는지는 사람이 확인한다.

고칠 것오늘 어디서 했나확인하는 법
front_of가 값으로 받고 안에서 또 복사한다 → const & 둘②front_of 안에 &가 두 군데 있다
ScanMsg에 이동 생성자가 없어서 이동이 전부 복사로 된다 → noexcept 이동 생성자를 더한다④ScanMsg(ScanMsg &&) noexcept가 있다
keeper.add(scan) 뒤로 scan을 안 쓴다 → std::move로 넘기고, add 안에서도 push_back(std::move(m))④std::move가 두 군데 있고, 그 뒤에 scan·m을 읽는 줄이 없다
make_scan의 return은 이미 맞다 — move를 붙이지 않는다⑤빌드에 -Wpessimizing-move 경고가 없다
이 코드에서 불필요한 복사가 나는 자리를 표로 정리한 뒤 고쳐 줘. 읽기만 하는 인자는 const 참조로, ScanMsg에는 noexcept 이동 생성자를 더하고, keeper.add(scan) 뒤로 scan은 안 쓰니 알맹이를 넘겨 줘. 반환문에는 std::move를 붙이지 마. 마지막 줄이 「복사 0회」가 될 때까지 한 항목 고칠 때마다 빌드해서 확인해 줘.

정답은 하나가 아니다. 위 표의 「확인하는 법」이 전부 통과하고 복사가 0회면 된 것이다. 수업 시간에 몇 사람의 결과를 같이 본다.

이럴 때이렇게 말한다
콜백이 메시지를 값으로 받을 때"메시지를 값 말고 const 참조로 받아 줘. 안에서도 새 변수에 복사하지 말고 별칭만 잡아 줘."
코드를 받자마자"이 파일에서 불필요한 복사가 일어나는 자리를 전부 찾아서 표로 정리해 줘. 고치기 전에 어디가 왜 복사인지부터 알려 줘."
보관해야 하는 값이 있을 때"이 변수는 보관한 뒤로 다시 쓰지 않아. 복사하지 말고 알맹이를 넘기도록 고쳐 줘."
반환문에 move가 보일 때"반환문에 std::move를 붙이지 말아 줘. 지역 변수를 그대로 return해 줘."
빌드 파일을 받을 때"CMakeLists.txt에 -Wall을 켜 줘. 경고가 나오면 그대로 보여 줘."
해석: 셋째 줄이 오늘 가장 중요한 프롬프트다. 「빠르게 해 줘」라고 말하지 않았다는 것에 주목한다. 빠르게 해 달라고 하면 AI는 아무 데나 move를 붙인다. 「다시 쓰지 않는다」는 사실을 알려 주면 맞는 자리에만 붙는다. 이 사실은 코드를 짠 사람만 안다.

✅ 오늘의 점검

조금 더 알아두면 시험 범위 아님

이동 생성자에 noexcept를 안 붙이면 생기는 일

std::vector는 자리가 모자라면 더 큰 자리를 새로 잡아 있던 것들을 옮긴다(12회). 옮기는 도중에 예외가 나면 원래 것도 새 것도 성치 않은 상태가 된다. 그래서 표준 라이브러리는 이동 생성자에 noexcept가 붙어 있으면 이동을 쓰고, 없으면 복사를 쓴다. 복사는 실패해도 원본이 멀쩡하기 때문이다. 결과는 이렇다. noexcept 한 단어를 빠뜨리면 이동이 조용히 복사로 바뀐다. 코드는 그대로 돌고 결과도 맞다. 느려질 뿐이다 — 오늘 계속 본 「맞지만 둔한 코드」다.

복사 생성자를 손으로 쓰면 딸려 오는 것들 (다섯 개 규칙)

한 객체에는 복사·이동과 관련된 특수 멤버 함수가 다섯 개 있다 — 복사 생성자, 복사 대입 operator=(const T &), 이동 생성자, 이동 대입 operator=(T &&), 소멸자.

이 중 하나라도 손으로 쓰면 나머지도 같이 생각해야 한다. 하나만 쓰고 나머지를 컴파일러에 맡기면 짝이 안 맞는 일이 생긴다. 오늘 예제에서 = delete로 대입을 막아 둔 것도 그 때문이다. 더 좋은 방법은 다섯 개 전부 안 쓰는 것이다. 값을 std::vector·std::string 같은 표준 컨테이너에 담아 두면 복사·이동·정리를 컨테이너가 알아서 한다. 우리 예제가 그중 셋을 손으로 쓴 것은 횟수를 세기 위해서일 뿐이다.

값으로 받은 뒤 move하는 모양 — explicit Sensor(std::string n) : n_(std::move(n))

④절 표의 「보관해야 하고 원본은 버린다」를 생성자에 적용하면 이 모양이 된다. 인자를 값으로 받고(사본이 어차피 필요하니까) 그것을 멤버로 이동한다. 부르는 쪽이 임시 값을 넘기면 복사 0회, 이름 있는 변수를 넘기면 복사 1회로 끝난다. 12회의 Sensor 생성자가 이 모양이다.

참조로 받으면 항상 이득인가 — 아닌 자리
  • 작은 값 — int·float·bool. 주소를 넘기는 데도 8바이트가 든다.
  • 어차피 사본을 만들 함수 — 받아서 고쳐 쓰거나 보관할 거라면 값으로 받은 뒤 std::move로 넘기는 편이 낫다.
  • 원본이 언제 사라질지 모르는 값 — 다른 스레드나 다음 콜백까지 살아 있어야 하면 사본이 필요하다.
