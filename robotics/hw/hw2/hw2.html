이 과제가 묻는 것
  1. 함수에 & 한 글자가 없으면 무엇이 달라지나요? 빌드는 되는데 결과가 이상한 이유가 거기 있습니다.
  2. 헤더에 함수의 본문까지 적으면, 소스 파일이 둘이 되는 순간 무슨 일이 나나요?
  3. 포인터를 받는 함수는 왜 nullptr인지부터 봐야 하나요?

왜 이걸 하나요

코드를 읽기 위한 최소 장비와 빌드 시스템, 두 수업에서 본 것을 한 프로젝트 안에 전부 넣어 봅니다. 수업에서는 라이다 예제 하나를 아홉 단계로 고쳐 갔습니다. 이번에는 여러분이 고른 주제로 헤더·소스·CMakeLists.txt를 처음부터 만듭니다.

무엇을 만드느냐는 정하지 않습니다. 대신 어떤 요소가 들어가야 하는지와 보고서에 무엇을 적는지는 아래에 자세히 정해 두었습니다. 요소 하나하나가 수업에서 "이게 없으면 이런 일이 난다"를 보였던 자리입니다.

이 과제에서 여러분이 하는 일 — AI가 준 코드를 지적하고 고치는 것

코드를 AI에게 받아도 됩니다. 그러면 여러분이 하는 일은 무엇일까요? 받은 코드를 7·8회에서 배운 것으로 읽고, 어긋난 자리를 짚어 내고, 고치게 하는 것입니다. 헤더에 본문이 들어 있지 않은지, 값으로 받아서 원본이 안 바뀌는 함수는 없는지, 포인터를 nullptr 검사 없이 쓰지 않는지, CMakeLists.txt가 수업에서 본 모양인지 — 수업에서 「이게 없으면 이런 일이 난다」고 본 자리가 그대로 검사 목록이 됩니다.

보고서에는 여러분이 무엇을 지적했고 어떻게 고쳤는지를 따로 정리하고(5절), AI와의 대화 요약을 맨 뒤에 붙입니다(8절). 받은 코드에 지적할 것이 하나도 없는 경우는 드뭅니다 — 찾아보면 대체로 나옵니다.

프로그램의 크기는 작아도 됩니다. 파일 넷(헤더 하나 · 소스 둘 · CMake 하나), 100~150줄이면 충분합니다. 보려는 것은 규모가 아니라 요소 하나하나가 제자리에 있는가와 그것을 여러분의 말로 설명할 수 있는가입니다.

무엇을 만드나요 — 주제는 자유

등장하는 것이 둘 이상 있고, 각자 하는 일이 있고, 서로 주고받는 일이 있는 프로그램이면 무엇이든 좋습니다. 게임 캐릭터, 스포츠 선수, 악기, 로봇, 가게와 손님, 행성과 위성 — 여러분이 좋아하는 것으로 하는 편이 대체로 잘 됩니다.

있어야 하는 것무슨 뜻인가예시(스타크래프트)에서는
등장하는 것 둘 이상같은 종류의 값 묶음이 여럿 있다 — struct와 std::vector가 여기서 나온다마린 둘, 질럿 하나
자체 동작등장하는 것 하나가 자기 상태를 바꾸는 일 — &로 받는 함수목표를 향해 한 칸 움직인다 (move_toward)
상호작용둘 사이에서 한쪽이 다른 쪽을 바꾸는 일 — 상대는 포인터로 받고 nullptr을 먼저 본다사거리 안이면 때린다 (attack)
진행 과정이 보이는 출력단계(프레임·턴·회차)마다 무슨 일이 났는지 찍고, 끝에 결과를 요약한다--- frame 4 / marine1 hits zealot (hp 94) / 마지막 줄에 생존자 수
⚠️ 수업 예제와 아래 예시는 주제로 쓰지 않습니다

「정면 장애물 판정기」(7회) · 「거리 값 평균 mean_range」(8회) · 아래 「마린과 질럿」은 빼고 고릅니다. 이름만 바꾼 것도 같은 것으로 봅니다. 라이다를 소재로 하고 싶으면 다른 문제를 골라 주세요 — 예를 들어 「로봇 둘이 같은 방에서 서로를 피해 다닌다」 같은 것은 괜찮습니다.

친구 것을 베낀 것은 보여 준 사람과 베낀 사람 모두 0점입니다. 주제가 자유인 과제에서 같은 코드가 나오면 바로 보입니다.

예시 — 마린 둘과 질럿 하나

아래는 요구하는 요소를 전부 갖춘 예시입니다. 마린 둘이 질럿 하나에게 다가가 쏘고, 질럿은 가까운 마린에게 달려가 벱니다. 파일 넷, 130줄입니다. 클래스는 아직 안 배웠으니 구조체와 함수만으로 짰습니다.

이 정도면 됩니다. 그런데 여기서 멈출 이유도 없습니다. 유닛 종류를 다섯 개로 늘리고, 체력이 닳으면 후퇴하게 하고, 지형에 따라 속도를 바꾸고, 100프레임 뒤에 누가 이기는지 통계를 내는 것 — 이런 것은 에이전트에게 시키면 몇 분이면 나옵니다. 여러분이 좋아하는 세계를 하나 골라, 그 세계의 규칙을 코드로 옮겨 보세요. 규칙이 재미있을수록 코드도 재미있어집니다.

CMakeLists.txt

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# ① 유닛 규칙을 라이브러리로 묶는다
add_library(units src/units.cpp)
target_include_directories(units PUBLIC include)

# ② 전투를 돌리는 실행 파일에 ①을 붙인다

include/units.hpp — 선언만 있다 
// units.hpp — 유닛의 모양(구조체)과 할 수 있는 일(함수 선언)
#ifndef UNITS_HPP_
#define UNITS_HPP_
#include <string>
#include <vector>

namespace starcraft {

struct Point {                // 2차원 위치
  float x;
  float y;
};

struct Unit {                 // 유닛 하나 = 이름 + 능력치 + 위치
  std::string name;
  int hp;                     // 체력
  int strike;                 // 공격력
  float range;                // 사거리
  float speed;                // 한 프레임에 움직이는 거리
  Point pos;
};

// 유닛을 만든다 — 이름과 위치만 다르고 능력치는 종류마다 정해져 있다
Unit make_marine(const std::string & name, Point pos);
Unit make_zealot(const std::string & name, Point pos);

// 읽기만 하는 함수들 — const & 로 받는다
float distance(const Point & a, const Point & b);
bool  is_alive(const Unit & u);
int   alive_count(const std::vector<Unit> & units);

// 자체 동작 — 유닛 자신을 바꾸므로 & 로 받는다
void move_toward(Unit & u, const Point & target);

// 상호작용 — 공격하는 쪽은 &, 맞는 쪽은 포인터. 상대가 없으면(nullptr) 아무 일도 안 한다
void attack(Unit & attacker, Unit * target);

// 살아 있는 적 중 가장 가까운 것을 가리킨다. 아무도 없으면 nullptr
Unit * nearest_enemy(const Unit & me, std::vector<Unit> & enemies);

}  // namespace starcraft
#endif
src/units.cpp — 함수의 내용 
// units.cpp — 함수의 내용
#include "units.hpp"
#include <cmath>
#include <iostream>

namespace starcraft {

Unit make_marine(const std::string & name, Point pos)
{
  std::cout << name << ": You wanna piece of me, boy?\n";
  return Unit{name, 40, 6, 4.0f, 1.0f, pos};
}

Unit make_zealot(const std::string & name, Point pos)
{
  std::cout << name << ": My life for Aiur!\n";
  return Unit{name, 100, 8, 1.0f, 1.0f, pos};
}

float distance(const Point & a, const Point & b)
{
  const float dx = a.x - b.x;
  const float dy = a.y - b.y;
  return std::sqrt(dx * dx + dy * dy);
}

bool is_alive(const Unit & u)
{
  return u.hp > 0;
}

int alive_count(const std::vector<Unit> & units)
{
  int n = 0;
  for (const auto & u : units) {
    if (is_alive(u)) n++;
  }
  return n;
}

void move_toward(Unit & u, const Point & target)
{
  const float dist = distance(u.pos, target);
  if (dist < 0.01f) return;                    // 이미 도착했다
  const float step = std::min(u.speed, dist);  // 목표를 지나치지 않는다
  u.pos.x += (target.x - u.pos.x) / dist * step;
  u.pos.y += (target.y - u.pos.y) / dist * step;
  std::cout << "  " << u.name << " -> (" << u.pos.x << ", " << u.pos.y << ")\n";
}

void attack(Unit & attacker, Unit * target)
{
  if (target == nullptr) return;               // 공격할 상대가 없다
  if (!is_alive(*target)) return;
  if (distance(attacker.pos, target->pos) > attacker.range) {
    move_toward(attacker, target->pos);        // 사거리 밖이면 다가간다
    return;
  }
  target->hp -= attacker.strike;
  std::cout << "  " << attacker.name << " hits " << target->name
            << " (hp " << target->hp << ")\n";
  if (!is_alive(*target)) std::cout << "  " << target->name << " is KILLED\n";
}

Unit * nearest_enemy(const Unit & me, std::vector<Unit> & enemies)
{
  Unit * best = nullptr;
  float best_dist = 1e9f;
  for (auto & e : enemies) {
    if (!is_alive(e)) continue;
    const float d = distance(me.pos, e.pos);
    if (d < best_dist) {
      best_dist = d;
      best = &e;
    }
  }
  return best;
}

}  // namespace starcraft
src/main.cpp — 유닛을 만들고 프레임을 돌린다 
// main.cpp — 마린 둘과 질럿 하나가 만날 때까지 프레임을 돌린다
#include "units.hpp"
#include <iostream>

int main()
{
  using namespace starcraft;
  std::cout.precision(2);
  std::cout << std::fixed;

  std::vector<Unit> terran{make_marine("marine1", {0.0f, 0.0f}),
                           make_marine("marine2", {0.0f, 2.0f})};
  std::vector<Unit> protoss{make_zealot("zealot", {8.0f, 1.0f})};

  const int max_frames = 30;                 // 이보다 오래 끌면 무승부
  for (int frame = 1; frame <= max_frames; ++frame) {
    std::cout << "--- frame " << frame << "\n";
    for (auto & m : terran) {
      if (is_alive(m)) attack(m, nearest_enemy(m, protoss));
    }
    for (auto & z : protoss) {
      if (is_alive(z)) attack(z, nearest_enemy(z, terran));
    }
    if (alive_count(terran) == 0 || alive_count(protoss) == 0) break;
  }

  std::cout << "terran " << alive_count(terran) << " alive, protoss "
            << alive_count(protoss) << " alive\n";
  return 0;
}

이 예시에서 요소를 찾아보세요. namespace starcraft · 구조체 Point와 Unit · std::vector<Unit>과 for (auto & m : terran) · 자체 동작 move_toward(Unit &, …) · 읽기만 하는 distance(const Point &, …)와 const int max_frames · 상호작용 attack(Unit &, Unit *)의 nullptr 검사 · 헤더에는 선언만. 보고서 3절이 바로 이 일곱 가지를 여러분 코드에서 찾아 적는 자리입니다.

A — 파일 구조와 CMake

폴더 모양은 8회 ③절과 위 예시가 같습니다. 헤더는 include/에, 소스는 src/에 둡니다.

#있어야 하는 것수업의 어디
A-1CMakeLists.txt · include/에 헤더 1개 이상 · src/에 main.cpp와 소스 1개 이상8회 ③
A-2add_library로 라이브러리 하나(main.cpp가 아닌 소스들) + target_include_directories(… PUBLIC include)8회 ③ · ⑥
A-3add_executable로 실행 파일 하나 + target_link_libraries(… PRIVATE …)로 라이브러리를 붙인다8회 ③
A-4CMAKE_CXX_STANDARD 17이 있고, include_directories(…)는 없다8회 ⑤

빌드 명령은 수업 그대로 cmake -S . -B build → cmake --build build → ./build/실행파일입니다. 세 명령의 출력을 그대로 보고서 4절에 붙입니다.

B — 코드에 들어갈 것 여섯

7회 자료의 절 순서 그대로입니다. 보고서 3절에서 요소마다 「어디에 썼고 왜 거기 썼는지」 두 줄과 그 부분의 코드 조각으로 보여 줍니다.

#들어가야 하는 것이렇게 확인합니다수업의 어디
B-1namespace 하나에 여러분의 struct와 함수를 넣는다. 이름은 여러분 세계의 것으로부르는 쪽에 이름::이 보인다7회 ⑧
B-2struct 하나 이상 — 등장하는 것 하나를 값 둘 이상으로 묶는다멤버가 둘 이상이다7회 ⑦
B-3std::vector에 등장하는 것들을 담고, 범위 for와 auto로 돈다for (auto & x : v) 꼴이 있다7회 ③·④
B-4자체 동작 — 원본을 고치는 함수. &로 받는다부른 뒤 부른 쪽의 값이 바뀌어 있다7회 ⑤
B-5읽기만 하는 함수는 const &로 받는다. 그리고 바뀌면 안 되는 지역 변수 하나에 const그 함수 안에서 인자를 고치려 들면 빌드가 막힌다7회 ⑥
B-6상호작용 — 상대를 포인터로 받는 함수. nullptr인지 먼저 보고, ->로 멤버를 꺼낸다nullptr을 넘겨도 죽지 않고 조용히 돌아온다7회 ⑨

🆕 헤더에는 선언만, 내용은 소스에

B-4·5·6의 함수는 선언은 헤더에, 정의(본문)는 소스에 둡니다 (7회 ⑩). 헤더에 본문까지 적으면 소스가 둘이 되는 순간 링크 단계에서 multiple definition이 납니다. AI가 흔히 그렇게 써 주니 받은 코드에서 먼저 볼 자리입니다. 헤더 위아래의 #ifndef·#define·#endif도 빠뜨리지 않습니다.

클래스는 아직 수업에서 안 다뤘습니다. struct와 함수만으로 충분하고, 예시도 그렇게 짰습니다.

AI와 함께 만들 때

코드를 에이전트에게 받아도 됩니다. 오히려 이 과제는 그러라고 있는 과제입니다 — 위 예시보다 훨씬 복잡한 세계를 만들 수 있는 도구가 손에 있으니까요. 다만 1회차의 규칙이 그대로 적용됩니다 — 설명하지 못하는 코드는 내지 않습니다. 보고서의 요소별 설명은 여러분의 말로 적고, 퀴즈는 그 설명에서 나옵니다.

프롬프트는 여러분이 씁니다. 무엇을 등장시키고 각자 무엇을 하고 서로 무엇을 주고받는지, 그리고 A와 B의 요소가 어떤 모양으로 들어가야 하는지를 여러분의 말로 적어서 시킵니다. 한 번에 다 나오지 않아도 됩니다 — 빠진 요소는 다시 시키고, 마음에 안 드는 동작은 고쳐 달라고 하면 됩니다. 그 과정이 그대로 보고서 8절의 대화 요약이 됩니다.

받은 코드는 여러분이 읽고 지적합니다

AI가 준 코드가 그대로 맞는 경우는 드뭅니다. 7·8회에서 「AI가 흔히 하는 실수」로 짚었던 것부터 봅니다.

  • 헤더에 함수 본문이 들어 있지 않은가 (7회 ⑩)
  • CMakeLists.txt에 include_directories가 있지 않은가 (8회 ⑤)
  • 원본을 고쳐야 하는 함수가 & 없이 값으로 받고 있지 않은가 (7회 ⑤)
  • 읽기만 하는 함수에 const &가 빠져 있지 않은가 (7회 ⑥)
  • 포인터를 받는 함수가 nullptr 검사 없이 ->를 쓰지 않는가 (7회 ⑨)
  • 클래스로 짜 오지 않았는가 — 「구조체와 함수로 바꿔 줘」 한마디면 됩니다

그 밖에도 A·B 표와 어긋난 것, 출력이 진행 과정을 안 보여 주는 것, 여러분이 시킨 것과 다르게 만든 것이 있으면 지적 대상입니다. 지적한 것마다 보고서 5절에 소제목을 하나씩 붙여 적습니다 — 무엇이 어떻게 되어 있었고, 수업의 어느 내용에 어긋났고, 어떻게 고쳤는지를 2줄 이상 10줄 이하로. 직접 고쳐도 되고 AI에게 고치라고 해도 됩니다. 어느 쪽이든 찾아낸 것은 여러분이어야 합니다.

세션을 끝내기 전에 — 대화 요약을 받아 둡니다

보고서 맨 뒤 8절에는 AI와 주고받은 대화의 요약을 붙입니다. 직접 정리하지 않아도 됩니다 — 세션을 닫기 전에 아래 글을 그대로 보내면 AI가 정리해 줍니다. 그 출력을 고치지 않고 그대로 8절에 붙여 넣습니다. 세션을 여러 번 열었으면 세션마다 한 번씩 받아 이어 붙입니다. 

이 세션을 끝내기 전에 지금까지의 대화를 아래 규칙대로 정리해 줘.
- 내가 보낸 메시지는 요약하지 말고 순서대로 원문 그대로 적어. 한 글자도 바꾸지 마.
- 네 대답은 중간 과정(탐색·시도·설명·되묻기)을 빼고, 그 요청으로 실제로 만들거나 고친 것만 두세 줄로 요약해.
  만들거나 고친 파일 이름과 함수 이름을 적고, 요청과 다르게 한 것이 있으면 그것도 적어.
- 대화 순서대로 번호를 붙여 아래 형식으로 써. 이 형식 밖의 말은 붙이지 마.

### 1
**나:** (원문 그대로)
**AI:** (구현하거나 수정한 것 요약)

### 2
**나:** …
**AI:** …

여러분이 무엇을 시켰는지가 원문으로 남고, AI가 무엇을 만들었는지가 요약으로 남습니다. 이 둘을 나란히 보면 어디까지가 여러분의 설계이고 어디부터 AI의 손인지 보입니다. 채점은 그 기록이 있느냐를 봅니다 — 내용이 길거나 짧다고 점수가 달라지지는 않습니다. AI를 쓰지 않고 만들었으면 8절에 그렇게 적고, 어떻게 만들었는지 두 줄이면 됩니다.
