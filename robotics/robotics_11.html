복사와 이동 — 값을 넘길 때 무슨 일이 일어나나

오늘 답할 질문
  1. 함수에 값을 넘길 때 정확히 무슨 일이 일어나나?
  2. "복사가 비싸다"는 말은 얼마나 비싸다는 뜻인가?
  3. std::move는 무엇을 옮기나? 옮기고 난 원본은 어떻게 되나?
  4. 반환할 때도 move를 붙이면 더 빨라지나?

실제 회사의 C++ 코드 1천만 줄을 1년간 추적한 연구가 있다. 거기서 나온 항목 중 1위가 오늘 다루는 것이다. AI가 짠 코드는 사람이 짠 코드보다 복사·할당 오버헤드가 1.39배 많았다. 같은 연구에서 정확성·안전성 문제는 오히려 사람의 0.94배였다.

두 숫자를 나란히 놓으면 이 회차의 논지가 나온다. AI는 틀린 코드를 더 많이 만들지 않는다. 둔한 코드를 만든다. 둔한 코드는 컴파일되고, 실행되고, 맞는 답을 낸다. 그래서 아무도 지적하지 않는다. 학생이 검사 목록으로 훑지 않으면 그대로 로봇에 올라간다.

오늘은 그 「둔함」이 어디서 생기는지 딱 하나만 판다. 값을 넘길 때 사본이 만들어진다는 것, 그리고 그 사본이 대부분 아무 이득이 없다는 것이다. 말로 하면 뻔해 보이므로 두 가지 방법으로 실제로 잰다 — 복사 횟수와 시간이다.

오늘 쓰는 코드는 파일 하나다. scan_copy.cpp. AI가 준 스무 줄짜리 콜백에서 시작해서, 절이 넘어갈 때마다 한 곳을 고치거나 재는 장치를 몇 줄 더한다. 본문에는 그 절에서 고치거나 더한 줄만 보이고(초록 바탕이 새 줄, 붉은 취소선이 지운 줄), 그 아래 📄 「전체 코드」 상자를 누르면 그 단계의 파일 전체가 나온다. 어느 단계를 펼쳐도 그대로 빌드되고 돌아간다. 「실제로 나온 출력」에는 그 절이 새로 찍는 줄만 보인다.

한 장 요약 — 학기가 끝나도 이 표만 남으면 된다 🔴 사람이 한다

무엇을 먼저 볼지: 맨 윗줄 하나가 오늘의 결론이다. 나머지 네 줄은 전부 첫 줄의 예외다.

이렇게 쓴다언제수준
void f(const T & x) 기본값. 읽기만 할 때. 고민되면 이것부터 놓는다 [요구]
void f(T x) 어차피 사본이 필요할 때. 또는 int·float처럼 8바이트 이하의 작은 값 [판단]
void f(T & x) 원본을 고쳐야 할 때. 함수가 결과를 인자에 써 넣을 때 [판단]
std::move(x) 사본이 필요하지만 원본을 다시 안 쓸 때. 알맹이만 넘긴다 [요구]
return std::move(x) 쓰지 않는다. 붙이면 오히려 컴파일러의 최적화를 막는다 [요구]
해석: 오늘 외울 것은 첫 줄 하나다. 받은 코드에서 함수 인자를 보고 "이거 왜 const &가 아니지?"를 물을 수 있으면 이 회차는 성공이다. 마지막 줄은 AI가 자주 하는 실수여서 따로 넣었다. 좋은 뜻으로 붙인 move가 손해가 되는 유일한 자리다.

① 라이다 콜백 한 번이 값 720개를 새로 만들고 있다 🔴 사람이 한다

언제 이게 필요해지나

라이다가 준 거리 값을 받아서 앞이 막혔는지를 판단하려고 한다. 터틀봇3의 라이다는 한 바퀴를 돌면서 360개의 거리 값을 한 묶음으로 보낸다. 이 묶음이 초당 5번 이상 들어온다.

여기서 중요한 사실이 하나 있다. 우리는 그 값을 읽기만 한다. 고치지도 않고, 따로 보관하지도 않는다. 읽고 판단하고 버린다.

1단계 — AI가 준 콜백을 그대로 돌려 본다

오늘 쓸 구조체의 이름부터 정해 둔다. 라이다 메시지를 흉내 낸 것이다.

// 11회 — 복사와 이동: 값을 넘길 때 무슨 일이 일어나나
#include <cstdio>
#include <vector>

struct ScanMsg {
  std::vector<float> ranges;   // 거리 값 360개가 들어 있다
};

실제 ROS 2 코드에서는 이 자리에 sensor_msgs::msg::LaserScan이라는 긴 이름이 온다. 모양과 성질은 같다. 오늘은 이름이 짧은 ScanMsg로 쓴다.

그 아래가 "정면 거리를 꺼내 달라"고 AI에게 시켜서 받은 콜백이다.

AI가 보통 주는 코드 🔴
// AI가 보통 주는 모양 — 값으로 받고, 안에서 또 복사한다
float scan_callback(ScanMsg msg)                       // ① 값으로 받음
{
  std::vector<float> ranges = msg.ranges;              // ② 또 복사
  return ranges.at(0);                                 // 정면 거리
}

돌려 보려면 부르는 쪽이 있어야 한다. main에서 라이다 한 바퀴를 흉내낸 메시지를 만들어 넘긴다.

int main()
{
  ScanMsg msg;
  msg.ranges = std::vector<float>(360, 1.0f);          // 라이다 한 바퀴를 흉내낸다. 전부 1.0 m
  std::printf("정면 거리 = %.1f m\n", scan_callback(msg));
  return 0;
}

🆕 이 코드에서 처음 나오는 것

std::vector<float>(360, 1.0f)
원소가 360개이고 전부 1.0으로 채워진 vector를 만든다. 6회에서 ranges(N)으로 칸만 잡았던 것에 채울 값을 하나 더 준 모양이다. 여기서는 라이다 한 바퀴의 거리 값이 전부 1.0 m라고 치고 메시지를 채우는 데 썼다.
ranges.at(0)
몇 번째 값인지를 주고 꺼낸다. 여기서는 정면 방향의 거리를 꺼냈다. 범위를 벗어난 번호를 주면 그 자리에서 오류를 낸다 — 조용히 이상한 값을 주지 않는다. 오늘 뒤에서 그 오류가 실제로 나는 장면을 보게 된다.

제대로 다루는 곳: 12회(컨테이너 — vector·array·reserve)

// 11회 — 복사와 이동: 값을 넘길 때 무슨 일이 일어나나
#include <cstdio>
#include <vector>

struct ScanMsg {
  std::vector<float> ranges;   // 거리 값 360개가 들어 있다
};

// AI가 보통 주는 모양 — 값으로 받고, 안에서 또 복사한다
float scan_callback(ScanMsg msg)                       // ① 값으로 받음
{
  std::vector<float> ranges = msg.ranges;              // ② 또 복사
  return ranges.at(0);                                 // 정면 거리
}

int main()
{
  ScanMsg msg;
  msg.ranges = std::vector<float>(360, 1.0f);          // 라이다 한 바퀴를 흉내낸다. 전부 1.0 m
  std::printf("정면 거리 = %.1f m\n", scan_callback(msg));
  return 0;
}

무엇이 문제인가

이 코드는 컴파일되고, 실행되고, 맞는 값을 낸다. 그래서 코드 리뷰에서 그냥 넘어간다. 문제는 눈에 안 보이는 곳에 있다.

표시한 자리여기서 실제로 일어나는 일
① ScanMsg msg 함수가 시작될 때 float 360개짜리 사본이 하나 만들어진다. 부른 쪽의 원본은 그대로 있고, 함수 안에는 똑같은 것이 하나 더 생긴다
② std::vector<float> ranges = msg.ranges; 그 사본에서 또 360개를 복사한다. 이름을 짧게 쓰려고 한 줄인데 값이 통째로 복제됐다
둘을 합치면 메시지 하나가 들어올 때마다 값 720개를 새로 만든다. 초당 5번이면 초당 3,600개다

그리고 결정적인 것은 이 일이 아무 이득 없이 일어난다는 점이다. 사본을 만드는 이유는 보통 원본을 건드리지 않고 고치기 위해서인데, 이 함수는 아무것도 고치지 않는다. 읽고 버린다. 비용만 있고 목적이 없다.

이렇게 말하면 된다

콜백에서 메시지를 값으로 받지 말고 const 참조로 받아 줘. 안에서 ranges도 새 변수에 복사하지 말고 const 참조로 별칭만 잡아 줘.

2단계 — 함수 한 곳을 고친다

바뀌는 것은 함수 머리 한 줄과 안쪽 한 줄이다. 나머지는 1단계 그대로다.

받은 코드
// 고친 모양 — 참조로 받고, 별명만 잡는다
float scan_callback(ScanMsg msg)                       // ① 값으로 받음
float scan_callback(const ScanMsg & msg)               // ① 참조로 받음 — 사본이 없다
{
  std::vector<float> ranges = msg.ranges;              // ② 또 복사
  const std::vector<float> & ranges = msg.ranges;      // ② 이름표만 하나 더 붙였다
  return ranges.at(0);                                 // 정면 거리
}

실제로 나온 출력

정면 거리 = 1.0 m
해석: 출력이 1단계와 글자 하나 다르지 않다. 7회의 fill_missing은 원본을 고치는 함수라 &가 빠진 것이 출력에 드러났지만, 읽기만 하는 함수는 그렇지 않다. 고친 것이 맞는지 출력으로는 확인할 수 없다. 그래서 이 회차의 나머지는 전부 눈에 안 보이는 차이를 보이게 만드는 장치를 이 파일에 하나씩 붙이는 일이다.
전체 코드 — scan_copy.cpp (2단계 · const & 로 고친 뒤)

쓸 때 / 안 쓸 때 — 이 표가 오늘의 결론이다

무엇을 먼저 볼지: 첫 줄이 기본값이고 나머지 두 줄은 예외다. 예외를 고를 이유가 없으면 첫 줄이다.

이렇게 받는다언제왜
const T & 기본값. 함수가 값을 읽기만 할 때 사본이 안 만들어진다. const가 붙어 있어 원본을 못 고친다는 것이 함수 이름 옆에 적혀 있는 셈이다
T (값) 어차피 사본이 필요할 때 (보관하거나, 받아서 고쳐 쓸 때).
또는 int·float·bool처럼 작은 값		 작은 값은 참조로 받는 것이 오히려 손해다. 참조도 결국 8바이트짜리 주소를 넘기는 일이기 때문이다
T & 원본을 고쳐야 할 때 결과를 인자에 써 넣는 함수다. 부르는 쪽에서 값이 바뀔 수 있다는 것을 알아야 하므로 함부로 쓰지 않는다

기준선은 대략 포인터 하나의 크기, 즉 8바이트다. 이보다 크면 참조를 생각하고, 이보다 작으면 그냥 값으로 받는다. 말로만 하면 감이 안 오므로 실제로 재 봤다.

3단계 — 크기를 찍는 줄을 main에 더한다

맨 위에 #include <string> 한 줄을 더하고(std::string의 크기도 재려고), main의 정면 거리 줄 아래에 일곱 줄을 넣는다.

  std::printf("정면 거리 = %.1f m\n", scan_callback(msg));

  std::printf("\n포인터 하나            : %2zu 바이트\n", sizeof(void *));
  std::printf("int                    : %2zu 바이트\n", sizeof(int));
  std::printf("float                  : %2zu 바이트\n", sizeof(float));
  std::printf("double                 : %2zu 바이트\n", sizeof(double));
  std::printf("std::string            : %2zu 바이트 (+ 글자는 따로)\n", sizeof(std::string));
  std::printf("std::vector<float>     : %2zu 바이트 (+ 값 360개는 따로 %zu 바이트)\n",
              sizeof(std::vector<float>), 360 * sizeof(float));
  std::printf("ScanMsg                : %2zu 바이트 (+ 값 360개는 따로)\n", sizeof(ScanMsg));
  return 0;

🆕 이 코드에서 처음 나오는 것

sizeof(int) · sizeof(void *)
그 타입 하나가 메모리를 몇 바이트 차지하는지 알려 준다. 실행 전에 컴파일러가 정하는 값이다. 여기서는 「8바이트보다 크면 참조」라는 기준선을 실제 숫자로 보려고 썼다. void *는 "무엇이든 가리키는 주소"라는 뜻으로, 포인터 하나의 크기를 재는 데 쓴다.
%2zu
sizeof가 돌려주는 값을 찍는 자리다. %d가 아니라 %zu를 써야 하고, 가운데 2는 두 칸에 맞춰 찍으라는 뜻이다. 여기서는 숫자를 세로로 맞추려고 썼다.

포인터 하나            :  8 바이트

float                  :  4 바이트
double                 :  8 바이트
std::string            : 32 바이트 (+ 글자는 따로)

해석: std::vector<float>가 24바이트라는 것에 속으면 안 된다. 이 24바이트는 「값이 어디 있는지 적어 둔 쪽지」의 크기이고, 실제 값 360개는 따로 1,440바이트를 차지한다. 그리고 복사할 때는 쪽지가 아니라 1,440바이트를 통째로 새로 만든다. int는 4바이트라 8바이트보다 작다 — const int &로 받는 것은 오히려 손해다. 잰 곳: 컨테이너(우분투 24.04.4, g++ 13.3.0 -O2).

② 복사를 세어 보면 1회와 0회다 🔴 사람이 한다

"복사가 일어난다"는 말은 화면에 아무것도 안 뜬다. 그래서 믿기 어렵다. 복사를 눈으로 보는 방법이 하나 있다. 복사가 일어날 때 숫자를 하나 올리게 만드는 것이다.

C++에는 "이 객체가 복사될 때 실행되는 함수"가 있다. 거기에 세는 코드를 한 줄 넣으면 된다. 그 장치를 scan_copy.cpp의 ScanMsg에 붙인다.

4단계 — ScanMsg에 세는 장치를 붙이고, 고치기 전 판을 옆에 되살린다

먼저 구조체다. 세는 변수 하나와 함수 세 줄이 들어간다.

double sink

④ std::move는 "이제 안 쓸 거니 가져가라"는 말이다 🔴 사람이 한다

const &로 해결되지 않는 경우가 있다. 사본이 정말로 필요한 경우다. 콜백에서 받은 스캔을 클래스 안에 보관해 두고 다음 콜백에서 비교하려면, 함수가 끝나도 값이 살아 있어야 한다. 참조는 원본이 사라지면 같이 못 쓰게 된다.

그런데 여기에 조건이 하나 더 붙으면 이야기가 달라진다. 넘겨주는 쪽이 그 값을 다시 안 쓸 거라면, 알맹이를 새로 만들 이유가 없다. 있는 알맹이의 주인만 바꾸면 된다. 그 요청이 std::move다.

6단계 — 이동을 세는 장치를 붙이고 실제로 넘겨 본다

복사를 세는 함수가 있었듯 이동될 때 불리는 함수도 있다. 그것을 ScanMsg에 더한다. 맨 위에는 #include <utility>(std::move가 사는 헤더)가 한 줄 들어간다. 

int g_copy = 0;   // ScanMsg 가 복사된 횟수
int g_move = 0;   // ScanMsg 가 이동된 횟수

struct ScanMsg {
  std::vector<float> ranges;   // 거리 값 360개가 들어 있다

  ScanMsg() : ranges(360, 1.0f) {}                               // 만들 때 360칸을 1.0 m 로 채운다
  ScanMsg(const ScanMsg & o) : ranges(o.ranges) { ++g_copy; }    // 복사될 때 불린다 — 세기만 한다
  ScanMsg(ScanMsg && o) noexcept : ranges(std::move(o.ranges)) { ++g_move; }  // 이동될 때 불린다
  ScanMsg & operator=(const ScanMsg &) = delete;                 // 대입은 오늘 안 센다. 막아 둔다
};

  std::printf("  복사 %d회, 이동 %d회\n", g_copy, g_move);

🆕 이 코드에서 처음 나오는 것

std::move(x)
이름과 달리 아무것도 옮기지 않는다. "이 값은 이제 안 쓸 거니 가져가도 된다"고 표시만 해 준다. 실제로 알맹이를 가져가는 일은 이동 생성자가 한다. 여기서는 taken이 tmp의 360개를 새로 만들지 않고 넘겨받게 하는 데 썼다.
ScanMsg(ScanMsg && o)
이동 생성자다. 꺾쇠 두 개(&&)가 "이건 곧 버려질 임시 값이다"라는 표시다. 복사 생성자와 달리 알맹이를 새로 만들지 않고 가져온다. 안쪽의 std::move(o.ranges)가 vector의 내부 버퍼를 넘겨받는 자리다.
noexcept
"이 함수는 예외를 던지지 않는다"는 약속이다. 이동 생성자에는 거의 항상 붙인다 — 이 약속이 없으면 표준 라이브러리가 안전을 위해 이동 대신 복사를 골라 버린다.
ranges.size()
지금 그 안에 값이 몇 개 들어 있는지 알려 준다. 여기서는 이 숫자가 360에서 0으로 바뀌는 장면을 보려고 썼다 — 그것이 이 회차의 함정이다.

#include <string>

int g_move = 0;   // ScanMsg 가 이동된 횟수

struct ScanMsg {
  std::vector<float> ranges;   // 거리 값 360개가 들어 있다

  ScanMsg() : ranges(360, 1.0f) {}                               // 만들 때 360칸을 1.0 m 로 채운다
  ScanMsg(const ScanMsg & o) : ranges(o.ranges) { ++g_copy; }    // 복사될 때 불린다 — 세기만 한다
  ScanMsg(ScanMsg && o) noexcept : ranges(std::move(o.ranges)) { ++g_move; }  // 이동될 때 불린다
  ScanMsg & operator=(const ScanMsg &) = delete;                 // 대입은 오늘 안 센다. 막아 둔다
};

// 비교하려고 남겨 둔 고치기 전 판 — 값으로 받고, 안에서 또 복사한다

{

}

{

  return ranges.at(0);                                 // 정면 거리
}

해석: 위쪽은 복사도 이동도 0회다. 아무 일도 안 일어났다. 아래쪽은 이동이 1회 생겼다. move를 붙여서 일이 하나 늘었다. 잰 곳: 컨테이너(우분투 24.04.4, g++ 13.3.0 -O2).

// 11회 — 복사와 이동: 값을 넘길 때 무슨 일이 일어나나
#include <cstdio>
#include <vector>
#include <string>
#include <chrono>
#include <utility>       // std::move

int g_copy = 0;   // ScanMsg 가 복사된 횟수
int g_move = 0;   // ScanMsg 가 이동된 횟수

struct ScanMsg {
  std::vector<float> ranges;   // 거리 값 360개가 들어 있다

  ScanMsg() : ranges(360, 1.0f) {}                               // 만들 때 360칸을 1.0 m 로 채운다
  ScanMsg(const ScanMsg & o) : ranges(o.ranges) { ++g_copy; }    // 복사될 때 불린다 — 세기만 한다
  ScanMsg(ScanMsg && o) noexcept : ranges(std::move(o.ranges)) { ++g_move; }  // 이동될 때 불린다
  ScanMsg & operator=(const ScanMsg &) = delete;                 // 대입은 오늘 안 센다. 막아 둔다
};

// 비교하려고 남겨 둔 고치기 전 판 — 값으로 받고, 안에서 또 복사한다
float scan_callback_by_value(const ScanMsg & msg)      // ① 참조로 고쳤다
{
  const std::vector<float> & ranges = msg.ranges;      // ② 이름표만 붙이게 고쳤다
  return ranges.at(0);
}

// 고친 모양 — 참조로 받고, 별명만 잡는다
float scan_callback(const ScanMsg & msg)               // ① 참조로 받음 — 사본이 없다
{
  const std::vector<float> & ranges = msg.ranges;      // ② 이름표만 하나 더 붙였다
  return ranges.at(0);                                 // 정면 거리
}

// 그냥 돌려준다 — 컴파일러가 부를 쪽 자리에 바로 만들어 준다
ScanMsg make_plain()
{
  ScanMsg s;
  return s;
}

// move 를 붙여 돌려준다 — 위의 최적화가 막힌다 (AI가 자주 이렇게 준다)
ScanMsg make_moved()
{
  ScanMsg s;
  return std::move(s);
}

int main()
{
  ScanMsg msg;                                         // 생성자가 360칸을 1.0 m 로 채운다
  std::printf("정면 거리 = %.1f m\n", scan_callback(msg));

  std::printf("\n포인터 하나            : %2zu 바이트\n", sizeof(void *));
  std::printf("int                    : %2zu 바이트\n", sizeof(int));
  std::printf("float                  : %2zu 바이트\n", sizeof(float));
  std::printf("double                 : %2zu 바이트\n", sizeof(double));
  std::printf("std::string            : %2zu 바이트 (+ 글자는 따로)\n", sizeof(std::string));
  std::printf("std::vector<float>     : %2zu 바이트 (+ 값 360개는 따로 %zu 바이트)\n",
              sizeof(std::vector<float>), 360 * sizeof(float));
  std::printf("ScanMsg                : %2zu 바이트 (+ 값 360개는 따로)\n", sizeof(ScanMsg));

  g_copy = 0;
  scan_callback_by_value(msg);
  std::printf("\n값으로 받기      : ScanMsg 복사 %d회  (안쪽 vector 복사는 세지 않았는데도 이만큼이다)\n", g_copy);

  g_copy = 0;
  scan_callback(msg);
  std::printf("const 참조로 받기: ScanMsg 복사 %d회\n", g_copy);

  const int LOOPS = 100000;
  double sink = 0.0;                                   // 결과를 버리면 컴파일러가 계산을 지운다

  g_copy = 0;
  auto t0 = std::chrono::steady_clock::now();
  for (int i = 0; i < LOOPS; ++i) { sink += scan_callback_by_value(msg); }
  auto t1 = std::chrono::steady_clock::now();
  const double v = std::chrono::duration<double, std::milli>(t1 - t0).count();
  const int copies_v = g_copy;

  g_copy = 0;
  t0 = std::chrono::steady_clock::now();
  for (int i = 0; i < LOOPS; ++i) { sink += scan_callback(msg); }
  t1 = std::chrono::steady_clock::now();
  const double r = std::chrono::duration<double, std::milli>(t1 - t0).count();

  std::printf("\n%d회 반복\n", LOOPS);
  std::printf("값으로 받기      : %8.2f ms  (복사 %d회)\n", v, copies_v);
  std::printf("const 참조로 받기: %8.2f ms  (복사 %d회)\n", r, g_copy);
  std::printf("차이             : %.0f배  (sink=%.0f)\n", v / r, sink);

  std::printf("\nstd::move 로 넘기면\n");
  g_copy = g_move = 0;
  ScanMsg tmp;
  ScanMsg taken(std::move(tmp));                       // "가져가라" — 알맹이의 주인이 taken 으로 바뀐다
  std::printf("  복사 %d회, 이동 %d회\n", g_copy, g_move);
  std::printf("  넘겨준 쪽 tmp.ranges.size()   = %zu  ← 껍데기만 남았다. 이제 tmp 를 읽으면 안 된다\n", tmp.ranges.size());
  std::printf("  받은 쪽   taken.ranges.size() = %zu\n", taken.ranges.size());

  std::printf("\n함수에서 만들어 돌려주면\n");
  g_copy = g_move = 0;
  ScanMsg a = make_plain();
  std::printf("  return s;            : 복사 %d회, 이동 %d회  (ranges %zu개)\n", g_copy, g_move, a.ranges.size());

  g_copy = g_move = 0;
  ScanMsg b = make_moved();
  std::printf("  return std::move(s); : 복사 %d회, 이동 %d회  (ranges %zu개)\n", g_copy, g_move, b.ranges.size());
  return 0;
}

무엇을 먼저 볼지: 왼쪽 「이럴 때」를 먼저 읽는다. 상황을 알아보는 것이 문장을 외우는 것보다 먼저다.

이럴 때이렇게 말한다
콜백이 메시지를 값으로 받을 때"메시지를 값 말고 const 참조로 받아 줘. 안에서도 새 변수에 복사하지 말고 별칭만 잡아 줘."
코드를 받자마자"이 파일에서 불필요한 복사가 일어나는 자리를 전부 찾아서 표로 정리해 줘. 고치기 전에 어디가 왜 복사인지부터 알려 줘."
보관해야 하는 값이 있을 때"이 변수는 보관한 뒤로 다시 쓰지 않아. 복사하지 말고 알맹이를 넘기도록 고쳐 줘."
반환문에 move가 보일 때"반환문에 std::move를 붙이지 말아 줘. 지역 변수를 그대로 return해 줘."
빌드 명령을 받을 때"-Wall을 켜서 빌드하는 명령으로 알려 줘. 경고가 나오면 그대로 보여 줘."
해석: 셋째 줄이 오늘 가장 중요한 프롬프트다. "빠르게 해 줘"라고 말하지 않았다는 것에 주목한다. 빠르게 해 달라고 하면 AI는 아무 데나 move를 붙인다. "다시 쓰지 않는다"는 사실을 알려 주면 맞는 자리에만 붙는다. 이 사실은 코드를 짠 사람만 안다.

✅ 오늘의 점검

조금 더 알아두면 시험 범위 아님

왜 return s;에는 복사가 아예 안 생기나 (복사 생략)

C++에는 복사 생략(copy elision)이라는 규칙이 있다. 함수가 돌려주는 값은 부른 쪽이 받을 자리에 처음부터 만들어진다. 만들어 놓고 옮기는 것이 아니라, 애초에 그 자리에서 만든다. 그래서 복사도 이동도 0회다.

C++17부터는 임시 값을 돌려주는 경우에 이 생략이 의무가 됐다. 컴파일러가 마음대로 하는 최적화가 아니라 표준이 그렇게 하라고 정한 것이다. 우리가 쓰는 -std=c++17이 그 표준이다.

std::move를 붙이면 돌려주는 것이 "곧 버려질 임시 값"으로 바뀌면서 이 규칙의 조건에서 벗어난다. 그래서 이동이 하나 생긴다.

이동 생성자에 noexcept를 안 붙이면 생기는 일

std::vector 같은 컨테이너는 자리가 모자라면 더 큰 자리를 새로 잡아 있던 것들을 옮긴다. 옮기는 도중에 오류가 나면 원래 것도 새 것도 성치 않은 상태가 된다.

그래서 표준 라이브러리는 이렇게 정해 두었다. 이동 생성자에 noexcept가 붙어 있으면 이동을 쓰고, 없으면 복사를 쓴다. 복사는 실패해도 원본이 멀쩡하기 때문이다.

결과는 이렇다. noexcept 한 단어를 빠뜨리면 이동이 조용히 복사로 바뀐다. 코드는 그대로 돌아가고 결과도 맞다. 느려질 뿐이다. 오늘 계속 본 "맞지만 둔한 코드"의 전형적인 예다.

복사 생성자를 손으로 쓰면 딸려 오는 것들 (다섯 개 규칙)

한 객체에는 복사·이동과 관련된 함수가 다섯 개 있다.

  • 복사 생성자 — ScanMsg(const ScanMsg &)
  • 복사 대입 — operator=(const ScanMsg &)
  • 이동 생성자 — ScanMsg(ScanMsg &&)
  • 이동 대입 — operator=(ScanMsg &&)
  • 소멸자 — ~ScanMsg()

이 중 하나라도 손으로 쓰면 나머지도 같이 생각해야 한다. 하나만 쓰고 나머지를 컴파일러에 맡기면 짝이 안 맞는 일이 생긴다. 오늘 예제에서 = delete로 대입을 막아 둔 것도 그 때문이다.

더 좋은 방법은 다섯 개 전부 안 쓰는 것이다. 값을 std::vector·std::string 같은 표준 컨테이너에 담아 두면 복사·이동·정리를 컨테이너가 알아서 한다. 우리 예제가 그중 셋을 손으로 쓴 것은 횟수를 세기 위해서일 뿐이고, 평소 코드에서는 하나도 쓸 일이 없다.

참조로 받으면 항상 이득인가 — 아닌 자리

아니다. 세 가지 자리에서는 값으로 받는 것이 맞다.

  • 작은 값 — int(4바이트)·float(4바이트)·bool. 주소를 넘기는 데도 8바이트가 든다. 값보다 주소가 더 크다.
  • 어차피 사본을 만들 함수 — 받아서 고쳐 쓰거나 보관할 거라면 값으로 받은 뒤 std::move로 넘기는 편이 낫다. 참조로 받고 안에서 복사하면 결과가 같고 줄만 는다.
  • 원본이 언제 사라질지 모르는 값 — 참조는 원본이 사라지면 같이 못 쓴다. 다른 스레드나 다음 콜백까지 살아 있어야 하면 사본이 필요하다.

기준선은 오늘 잰 8바이트다. 그보다 크면 참조부터 생각하고, 위 세 가지에 걸리면 값으로 되돌린다.
