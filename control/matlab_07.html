근궤적을 이용한 PID 제어기 설계

오늘 답할 질문
  1. 이득 K 하나만 바꿔서는 왜 원하는 극점에 갈 수 없는 경우가 있나?
  2. PD 제어기의 영점 위치는 어떤 계산으로 정해지나? 그 계산을 MATLAB 코드로 어떻게 옮기나?
  3. PI 제어기의 영점은 왜 원점 가까이에 두나? 가까이 두면 무엇을 잃나?
  4. PID를 넣었더니 stepinfo가 이상한 성능값을 내놓는다. 무엇이 「이상한」 것인가?

6회에서는 성능 사양(최대초과·첨두시간·정착시간)을 s 평면의 경계선으로 바꾸고, 근궤적 위에서 그 영역 안에 드는 이득 K의 범위를 찾았다. 그런데 그 방법에는 전제가 하나 있었다. 근궤적이 원하는 영역을 지나가야 한다는 것이다. 근궤적이 아예 그 영역을 비켜 가면 K를 아무리 바꿔도 사양을 맞출 수 없다.

그럴 때 하는 일이 보상(compensation)이다. 제어기에 영점과 극점을 더해 근궤적의 모양 자체를 바꾼다. 오늘은 PD 제어기로 근궤적을 목표 극점 위로 끌어오고, PI 제어기로 정상상태 오차를 없앤 뒤, 그 결과를 \(K_p, K_i, K_d\) 세 이득으로 읽는다.

계산의 알맹이는 근궤적의 두 조건 — 각도 조건과 크기 조건 — 이다. 5회에서 근궤적을 그릴 때 썼던 바로 그 두 식이 이번에는 제어기를 설계하는 식으로 쓰인다.

왼쪽은 오늘 쓰는 함수, 오른쪽은 그 함수가 설계 절차의 어느 단계인지다. 위에서 아래로 읽으면 설계 순서가 된다.

① 문제 정의 — 개루프 전달함수와 사양

예제는 극점이 셋인 플랜트에 단위 피드백을 건 시스템이다. 이 시스템에 제어기를 붙여 아래 두 사양을 만족시키는 것이 목표다.

무엇값코드의 변수
개루프 전달함수 \(G(s)H(s)\)\(\dfrac{1}{(s+3)(s+5)(s+10)}\)otf (open-loop transfer function)
최대초과(%OS)20% 이하os = 0.20
첨두시간 \(T_p\)0.3초 이하tp = 0.3
clc; clear
% 개루프 전달함수 G(s)H(s)
s = tf('s');
otf = 1/((s+3)*(s+5)*(s+10))
% 최대초과 비율
os = 0.20;
% 첨두시간
tp = 0.3;
% 근궤적 그리기
rlocus(otf)
hold on

명령 창 출력

otf =

              1
  -------------------------
  s^3 + 18 s^2 + 95 s + 150

Continuous-time transfer function.
Model Properties

tf('s')로 라플라스 변수 s를 만들고 곱셈으로 전달함수를 쌓는 것은 4회에서 했다. 분모가 \((s+3)(s+5)(s+10) = s^3 + 18s^2 + 95s + 150\)으로 펼쳐져 찍힌 것을 확인한다. 마지막 줄의 hold on은 이 그림 위에 다음 조각에서 경계선과 목표 극점을 이어 그리기 위한 것이다. 그래서 이 조각만으로는 그림을 남기지 않고, 다음 조각까지 실행한 뒤의 그림을 본다.

② 목표 극점 정하기

사양 두 개를 만족하는 폐루프 극점은 어디에 있어야 하나? 6회에서 2차 시스템의 성능 공식을 거꾸로 풀어 경계선을 그리는 함수 세 개를 만들었다. 그중 최대초과 경계선과 첨두시간 경계선을 그리고, 두 선이 만나는 점을 목표 극점으로 삼는다. 

[zeta, theta] = draw_overshoot_line(os, 'b--');
w_d = draw_peak_time_line(tp, 'r--');
wn = w_d/sqrt(1-zeta^2);
pole_real = -zeta*wn;
pole_imag = w_d;
target_pole = pole_real + 1i*pole_imag;
fprintf('최대초과와 첨두시간을 만족하는 극점의 위치 s = %.4f + j%.4f\n', ...
        pole_real, pole_imag)
plot(pole_real, pole_imag, 'rd')
hold off
axis([-25 5 -15 15])
title('기본 근궤적과 극점 설계')

명령 창 출력

%OS = 20.0%, zeta = 0.4559, theta = 62.87 deg
Tp = 0.3000 s, 허수부 w_d = 10.4720 rad/s
최대초과와 첨두시간을 만족하는 극점의 위치 s = -5.3648 + j10.4720

출력 세 줄을 위에서부터 읽는다. 첫 줄은 draw_overshoot_line이 찍은 것이다 — 최대초과 20%에 해당하는 제동비가 ζ = 0.4559, 그 극점이 음의 실수축과 이루는 각이 62.87°다. 둘째 줄은 draw_peak_time_line이 찍은 것으로, 첨두시간 0.3초가 되려면 극점의 허수부가 10.472여야 한다는 뜻이다. 셋째 줄이 둘을 합친 목표 극점이다.

📐 이론과 잇기 — 목표 극점의 좌표

2차 시스템의 극점은 \(s = -\zeta\omega_n \pm j\omega_n\sqrt{1-\zeta^2}\)이고, 허수부를 \(\omega_d\)라고 부른다. 첨두시간과 최대초과는

$$T_p = \frac{\pi}{\omega_d}, \qquad \%OS = e^{-\zeta\pi/\sqrt{1-\zeta^2}} \times 100$$

이다. 두 식을 ζ와 \(\omega_d\)에 대해 풀고 숫자를 넣는다.

$$\zeta = \frac{-\ln(0.2)}{\sqrt{\pi^2 + \ln^2(0.2)}} = \frac{1.6094}{\sqrt{9.8696 + 2.5903}} = 0.4559$$ $$\omega_d = \frac{\pi}{T_p} = \frac{\pi}{0.3} = 10.4720$$ $$\omega_n = \frac{\omega_d}{\sqrt{1-\zeta^2}} = \frac{10.4720}{\sqrt{1-0.4559^2}} = 11.7662$$ $$\text{실수부} = -\zeta\omega_n = -0.4559 \times 11.7662 = -5.3648$$

코드의 wn·pole_real 두 줄이 정확히 마지막 두 식이다. 출력의 −5.3648 + j10.4720과 같다.

③ 비례 제어의 한계 — 각도 조건

그림만 봐도 근궤적이 마름모를 비켜 가는 것이 보인다. 그런데 「비켜 간다」를 숫자로 확인할 수는 없을까? 5회에서 배운 각도 조건이 그 판정법이다. 어떤 점 \(s_0\)가 근궤적 위에 있으려면 그 점에서 개루프 전달함수의 위상이 −180°(또는 +180°)여야 한다. 

% 비례 제어(K 만 바꾸기)로는 목표 극점에 갈 수 있나? — 목표 극점에서 otf 의 각도를 본다
phase_at_target = rad2deg(angle(evalfr(otf, target_pole)))

명령 창 출력

phase_at_target =

   99.1553

한 줄을 안에서부터 읽는다. evalfr(otf, target_pole)은 4회에서 \(s=0\)을 넣어 정상상태 값을 구할 때 썼던 함수다. 이번에는 s 자리에 복소수인 목표 극점을 넣었다. 결과는 복소수 하나이고, angle이 그 복소수의 각도를 라디안으로, rad2deg가 도로 바꾼다.

99.16°는 −180°와 거리가 멀다. −260.84°와 같은 각도인데(360°를 더하면 99.16°), −180°가 되려면 +80.84°가 모자란다. K는 양의 실수라서 각도를 바꾸지 못한다. 그래서 K만 바꾸는 비례 제어로는 이 극점에 갈 수 없다. 모자란 각도를 채워 줄 무언가가 필요하고, 그것이 영점이다.

📐 이론과 잇기 — 근궤적의 두 조건

단위 피드백 폐루프의 특성방정식은 \(1 + KG(s) = 0\), 곧 \(KG(s) = -1\)이다. 복소수 −1은 크기가 1이고 각도가 180°이므로 이 식은 두 개의 식이다.

$$\angle G(s_0) = (2k+1)\,180^\circ \qquad \text{(각도 조건)}$$ $$K = \frac{1}{|G(s_0)|} \qquad \text{(크기 조건)}$$

각도 조건은 K와 무관하다. 그래서 「이 점이 근궤적 위에 있나」는 각도만으로 판정되고, 위에 있다면 그 점에서의 K는 크기 조건이 알려 준다. 오늘의 설계는 이 순서 그대로다 — 영점으로 각도 조건을 맞추고(④), 크기 조건으로 K를 정한다(⑤).

④ PD 제어기의 영점 — 각도 조건

PD 제어기(비례-미분 제어기)는 \(K(s - z_{pd})\) 꼴이다. 비례 동작 K에 오차의 미분에 비례하는 동작을 더한 것으로, 전달함수로 보면 영점 하나를 더한다. 영점 \(z_{pd}\)에서 목표 극점으로 가는 벡터의 각도만큼 개루프 위상이 늘어나므로, 그 각도가 정확히 80.84°가 되는 자리에 영점을 놓으면 근궤적이 목표 극점을 지나게 된다.

함수 파일 design_pd_controller

이 계산은 함수 파일로 만들어 둔다. 플랜트나 사양이 바뀌어도 같은 계산을 다시 하기 때문이다. 4회에서 함수 파일을 만들 때처럼 파일 이름과 함수 이름을 같게(design_pd_controller.m) 저장하고, 스크립트와 같은 폴더에 둔다.

design_pd_controller.m
function zero_pd = design_pd_controller(otf, target_pole)
% 근궤적이 목표 극점 target_pole 을 지나게 하는 PD 제어기의 영점을 구한다.
% 각도 조건: 목표 극점에서 (PD 영점의 각도) + (otf 의 각도) = -180도
fprintf('\n>>>>> 근궤적이 목표 극점을 지나게 하는 PD 제어기 설계\n')
disp('목표 극점에서의 개루프 전달함수 위상 계산')
phase_G = 0;
zero_otf = zero(otf);
pole_otf = pole(otf);
% 영점에서 목표 극점으로 가는 벡터의 각도는 더한다
for i = 1:length(zero_otf)
    vector = target_pole - zero_otf(i);
    zero_phase = atan2(imag(vector), real(vector));
    phase_G = phase_G + zero_phase;
    fprintf('영점의 위상 angle(s - (%.3f + j%.3f)) = %.3f(deg)\n', ...
            real(zero_otf(i)), imag(zero_otf(i)), rad2deg(zero_phase))
end
% 극점에서 목표 극점으로 가는 벡터의 각도는 뺀다
for i = 1:length(pole_otf)
    vector = target_pole - pole_otf(i);
    pole_phase = atan2(imag(vector), real(vector));
    phase_G = phase_G - pole_phase;
    fprintf('극점의 위상 angle(s - (%.3f + j%.3f)) = %.3f(deg)\n', ...
            real(pole_otf(i)), imag(pole_otf(i)), rad2deg(pole_phase))
end
fprintf('극점 s = %.3f + j%.3f 에서 G(s)의 위상 = %.1f(deg) = %.3f(rad)\n', ...
        real(target_pole), imag(target_pole), rad2deg(phase_G), phase_G)
% PD 영점이 채워야 할 각도: phase_PD + phase_G = -pi
phase_PD = -pi - phase_G;
fprintf('PD 제어기가 가져야할 위상 = %.3f - (%.3f) = %.4f(rad) = %.3f(deg)\n', ...
        -pi, phase_G, phase_PD, rad2deg(phase_PD))
% 목표 극점에서 영점을 바라본 각도가 phase_PD 가 되도록 실수축 위의 점을 고른다
zero_pd = real(target_pole) - imag(target_pole)/tan(phase_PD);
fprintf('PD 제어기의 영점 위치 = %.4f\n', zero_pd)
end

함수는 세 부분으로 읽는다.

  1. 두 개의 for 문 — 개루프 전달함수의 영점과 극점에서 목표 극점으로 가는 벡터를 하나씩 만들고, 그 각도를 영점이면 더하고 극점이면 뺀다. 이것이 \(\angle G(s_0) = \sum \angle(s_0 - z_i) - \sum \angle(s_0 - p_i)\)의 코드 모양이다.
  2. phase_PD = -pi - phase_G — 각도 조건 \(\theta_{pd} + \angle G = -\pi\)를 \(\theta_{pd}\)에 대해 푼 줄이다.
  3. zero_pd = …/tan(phase_PD) — 그 각도가 나오는 실수축 위의 점을 삼각형으로 구하는 줄이다 (아래 📐).

🆕 이 코드에서 처음 나오는 것

theta = atan2(y, x)
점 (x, y)의 각도를 −π~π 라디안으로 돌려준다. atan(y/x)는 x의 부호를 잃어 −90°~90°밖에 내놓지 못하지만, atan2는 x와 y를 따로 받아 네 사분면을 구별한다. 여기서는 영점·극점에서 목표 극점으로 가는 벡터(복소수)의 허수부를 y, 실수부를 x로 넣어 그 벡터의 각도를 구했다. ③에서 쓴 angle에 그 복소수를 넣은 angle(vector)와 같은 값이다.
tan(x)
탄젠트. 입력은 라디안이다. 여기서는 영점에서 목표 극점을 바라본 각도 \(\theta_{pd}\)로부터 「밑변 = 높이 / tan θ」를 계산하는 데 썼다.
fprintf('…%%…')
fprintf의 서식 문자열 안에서 % 글자 자체를 찍으려면 %%로 쓴다. 6회 함수 draw_overshoot_line의 '%%OS = …'가 그 예다.

for·함수 파일은 3회·4회에서 나왔다.

이제 함수를 부른다. 끝에 ;를 붙였으므로 반환값은 찍히지 않고, 함수 안의 fprintf만 찍힌다.

zero_pd = design_pd_controller(otf, target_pole);

📐 이론과 잇기 — 각도를 더하고, 모자란 만큼을 영점으로

목표 극점 \(s_0 = -5.3648 + j10.4720\)에서 세 극점까지의 벡터 각도를 출력에서 읽어 모두 뺀다. 이 플랜트에는 영점이 없어 첫 번째 for 문은 한 번도 돌지 않았다.

$$\angle G(s_0) = -(66.124^\circ + 91.995^\circ + 102.725^\circ) = -260.844^\circ$$

③에서 angle로 구한 99.16°와 같은 각도다(−260.84° + 360° = 99.16°). 각도 조건을 맞추려면

$$\theta_{pd} = -180^\circ - (-260.844^\circ) = 80.845^\circ$$

영점은 실수축 위에 있으므로, 목표 극점에서 수선을 내리면 높이 \(\omega_d = 10.4720\), 밑변 \(x\), 각도 \(\theta_{pd}\)인 직각삼각형이 생긴다.

$$\tan\theta_{pd} = \frac{10.4720}{x} \;\Rightarrow\; x = \frac{10.4720}{\tan 80.845^\circ} = \frac{10.4720}{6.2051} = 1.6877$$ $$z_{pd} = -5.3648 - 1.6877 = -7.0525$$

코드의 real(target_pole) - imag(target_pole)/tan(phase_PD)가 이 두 줄이다. 영점이 목표 극점보다 1.69만큼 왼쪽에 놓인다.

⚠️ 한 번도 돌지 않은 줄의 오타 — 영점이 있는 플랜트에서만 터진다

「영점이 없으면 첫 번째 for 문을 건너뛰자」고 if ~isempty(zero_otf)로 감싸고, 그 안에서 for i = 1:length(zeros_otf)처럼 변수 이름을 살짝 틀리게 쓰기 쉽다(zeros는 MATLAB 함수 이름이기도 해서 손에 붙는다). 이 예제처럼 영점이 없는 플랜트로만 시험하면 if가 그 줄을 건너뛰므로 오류가 한 번도 드러나지 않는다. 영점이 하나라도 있는 플랜트를 넣는 순간 「Unrecognized function or variable 'zeros_otf'」로 멈춘다.

위 함수는 if를 쓰지 않는다. 영점이 없으면 1:0이 빈 범위라 반복이 저절로 0번 돌기 때문이다. 그러면 반복 범위의 줄이 언제나 실행되어, 이름이 틀렸을 때 첫 실행에서 바로 드러난다. 기억해 둘 것은 하나다 — 한 번도 실행되지 않은 줄은 검사되지 않은 줄이다. 연습문제 1번이 이 경로를 실제로 돌려 보는 문제다.

⑤ 이득 K — 크기 조건과 evalfr

영점을 더한 개루프 전달함수 \(G_{pd}(s) = (s + 7.0525)\,G(s)\)는 이제 각도 조건상 목표 극점을 지난다. 그 점에서 K가 얼마여야 하는지는 크기 조건이 알려 준다. 코드에서는 크기 조건과 각도 조건을 따로 쓰지 않고 \(KG_{pd}(s_0) = -1\)을 K에 대해 그대로 푼다. 

% PD 제어기를 반영한 근궤적
otf_pd = otf * (s - zero_pd)
K_pd = -1/evalfr(otf_pd, target_pole);
K_pd = real(K_pd);
fprintf("PD 제어기 적용 후 target pole에서의 상수 이득 K=%1.4f\n", K_pd)
rlocus(otf_pd)
hold on
plot(real(target_pole), imag(target_pole), 'rd')
hold off
title('PD 보상 후 근궤적')
axis([-25 5 -15 15])

K_pd = -1/evalfr(otf_pd, target_pole)이 \(K = -1/G_{pd}(s_0)\)이다. 각도 조건이 정확히 맞았다면 \(G_{pd}(s_0)\)는 음의 실수이고 K는 양의 실수로 나온다. 실제로는 목표 극점의 좌표를 소수점에서 자른 오차 때문에 허수부가 아주 조금 남을 수 있어서, 다음 줄에서 real로 실수부만 남긴다.

📐 이론과 잇기 — 크기 조건을 손으로

크기 조건 \(K = 1/|G_{pd}(s_0)|\)을 벡터 길이로 쓰면 「극점까지 거리의 곱 ÷ 영점까지 거리의 곱」이다.

$$K = \frac{|s_0+3|\,|s_0+5|\,|s_0+10|}{|s_0+7.0525|} = \frac{10.7357 \times 10.4784 \times 11.4520}{10.6071} = 121.45$$

출력의 K=121.4518과 같다. 거리 네 개는 각도를 구할 때 쓴 벡터들의 길이(abs(vector))다 — 같은 벡터의 각도와 길이를 각각 각도 조건과 크기 조건에 쓴 것이다.

📐 이론과 잇기 — 0형 시스템의 정상상태 오차

개루프 \(K_{pd}G_{pd}(s)\)에는 원점 극점이 없다(0형). 4회의 위치 오차 상수 \(K_p\)로 정상상태 값을 구하면

$$K_p = \lim_{s\to0} K_{pd}G_{pd}(s) = \frac{121.45 \times 7.0525}{150} = 5.710$$ $$y(\infty) = \frac{K_p}{1+K_p} = \frac{5.710}{6.710} = 0.851, \qquad e(\infty) = \frac{1}{1+K_p} = 0.149$$

출력의 steady = 0.8510과 같다. 이 오차를 0으로 만들려면 개루프에 원점 극점(적분기)이 있어야 한다 — 그것이 PI 제어기다.

⑦ PI 제어기의 영점 — 원점 가까이

PI 제어기(비례-적분 제어기)는 \(\dfrac{s - z_{pi}}{s}\) 꼴로, 원점 극점 하나와 영점 하나를 더한다. 원점 극점이 1형 시스템을 만들어 계단 입력의 정상상태 오차를 0으로 만든다.

그런데 극점과 영점을 더하면 근궤적의 모양이 또 바뀌어서, 애써 맞춘 목표 극점을 벗어날 수 있다. 그래서 영점을 원점 바로 옆(−0.01)에 둔다. 목표 극점에서 보면 원점과 −0.01은 거의 같은 자리라서, 두 벡터의 각도가 거의 같고 서로 상쇄된다. 근궤적의 모양이 목표 극점 근처에서는 거의 바뀌지 않는다. 

zero_pi = -0.01;
fprintf('PI 제어기의 영점 위치 선택: %.2f\n', zero_pi)
% PID 제어기를 반영한 근궤적
otf_pid = otf_pd * (s - zero_pi) / s
rlocus(otf_pid)
hold on
plot(real(target_pole), imag(target_pole), 'rd')
fprintf('target pole에서의 상수이득:')
K = -1/evalfr(otf_pid, target_pole)
% K 값은 양의 실수여야 하므로 실수부만 사용함
K = real(K)
mark_closed_pole(K*otf_pid)
hold off
axis([-25 5 -15 15])
title('PID 보상 후 근궤적')

📐 이론과 잇기 — 극점·영점 거의 상쇄와 느린 꼬리

폐루프 극점 −0.0085와 영점 −0.01은 거의 붙어 있다. 이런 쌍은 부분분수 전개에서 계수(유수)가 작은 항을 만든다. 응답은 대략 「빠른 부분 + 느린 꼬리」로 나뉜다.

$$y(t) \approx \underbrace{0.85 + (\text{빠른 진동})}_{\text{PD 때와 거의 같은 응답}} \; + \; \underbrace{0.15\,\bigl(1 - e^{-0.0085\,t}\bigr)}_{\text{느린 꼬리}}$$

꼬리의 시정수는 \(1/0.0085 \approx 118\)초다. 남은 몫 0.15가 2% 띠(0.02) 아래로 줄어드는 시간은 \(0.15\,e^{-t/118} = 0.02\)에서 \(t = 118 \ln(0.15/0.02) = 118 \times 2.01 = 238\)초 — 600초짜리 출력의 SettlingTime: 235.46과 거의 같다. 100초에서 \(y = 0.9366\)인 것도 꼬리 식으로 맞춰 볼 수 있다: \(0.85 + 0.15(1 - e^{-0.85}) = 0.85 + 0.15 \times 0.573 = 0.936\).

0.85라는 숫자는 ⑥의 PD 정상상태 값 0.851이다. PI 영점을 원점 가까이 둔 덕에 빠른 부분은 PD 때와 거의 같고, PD가 남긴 오차 0.149를 느린 꼬리가 아주 천천히 메운다.

이제 처음의 18.4%가 설명된다. stepinfo(tf_total)처럼 시스템을 넘기면 stepinfo가 스스로 시뮬레이션 구간을 고르는데, 이 시스템에서는 그 구간이 10초 정도에서 끝난다(같은 시스템에 step(tf_total)을 기본값으로 부르면 9.7초에서 끝난다). 그 구간 끝에서 응답은 아직 0.86 근처다. 18.4%를 거꾸로 풀면 \(1.0322 / 1.1845 = 0.871\) — 성능값이 1이 아니라 0.87쯤을 기준으로 계산된 셈이다. 정착시간 2.05초도 같은 기준에서 나온 숫자다. 최종값 1을 직접 주고 긴 구간으로 다시 재면 최대초과 3.2%, 정착시간 235초가 된다.

해석: 어느 쪽이 「맞는」 숫자인가는 무엇을 보려는지에 달렸다. 사람이 느끼는 응답 — 0.3초 만에 솟았다가 1초 안에 가라앉는 모양 — 은 PD 설계 그대로다. 다만 1에 완전히 붙는 데에는 몇 분이 걸린다. PI 영점을 원점에 가까이 둘수록 빠른 부분은 덜 흐트러지지만 꼬리는 더 느려진다. 이 맞바꿈은 연습문제 2에서 숫자로 확인해 본다.

⚠️ 사양선을 그릴 기준값 — 단계마다 다시 구한다

성능선 peak = steady * (1+os)를 그릴 때 작업공간에 남아 있는 steady를 그대로 쓰기 쉽다. 그러면 PD 단계(⑥)에서 구한 0.851을 기준으로 선이 그려진다. PID 루프의 최종값은 1이므로 위 코드에서는 steady = dcgain(tf_total)로 다시 구했다. PD 단계의 0.851로 그린 선은 「빠른 부분」을 보는 데에는 오히려 잘 맞는다 — 위 해석의 두 관점이 그대로 두 기준값이다. 어느 값을 기준으로 그린 선인지는 그림 제목이나 주석에 적어 두어야 나중에 읽는 사람이 헷갈리지 않는다.

⑨ Kp · Ki · Kd로 읽기 — pid

지금까지 제어기를 \(K\dfrac{(s - z_{pd})(s - z_{pi})}{s}\)라는 극점·영점 꼴로 다뤘다. 그런데 PID 제어기는 보통 \(K_p + \dfrac{K_i}{s} + K_d s\)라는 이득 꼴로 적는다. 실제 장비와 Simulink 블록도 이 세 숫자를 받는다. 분자를 펼쳐 계수를 맞추면 바로 옮겨진다.

$$K\frac{(s - z_{pd})(s - z_{pi})}{s} = \frac{K s^2 - K(z_{pd}+z_{pi})\,s + K z_{pd} z_{pi}}{s} = \underbrace{K}_{K_d}\,s + \underbrace{-K(z_{pd}+z_{pi})}_{K_p} + \frac{\overbrace{K z_{pd} z_{pi}}^{K_i}}{s}$$ 
% K (s - zero_pd)(s - zero_pi) / s 를 펼쳐 Kp, Ki, Kd 로 읽는다
Kd = K;
Kp = -K*(zero_pd + zero_pi);
Ki = K*zero_pd*zero_pi;
fprintf('Kp = %.2f, Ki = %.2f, Kd = %.2f\n', Kp, Ki, Kd)
C = pid(Kp, Ki, Kd)
% 같은 제어기인지 확인: 두 전달함수의 차이가 0이면 같다
C_tf = K*(s - zero_pd)*(s - zero_pi)/s;
difference = norm(tf(C) - C_tf)

명령 창 출력

Kp = 858.09, Ki = 8.57, Kd = 121.50

C =

  Kp + Ki * --- + Kd * s
             s

  with Kp = 858, Ki = 8.57, Kd = 121

Model Properties

     0

🆕 이 코드에서 처음 나오는 것

C = pid(Kp, Ki, Kd)
PID 제어기 객체를 만든다(Control System Toolbox). 출력의 「parallel form」은 \(K_p + K_i/s + K_d s\) 꼴이라는 뜻이다. tf 객체처럼 곱하고 feedback에 넣을 수 있다. 여기서는 극점·영점으로 설계한 제어기를 이득 세 개로 옮겨 적는 데 썼다.
tf(C)
다른 꼴의 시스템 객체를 전달함수 객체로 바꾼다. 여기서는 pid 객체를 C_tf와 뺄셈하려고 같은 꼴로 맞췄다.
norm(sys)
시스템의 「크기」(기본은 H2 노름)를 숫자 하나로 낸다. 여기서는 두 제어기의 차이 시스템이 0인지 — 곧 두 제어기가 같은지 — 확인하는 데 썼다. 결과 0이 그 답이다.

\(K_p = 121.50 \times (7.0525 + 0.01) = 858.09\), \(K_i = 121.50 \times 7.0525 \times 0.01 = 8.57\)이다. \(K_i\)가 \(K_p\)의 1/100밖에 안 되는 것이 「PI 영점을 원점 가까이 둔다」의 이득 꼴 모습이다 — 적분 동작이 아주 약하다. 그래서 ⑧의 꼬리가 느렸다.

🧪 실습

사양을 바꿔 PID를 다시 설계하고, 계단응답으로 확인한다

이걸 해 보면 무엇을 알게 되나: 사양 → 목표 극점 → PD 영점 → K → PI 영점의 다섯 단계를 혼자 끝까지 밟아 보고, 설계 결과(K, 영점)가 \(K_p, K_i, K_d\)로 어떻게 옮겨지는지 손으로 확인한다.

준비물: MATLAB(Control System Toolbox), 6회의 함수 세 개(draw_*_line.m), 오늘의 함수 두 개(design_pd_controller.m · mark_closed_pole.m) — 모두 한 폴더에.

  1. ①~⑧의 조각을 스크립트 하나(pid_design.m)에 차례로 붙여 넣고 실행해, 자료와 같은 숫자(영점 −7.0525, K = 121.50)가 나오는지 본다. (10분)
  2. 사양을 최대초과 15%, 첨두시간 0.4초로 바꿔 다시 실행한다. 목표 극점·PD 영점·K가 각각 얼마로 바뀌는지 적는다. (10분)
  3. ⑨의 식으로 \(K_p, K_i, K_d\)를 구하고 C = pid(Kp, Ki, Kd)로 제어기를 만든다. (5분)
  4. [y, t] = step(feedback(C*otf, 1), 0:0.01:600)로 계단응답을 구해 그리고, stepinfo(y, t, 1)로 첨두시간과 최대초과를 잰다. (5분)

이렇게 되면 성공이다: 4번의 응답이 ⑧의 그림처럼 빠르게 솟았다가 가라앉고, 첨두시간이 0.4초 근처에 찍힌다. 1번에서 자료와 숫자가 다르면 6회 함수가 같은 폴더에 있는지부터 확인한다.

📝 연습문제

  1. 영점이 있는 플랜트. \(G(s) = \dfrac{s+6}{(s+2)(s+4)(s+10)}\)에 최대초과 20%, 첨두시간 0.4초 사양으로 design_pd_controller를 실행해 본다. ④의 ⚠️ 상자처럼 if 안에 이름 오타가 있는 함수였다면 어디서 멈췄을지 짚고, 출력의 「영점의 위상」 줄이 각도 합에 어떻게 들어가는지 설명한다.
  2. PI 영점의 맞바꿈. PI 영점을 −0.01, −0.1, −0.5로 바꿔 가며 for 문으로 비교한다. 영점마다 K를 크기 조건으로 다시 구하고, 최대초과와 정착시간(최종값 1, 시간 구간 600초)을 표로 정리한다. ⑧의 해석에서 말한 맞바꿈이 표의 숫자로 어떻게 드러나는지 설명한다.

미분 제어를 실제로 쓸 때

순수 미분 \(K_d s\)는 주파수가 높을수록 이득이 끝없이 커져서, 센서 잡음을 그대로 증폭한다. 그래서 실제 PID에는 미분 항에 필터(\(Ns/(s+N)\))를 씌운다. Simulink의 PID 블록도 그렇게 되어 있다(9회). N은 보통 설계한 폐루프 대역폭보다 열 배쯤 크게 잡는다.
