STL 알고리즘 — 이미 있는 것을 먼저 찾는다

오늘 답할 질문
  1. for문으로 잘 돌아가는 코드를 왜 굳이 바꾸나?
  2. AI는 왜 표준 라이브러리를 잘 안 쓰나?
  3. 표준 알고리즘으로 바꾸면 실제로 얼마나 빨라지나? 안 빨라지는 경우도 있나?
  4. 표준 알고리즘을 썼는데도 실제 로봇에서만 틀리는 경우가 있다. 왜인가?

실제 회사의 C++ 코드 1천만 줄을 1년간 추적한 연구가 있다. 거기서 나온 숫자 하나가 이 회차의 출발점이다. AI가 짠 코드는 표준 라이브러리를 사람의 40%밖에 쓰지 않았다. 대신 직접 짠 for문이 약 2배 많았다. 틀린 코드를 더 많이 만든 것은 아니다 — 정확성 문제는 오히려 사람의 0.94배였다. 문제는 맞지만 둔한 코드다.

오늘은 그 둔한 코드를 알아보고 무엇으로 바꿔 달라고 말할지를 배운다. 함수 이름을 외우는 시간이 아니다. 받은 코드에서 "이건 표준에 이미 있는 것 아닌가" 하고 의심할 줄 아는 것이 목표다. 이름은 그때 AI에게 물어보면 된다.

그리고 마지막에 함정이 하나 있다. 표준 알고리즘으로 바꿔도 실제 라이다에서만 틀리는 코드다. 그 함정이 이 회차에서 가장 중요하다.

한 장 요약 — 학기가 끝나도 이 표만 남으면 된다

무엇을 먼저 볼지: 가운데 「이 for문이 보이면」 열만 읽어도 판단이 선다. 왼쪽 이름은 외우지 않아도 된다.

이걸 쓴다이 for문이 보이면 바꾼다수준
std::min_element / max_element가장 작은(큰) 것을 찾는 루프[요구]
std::count_if조건에 맞는 것의 개수를 세는 루프[요구]
std::copy_if조건에 맞는 것만 다른 그릇에 담는 루프[요구]
std::find_if조건에 맞는 첫 번째를 찾는 루프[요구]
std::transform전부 바꿔서 다른 그릇에 담는 루프[요구]
std::accumulate합계를 내는 루프[판단]
std::any_of / all_of"하나라도 / 전부"를 확인하는 루프[판단]
std::sort / nth_element정렬하거나 중앙값을 구하는 루프[판단]
해석: 외울 것은 함수 이름이 아니라 가운데 열이다. 받은 코드에서 저런 모양의 for문이 보이면 "이건 표준에 이미 있는 것 아닌가"를 의심하면 된다. 이 표에 없는 알고리즘이 훨씬 많다. 다 알 필요도 없고 알 수도 없다. 모양을 알아보는 것이 이 표의 목적이다.
STL은 20년 동안 다른 언어에서 갈고닦은 것이다 (10분 · 건너뛰어도 됩니다)

① 1980년대 — "자료구조와 알고리즘을 떼어 놓을 수 있다"

알렉산더 스테파노프(Alexander Stepanov)는 이상한 생각을 하나 밀고 있었다. 정렬하는 코드가 배열이든 리스트든 상관없이 똑같이 돌아가게 만들 수 있다는 생각이다. 지금은 당연해 보이지만, 당시에는 자료구조마다 알고리즘을 따로 짜는 것이 상식이었다. 배열용 정렬과 리스트용 정렬은 다른 코드였다.

② 그는 언어를 갈아탔다

먼저 에이다(Ada)로 만들어 1987년에 발표했다. 그런데 에이다는 국방 분야 밖으로 퍼지지 않았다. 갈고닦은 생각이 있는데 쓸 사람이 없었다. 그래서 그는 C++로 옮겨 탄다 — 그쪽이 널리 쓰일 것 같아서였다. 기술이 좋아서가 아니라 사람이 많아서 고른 것이다.

③ 여기가 재미있다 — 완성품을 들고 위원회에 갔다

1994년 3월 7일, 그는 C++ 표준화 위원회 앞에 섰다. 들고 간 것은 아이디어가 아니라 20년 가까이 다른 언어에서 다듬어 온 라이브러리 전체였다. 보통 표준은 위원회가 몇 년에 걸쳐 설계한다. 이건 반대였다 — 완성된 물건을 가져와서 "이거 그냥 넣으시죠"라고 한 것이다. 위원회는 그것을 통째로 표준에 넣기로 한다. 그것이 STL(Standard Template Library)이다.

④ 그래서 지금 우리 손에 남은 것

std::min_element 같은 함수는 누가 급하게 만든 편의 함수가 아니라 20년 걸려 설계된 것이다.

⓪ 오늘은 프로그램 하나에 알고리즘을 하나씩 더해 간다 🟢 맡긴다

함수 이름을 하나씩 따로 보면 남지 않는다. 그래서 라이다 스캔 하나를 놓고 실제로 돌아가는 파일 하나를 준비했다. scan_algo.cpp다. 처음에는 값 10개를 찍기만 하는 스무 줄이 안 되는 프로그램이고, 절이 하나 넘어갈 때마다 for문 하나가 표준 알고리즘으로 바뀌거나 알고리즘이 하나씩 더해진다. ⚠️ 함정 절이 끝나면 완성본이 된다.

읽는 법은 7회와 같다.

  • 본문에는 그 절에서 새로 넣거나 고친 줄만 보인다. 초록 바탕이 새 줄, 붉은 바탕이 지운 줄이다.
  • 그 아래 📄 「전체 코드」 상자를 누르면 그 단계까지의 파일 전체가 나온다. 어느 단계를 펼쳐도 그대로 빌드되고 돌아간다. 오른쪽 위 「복사」로 통째로 가져갈 수 있다.
  • 「실제로 나온 출력」에는 그 절이 새로 찍는 줄만 보인다. 전체 출력은 실습 「성공 화면」에 있다.

1단계 — 라이다 스캔 하나를 만들고 찍어 본다

터틀봇3 라이다는 한 바퀴에 값 360개를 주는데, 눈으로 따라가기에는 많다. 그래서 10개만 흉내냈다. 대신 실제 스캔에 섞여 오는 것들 — 측정 실패(inf·nan)와 잴 수 있는 거리 밖의 값 — 을 일부러 넣어 두었다. 

// 13회 — STL 알고리즘: 라이다 스캔 하나를 놓고 for 문을 표준 알고리즘으로 바꿔 간다
#include <cmath>       // INFINITY · std::nanf · std::isfinite
#include <cstdio>      // std::printf
#include <vector>

int main()
{
  // 라이다 한 스캔을 흉내낸 값 10개. 측정 실패(inf · nan)와 범위 밖 값이 섞여 있다
  const std::vector<float> raw{0.10f, 0.83f, INFINITY, 1.24f, 9.90f,
                               std::nanf(""), 2.05f, 0.42f, 3.30f, 0.55f};
  const float lo = 0.16f, hi = 8.0f;   // 이 라이다(LDS-02)가 잴 수 있는 거리

  std::printf("원본 %d개 = ", static_cast<int>(raw.size()));
  for (float r : raw) { std::printf("%.2f ", r); }
  std::printf("\n잴 수 있는 거리 = %.2f ~ %.2f m\n", lo, hi);
  return 0;
}

🆕 이 코드에서 처음 나오는 것

std::nanf("")
NaN(숫자가 아님) 값을 하나 만들어 준다. 라이다가 측정에 실패했을 때 보내는 것과 같은 값이다. 여기서는 함정을 재현하려고 일부러 섞었다. INFINITY는 6회에서 본 그 값이다.
std::printf("%.2f", r) 가 inf · nan 을 만나면
오류가 나지 않고 글자 그대로 inf·nan이 찍힌다. 여기서는 그 덕에 어느 칸이 측정 실패값인지 출력에서 바로 보인다.

① 가장 가까운 장애물을 찾는 코드 🟡 맡기되 검사

언제 이게 필요해지나

라이다가 준 거리 배열에서 가장 가까운 값을 찾으려고 한다. 앞에 뭔가 있는지 판단하려면 이게 첫 단계다. 배열은 0번이 정면이고 반시계 방향으로 돌아가므로, 몇 번째 칸인지가 곧 방향이다.

AI가 보통 주는 코드 🔴 — main의 출력 줄 아래에 이렇게 넣는다
  // … 1단계까지의 줄은 그대로 …
  // ① 가장 가까운 값 — AI가 보통 주는 모양
  float min_range = 999.0f;
  for (size_t i = 0; i < raw.size(); i++) {
    if (raw[i] < min_range) { min_range = raw[i]; }
  }
  std::printf("for 문      가장 가까운 값        = %.2f\n", min_range);
  return 0;

무엇이 문제인가

이 코드는 컴파일되고, 실행되고, 대체로 맞는 값을 낸다. 그래서 문제를 알아채기 어렵다.

자리무엇이 걸리나
999.0f왜 999인가? 근거 없는 값이다. 라이다 최대 거리가 8 m인데 999가 나오면 그건 "못 찾았다"는 뜻인지 "999 m"인지 알 수 없다
i < raw.size()인덱스를 직접 다루면 범위 실수가 들어갈 자리가 생긴다. <=로 한 글자만 틀려도 배열 밖을 읽는다
배열이 비었을 때999가 그대로 남는다. "장애물이 999 m 앞에 있다"는 답이 나간다
루프 전체읽어 봐야 무슨 일을 하는지 안다. 이름이 없다

출력에도 걸리는 것이 하나 있다. 답이 0.10 m인데, 바로 윗줄에 이 라이다는 0.16 m 아래를 못 잰다고 찍혀 있다. 측정 실패값을 「가장 가까운 장애물」로 잡은 것이다. 다만 이것은 for문의 잘못이 아니라 걸러 내지 않은 잘못이다. ②·③에서 고친다. 먼저 for문부터 바꾼다.

이렇게 말하면 된다

최솟값 찾는 for문을 std::min_element로 바꿔 줘. 초깃값을 임의로 두지 말고, 배열이 비었을 때도 안전하게 처리해 줘. 가장 가까운 값이 앞에서 몇 번째인지도 같이 찍어 줘.
받은 코드 — for문 다섯 줄이 이 네 줄로 바뀐다. 맨 위에 헤더 둘이 더 붙는다
#include <algorithm>   // min_element · count_if · copy_if · find_if · transform · any_of · all_of · sort
#include <cmath>       // INFINITY · std::nanf · std::isfinite
#include <cstdio>      // std::printf
#include <iterator>    // std::distance · std::back_inserter
#include <vector>
  // …
  float min_range = 999.0f;
  for (size_t i = 0; i < raw.size(); i++) {
    if (raw[i] < min_range) { min_range = raw[i]; }
  }
  // ① 가장 가까운 값 — min_element 는 값이 아니라 「자리」를 돌려준다
  const auto it = std::min_element(raw.begin(), raw.end());
  if (it == raw.end()) { return 1; }    // 배열이 비었다 — 여기서 끝낸다
  std::printf("min_element 가장 가까운 값        = %.2f (앞에서 %d번째)\n",
              *it, static_cast<int>(std::distance(raw.begin(), it)));
  return 0;

🆕 이 코드에서 처음 나오는 것

#include <algorithm>
오늘 나오는 함수들이 들어 있는 헤더다. accumulate만 <numeric>에 따로 들어 있다. 여기서는 min_element를 쓰려고 넣었다.
raw.begin() / raw.end()
배열의 첫 칸과 마지막 칸 다음을 가리키는 위치표다. end()는 마지막 값이 아니라 끝을 지나간 자리라는 것이 중요하다. 여기서는 "이 구간 전체를 봐 달라"고 알려 주는 데 썼다.
std::min_element(first, last)
구간에서 가장 작은 것이 어디 있는지를 돌려준다. 값이 아니라 위치다. 여기서는 그 위치를 it에 받았다.
*it
위치표 앞에 별표를 붙이면 그 자리에 있는 값이 나온다. 여기서는 min_element가 가리킨 자리의 거리 값을 꺼내는 데 썼다.
it == raw.end()
"찾지 못했다"는 뜻이다. 배열이 비어 있으면 min_element가 end()를 돌려준다. 여기서는 그 경우 return 1;로 프로그램을 끝냈다 — main이 0이 아닌 값을 돌려주면 「실패로 끝났다」는 뜻이다. 999.0f가 필요 없어진 이유가 이것이다.

가장 가까운 것이 「몇 번 방향」인지도 알아야 한다

거리만으로는 부족하다. 어느 쪽에 있는지를 알아야 피할 수 있다. 받은 코드의 마지막 줄이 그 일을 한다 — min_element가 돌려준 자리가 앞에서 몇 번째인지를 센다. 360개짜리 진짜 스캔이라면 그 번호가 곧 각도(도)다. 0 = 정면, 90 = 왼쪽, 270 = 오른쪽.

받은 코드 — ②의 조건에 이름이 붙고, 그 아래에 담는 코드가 온다

람다에 이름을 붙여 둔 것이다. 이름이 있으면 여러 곳에서 같은 조건을 다시 쓸 수 있다. 여기서는 count_if와 copy_if가 같은 valid를 받는다 — 조건을 고칠 일이 생기면 한 곳만 고치면 된다.
std::copy_if(first, last, 받는 곳, 조건)
구간에서 조건에 맞는 것만 골라 다른 곳으로 옮겨 담는다. 여기서는 쓸 만한 거리 값만 good에 모으는 데 썼다.
std::back_inserter(good)

전부 같은 방식으로 바꿔서 다른 그릇에 담는다. 여기서는 미터를 센티미터로 바꾸는 데 썼다. 받는 그릇은 미리 같은 크기로 만들어 둬야 한다.
[](float r) { ... }

#include <cmath>       // INFINITY · std::nanf · std::isfinite
#include <cstdio>      // std::printf
#include <iterator>    // std::distance · std::back_inserter
#include <numeric>     // std::accumulate
#include <vector>

int main()
{
  // 라이다 한 스캔을 흉내낸 값 10개. 측정 실패(inf · nan)와 범위 밖 값이 섞여 있다
  const std::vector<float> raw{0.10f, 0.83f, INFINITY, 1.24f, 9.90f,
                               std::nanf(""), 2.05f, 0.42f, 3.30f, 0.55f};
  const float lo = 0.16f, hi = 8.0f;   // 이 라이다(LDS-02)가 잴 수 있는 거리

  std::printf("원본 %d개 = ", static_cast<int>(raw.size()));
  for (float r : raw) { std::printf("%.2f ", r); }
  std::printf("\n잴 수 있는 거리 = %.2f ~ %.2f m\n", lo, hi);

  // ① 가장 가까운 값 — min_element 는 값이 아니라 「자리」를 돌려준다
  const auto it = std::min_element(raw.begin(), raw.end());
  if (it == raw.end()) { return 1; }    // 배열이 비었다 — 여기서 끝낸다
  std::printf("min_element 가장 가까운 값        = %.2f (앞에서 %d번째)\n",
              *it, static_cast<int>(std::distance(raw.begin(), it)));

  // ②③ 「쓸 만한 값인가」를 한 번만 적어 두고 두 곳에서 쓴다
  auto valid = [lo, hi](float r) { return std::isfinite(r) && r >= lo && r <= hi; };

  // ② 쓸 만한 값이 몇 개인가
  const auto n_valid = std::count_if(raw.begin(), raw.end(), valid);
  std::printf("count_if    유효값 개수           = %d\n", static_cast<int>(n_valid));

  // ③ 쓸 만한 값만 골라 담는다
  std::vector<float> good;
  good.reserve(raw.size());             // 미리 자리를 잡아 둔다
  std::copy_if(raw.begin(), raw.end(), std::back_inserter(good), valid);
  std::printf("copy_if     골라 담은 것          = ");
  for (float r : good) { std::printf("%.2f ", r); }
  std::printf("\n");

  const auto it2 = std::min_element(good.begin(), good.end());
  std::printf("min_element 걸러낸 뒤 가장 가까운 = %.2f (앞에서 %d번째)\n",
              *it2, static_cast<int>(std::distance(good.begin(), it2)));

  // ④ 나머지 여섯 개 — 전부 「구간을 주고, 필요하면 조건을 준다」는 같은 모양이다

  std::printf("find_if     0.5m 보다 가까운 첫 값 = %.2f\n", *f);

  const float sum = std::accumulate(good.begin(), good.end(), 0.0f);
  std::printf("accumulate  합 %.2f → 평균 %.3f m\n", sum, sum / good.size());

  std::vector<float> cm(good.size());   // 받는 그릇은 미리 같은 크기로
  std::transform(good.begin(), good.end(), cm.begin(), [](float m) { return m * 100.0f; });
  std::printf("transform   cm 로 바꾼 것         = ");
  for (float c : cm) { std::printf("%.0f ", c); }
  std::printf("\n");

  const bool near_any = std::any_of(good.begin(), good.end(), [](float r) { return r < 0.3f; });
  const bool all_far  = std::all_of(good.begin(), good.end(), [](float r) { return r > 1.0f; });
  std::printf("any_of      0.3m 안쪽에 뭐가 있나   = %s\n", near_any ? "있다" : "없다");
  std::printf("all_of      전부 1m 밖인가          = %s\n", all_far ? "그렇다" : "아니다");

  std::vector<float> sorted = good;     // 원본은 두고 사본을 정렬한다
  std::sort(sorted.begin(), sorted.end());
  std::printf("sort        정렬 후 중앙값         = %.2f\n", sorted.at(sorted.size() / 2));
  return 0;

  // ③ 쓸 만한 값만 골라 담는다
  std::vector<float> good;
  good.reserve(raw.size());             // 미리 자리를 잡아 둔다
  std::copy_if(raw.begin(), raw.end(), std::back_inserter(good), valid);
  std::printf("copy_if     골라 담은 것          = ");
  for (float r : good) { std::printf("%.2f ", r); }
  std::printf("\n");

  const auto it2 = std::min_element(good.begin(), good.end());
  std::printf("min_element 걸러낸 뒤 가장 가까운 = %.2f (앞에서 %d번째)\n",
              *it2, static_cast<int>(std::distance(good.begin(), it2)));

  // ④ 나머지 여섯 개 — 전부 「구간을 주고, 필요하면 조건을 준다」는 같은 모양이다
  const auto f = std::find_if(good.begin(), good.end(), [](float r) { return r < 0.5f; });
  std::printf("find_if     0.5m 보다 가까운 첫 값 = %.2f\n", *f);

  const float sum = std::accumulate(good.begin(), good.end(), 0.0f);
  std::printf("accumulate  합 %.2f → 평균 %.3f m\n", sum, sum / good.size());

  std::vector<float> cm(good.size());   // 받는 그릇은 미리 같은 크기로
  std::transform(good.begin(), good.end(), cm.begin(), [](float m) { return m * 100.0f; });
  std::printf("transform   cm 로 바꾼 것         = ");
  for (float c : cm) { std::printf("%.0f ", c); }
  std::printf("\n");

  const bool near_any = std::any_of(good.begin(), good.end(), [](float r) { return r < 0.3f; });
  const bool all_far  = std::all_of(good.begin(), good.end(), [](float r) { return r > 1.0f; });
  std::printf("any_of      0.3m 안쪽에 뭐가 있나   = %s\n", near_any ? "있다" : "없다");
  std::printf("all_of      전부 1m 밖인가          = %s\n", all_far ? "그렇다" : "아니다");

  std::vector<float> sorted = good;     // 원본은 두고 사본을 정렬한다
  std::sort(sorted.begin(), sorted.end());
  std::printf("sort        정렬 후 중앙값         = %.2f\n", sorted.at(sorted.size() / 2));

  measure_speed();
  return 0;
}

min_element는 "이게 저것보다 작은가"를 반복해서 묻는 함수인데, 그 질문에 계속 거짓이 돌아오면 비교가 무의미해진다. 결과는 NaN이 배열의 어디에 있느냐에 따라 달라진다. 맨 윗줄이 무서운 이유는 크래시가 안 나기 때문이다. 로봇은 nan을 거리로 받아 그대로 판단하고, 그다음에 무슨 일이 일어날지는 아무도 모른다.

「걸렀는데도」 뚫리는 모양이 있다

"그러니까 범위 밖은 거르면 되지 않나" — 맞다. 그런데 거르는 조건을 어느 쪽으로 쓰느냐에 따라 결과가 갈린다. AI는 「범위 밖이면 건너뛴다」는 빼는 조건을 자주 준다. 마지막으로 그 모양을 우리 valid(고르는 조건)와 나란히 놓아 본다. 

  // … 7단계 앞부분은 그대로 …
  std::printf("⚠️ 「빼는 조건」으로 거르면 NaN 이 통과한다\n");
  const std::vector<float> tricky{N, 3.0f, 0.5f, 2.0f, INFINITY};
  std::vector<float> leaky;             // AI가 자주 주는 모양: 범위 밖이면 건너뛴다
  for (float r : tricky) {
    if (r < lo || r > hi) { continue; } // NaN 은 둘 다 거짓 → 안 걸러진다
    leaky.push_back(r);
  }
  show_min("빼는 조건   :", leaky);
  std::vector<float> kept;              // ③ 과 같은 「고르는 조건」 + isfinite

  show_min("고르는 조건 :", kept);

⚠️ 「빼는 조건」으로 거르면 NaN 이 통과한다
  빼는 조건   : min_element →   nan  (앞에서 0번째)
  고르는 조건 : min_element →  0.50  (앞에서 1번째)

r < lo || r > hi는 NaN에게 두 번 다 「거짓」이라 continue에 걸리지 않는다. inf는 > hi에 걸려 빠지지만 NaN만 살아남는다. 반대로 「고르는 조건」은 NaN에게 「거짓」이라 안 담긴다. 그래도 std::isfinite를 앞에 붙이는 이유는, 조건을 누가 어느 쪽으로 고치든 뚫리지 않게 하려는 것이다.

그래서 이렇게 요구해야 한다:

ranges에 inf와 NaN이 섞여 있어. 유효한 값만 골라서 최솟값을 찾아 줘. lo~hi 범위 안에 있고 std::isfinite인 값만 「고르는」 조건으로 써 줘. 범위 밖을 빼는 식으로 쓰지 말아 줘.

// AI에게 "정렬을 직접 짜 줘"라고 하면 흔히 나오는 모양 (선택 정렬)
void hand_sort(std::vector<float> & v)
{
  for (size_t i = 0; i < v.size(); ++i) {
    size_t m = i;
    for (size_t j = i + 1; j < v.size(); ++j) { if (v[j] < v[m]) { m = j; } }
    const float t = v[i]; v[i] = v[m]; v[m] = t;
  }
}

// ⑤ 속도 — 진짜 스캔 크기(360개)로 직접 짠 루프와 표준을 같은 입력에 돌려 재 본다
void measure_speed()
{
  const int N = 360;
  std::vector<float> scan(N);
  for (int i = 0; i < N; ++i) { scan[i] = 0.2f + 0.02f * static_cast<float>((i * 37) % 300); }
  double sink = 0.0;   // 결과를 어딘가에 써야 컴파일러가 계산을 통째로 지우지 않는다

  // 최솟값 찾기 10만 번
  const int LOOPS_MIN = 100000;
  auto t0 = std::chrono::steady_clock::now();
  for (int k = 0; k < LOOPS_MIN; ++k) {
    float m = 999.0f;
    for (size_t i = 0; i < scan.size(); ++i) { if (scan[i] < m) { m = scan[i]; } }
    sink += m;
  }
  auto t1 = std::chrono::steady_clock::now();
  const double loop_ms = std::chrono::duration<double, std::milli>(t1 - t0).count();

  t0 = std::chrono::steady_clock::now();
  for (int k = 0; k < LOOPS_MIN; ++k) { sink += *std::min_element(scan.begin(), scan.end()); }
  t1 = std::chrono::steady_clock::now();
  const double stl_ms = std::chrono::duration<double, std::milli>(t1 - t0).count();

  std::printf("\n⑤ 속도 — 360개 배열 × %d회\n", LOOPS_MIN);
  std::printf("  직접 짠 for문   : %7.1f ms\n", loop_ms);
  std::printf("  min_element     : %7.1f ms   (%.2f배 빠르다)\n", stl_ms, loop_ms / stl_ms);

  // 정렬해서 중앙값 얻기 1만 번
  const int LOOPS_SORT = 10000;
  t0 = std::chrono::steady_clock::now();
  for (int k = 0; k < LOOPS_SORT; ++k) {
    std::vector<float> v = scan;
    hand_sort(v);
    sink += v.at(N / 2);
  }
  t1 = std::chrono::steady_clock::now();
  const double hand = std::chrono::duration<double, std::milli>(t1 - t0).count();

  t0 = std::chrono::steady_clock::now();
  for (int k = 0; k < LOOPS_SORT; ++k) {
    std::vector<float> v = scan;
    std::sort(v.begin(), v.end());
    sink += v.at(N / 2);
  }
  t1 = std::chrono::steady_clock::now();
  const double stl = std::chrono::duration<double, std::milli>(t1 - t0).count();

  // 중앙값만 필요하면 전부 정렬할 필요도 없다
  t0 = std::chrono::steady_clock::now();
  for (int k = 0; k < LOOPS_SORT; ++k) {
    std::vector<float> v = scan;
    std::nth_element(v.begin(), v.begin() + N / 2, v.end());
    sink += v.at(N / 2);
  }
  t1 = std::chrono::steady_clock::now();
  const double nth = std::chrono::duration<double, std::milli>(t1 - t0).count();

  std::printf("⑤ 정렬 — 360개 배열 × %d회 (sink=%.0f)\n", LOOPS_SORT, sink);
  std::printf("  직접 짠 선택 정렬 : %8.1f ms\n", hand);
  std::printf("  std::sort         : %8.1f ms   (%.1f배 빠르다)\n", stl, hand / stl);
  std::printf("  std::nth_element  : %8.1f ms   (%.1f배 빠르다)\n", nth, hand / nth);
}

  const bool all_far  = std::all_of(good.begin(), good.end(), [](float r) { return r > 1.0f; });
  std::printf("any_of      0.3m 안쪽에 뭐가 있나   = %s\n", near_any ? "있다" : "없다");

  const float N = std::nanf("");

  std::printf("  NaN < 5.0 : %s\n", (N < 5.0f) ? "참" : "거짓");
  std::printf("  NaN > 5.0 : %s\n", (N > 5.0f) ? "참" : "거짓");

  std::printf("⚠️ 같은 값 묶음인데 NaN 의 자리만 다르다\n");
  show_min("NaN 이 앞에  :", {N, 3.0f, 0.5f, 2.0f});

  show_min("NaN 이 없음  :", {3.0f, 0.5f, 2.0f});

  std::printf("⚠️ 「빼는 조건」으로 거르면 NaN 이 통과한다\n");
  const std::vector<float> tricky{N, 3.0f, 0.5f, 2.0f, INFINITY};
  std::vector<float> leaky;             // AI가 자주 주는 모양: 범위 밖이면 건너뛴다
  for (float r : tricky) {
    if (r < lo || r > hi) { continue; } // NaN 은 둘 다 거짓 → 안 걸러진다
    leaky.push_back(r);
  }
  show_min("빼는 조건   :", leaky);
  std::vector<float> kept;              // ③ 과 같은 「고르는 조건」 + isfinite
  std::copy_if(tricky.begin(), tricky.end(), std::back_inserter(kept), valid);
  show_min("고르는 조건 :", kept);
  return 0;
}

#include <cmath>       // INFINITY · std::nanf · std::isfinite

// AI에게 "정렬을 직접 짜 줘"라고 하면 흔히 나오는 모양 (선택 정렬)
void hand_sort(std::vector<float> & v)
{
  for (size_t i = 0; i < v.size(); ++i) {
    size_t m = i;
    for (size_t j = i + 1; j < v.size(); ++j) { if (v[j] < v[m]) { m = j; } }
    const float t = v[i]; v[i] = v[m]; v[m] = t;
  }
}

// ⑤ 속도 — 진짜 스캔 크기(360개)로 직접 짠 루프와 표준을 같은 입력에 돌려 재 본다
void measure_speed()
{
  const int N = 360;
  std::vector<float> scan(N);
  for (int i = 0; i < N; ++i) { scan[i] = 0.2f + 0.02f * static_cast<float>((i * 37) % 300); }
  double sink = 0.0;   // 결과를 어딘가에 써야 컴파일러가 계산을 통째로 지우지 않는다

  // 최솟값 찾기 10만 번
  const int LOOPS_MIN = 100000;
  auto t0 = std::chrono::steady_clock::now();
  for (int k = 0; k < LOOPS_MIN; ++k) {
    float m = 999.0f;
    for (size_t i = 0; i < scan.size(); ++i) { if (scan[i] < m) { m = scan[i]; } }
    sink += m;
  }
  auto t1 = std::chrono::steady_clock::now();
  const double loop_ms = std::chrono::duration<double, std::milli>(t1 - t0).count();

  t0 = std::chrono::steady_clock::now();
  for (int k = 0; k < LOOPS_MIN; ++k) { sink += *std::min_element(scan.begin(), scan.end()); }
  t1 = std::chrono::steady_clock::now();
  const double stl_ms = std::chrono::duration<double, std::milli>(t1 - t0).count();

  std::printf("\n⑤ 속도 — 360개 배열 × %d회\n", LOOPS_MIN);
  std::printf("  직접 짠 for문   : %7.1f ms\n", loop_ms);
  std::printf("  min_element     : %7.1f ms   (%.2f배 빠르다)\n", stl_ms, loop_ms / stl_ms);

  // 정렬해서 중앙값 얻기 1만 번
  const int LOOPS_SORT = 10000;
  t0 = std::chrono::steady_clock::now();
  for (int k = 0; k < LOOPS_SORT; ++k) {
    std::vector<float> v = scan;
    hand_sort(v);
    sink += v.at(N / 2);
  }
  t1 = std::chrono::steady_clock::now();
  const double hand = std::chrono::duration<double, std::milli>(t1 - t0).count();

  t0 = std::chrono::steady_clock::now();
  for (int k = 0; k < LOOPS_SORT; ++k) {
    std::vector<float> v = scan;
    std::sort(v.begin(), v.end());
    sink += v.at(N / 2);
  }
  t1 = std::chrono::steady_clock::now();
  const double stl = std::chrono::duration<double, std::milli>(t1 - t0).count();

  // 중앙값만 필요하면 전부 정렬할 필요도 없다
  t0 = std::chrono::steady_clock::now();
  for (int k = 0; k < LOOPS_SORT; ++k) {
    std::vector<float> v = scan;
    std::nth_element(v.begin(), v.begin() + N / 2, v.end());
    sink += v.at(N / 2);
  }
  t1 = std::chrono::steady_clock::now();
  const double nth = std::chrono::duration<double, std::milli>(t1 - t0).count();

  std::printf("⑤ 정렬 — 360개 배열 × %d회 (sink=%.0f)\n", LOOPS_SORT, sink);
  std::printf("  직접 짠 선택 정렬 : %8.1f ms\n", hand);
  std::printf("  std::sort         : %8.1f ms   (%.1f배 빠르다)\n", stl, hand / stl);
  std::printf("  std::nth_element  : %8.1f ms   (%.1f배 빠르다)\n", nth, hand / nth);
}

// ⚠️ 작은 묶음을 받아 min_element 가 무엇을 고르는지 찍는다
void show_min(const char * label, const std::vector<float> & v)
{
  const auto it = std::min_element(v.begin(), v.end());
  std::printf("  %s min_element → %5.2f  (앞에서 %d번째)\n",
              label, *it, static_cast<int>(std::distance(v.begin(), it)));
}

int main()
{
  // 라이다 한 스캔을 흉내낸 값 10개. 측정 실패(inf · nan)와 범위 밖 값이 섞여 있다
  const std::vector<float> raw{0.10f, 0.83f, INFINITY, 1.24f, 9.90f,
                               std::nanf(""), 2.05f, 0.42f, 3.30f, 0.55f};
  const float lo = 0.16f, hi = 8.0f;   // 이 라이다(LDS-02)가 잴 수 있는 거리

  std::printf("원본 %d개 = ", static_cast<int>(raw.size()));
  for (float r : raw) { std::printf("%.2f ", r); }
  std::printf("\n잴 수 있는 거리 = %.2f ~ %.2f m\n", lo, hi);

  // ① 가장 가까운 값 — min_element 는 값이 아니라 「자리」를 돌려준다
  const auto it = std::min_element(raw.begin(), raw.end());
  if (it == raw.end()) { return 1; }    // 배열이 비었다 — 여기서 끝낸다
  std::printf("min_element 가장 가까운 값        = %.2f (앞에서 %d번째)\n",
              *it, static_cast<int>(std::distance(raw.begin(), it)));

  // ②③ 「쓸 만한 값인가」를 한 번만 적어 두고 두 곳에서 쓴다
  auto valid = [lo, hi](float r) { return !(r < lo || r > hi); };   // 실습: 빼는 조건을 뒤집어 썼다

  // ② 쓸 만한 값이 몇 개인가
  const auto n_valid = std::count_if(raw.begin(), raw.end(), valid);
  std::printf("count_if    유효값 개수           = %d\n", static_cast<int>(n_valid));

  // ③ 쓸 만한 값만 골라 담는다
  std::vector<float> good;
  good.reserve(raw.size());             // 미리 자리를 잡아 둔다
  std::copy_if(raw.begin(), raw.end(), std::back_inserter(good), valid);
  std::printf("copy_if     골라 담은 것          = ");
  for (float r : good) { std::printf("%.2f ", r); }
  std::printf("\n");

  const auto it2 = std::min_element(good.begin(), good.end());
  std::printf("min_element 걸러낸 뒤 가장 가까운 = %.2f (앞에서 %d번째)\n",
              *it2, static_cast<int>(std::distance(good.begin(), it2)));

  // ④ 나머지 여섯 개 — 전부 「구간을 주고, 필요하면 조건을 준다」는 같은 모양이다
  const auto f = std::find_if(good.begin(), good.end(), [](float r) { return r < 0.5f; });
  std::printf("find_if     0.5m 보다 가까운 첫 값 = %.2f\n", *f);

  const float sum = std::accumulate(good.begin(), good.end(), 0.0f);
  std::printf("accumulate  합 %.2f → 평균 %.3f m\n", sum, sum / good.size());

  std::vector<float> cm(good.size());   // 받는 그릇은 미리 같은 크기로
  std::transform(good.begin(), good.end(), cm.begin(), [](float m) { return m * 100.0f; });
  std::printf("transform   cm 로 바꾼 것         = ");
  for (float c : cm) { std::printf("%.0f ", c); }
  std::printf("\n");

  const bool near_any = std::any_of(good.begin(), good.end(), [](float r) { return r < 0.3f; });
  const bool all_far  = std::all_of(good.begin(), good.end(), [](float r) { return r > 1.0f; });
  std::printf("any_of      0.3m 안쪽에 뭐가 있나   = %s\n", near_any ? "있다" : "없다");
  std::printf("all_of      전부 1m 밖인가          = %s\n", all_far ? "그렇다" : "아니다");

  std::vector<float> sorted = good;     // 원본은 두고 사본을 정렬한다
  std::sort(sorted.begin(), sorted.end());
  std::printf("sort        정렬 후 중앙값         = %.2f\n", sorted.at(sorted.size() / 2));

  measure_speed();

  // ⚠️ NaN 은 어떤 비교에도 거짓이다 — 그래서 어디 있느냐에 따라 답이 달라진다
  const float N = std::nanf("");
  std::printf("\n⚠️ NaN 비교\n");
  std::printf("  NaN < 5.0 : %s\n", (N < 5.0f) ? "참" : "거짓");
  std::printf("  NaN > 5.0 : %s\n", (N > 5.0f) ? "참" : "거짓");
  std::printf("  NaN == NaN: %s\n", (N == N) ? "참" : "거짓");

  std::printf("⚠️ 같은 값 묶음인데 NaN 의 자리만 다르다\n");
  show_min("NaN 이 앞에  :", {N, 3.0f, 0.5f, 2.0f});
  show_min("NaN 이 가운데:", {3.0f, N, 0.5f, 2.0f});
  show_min("NaN 이 없음  :", {3.0f, 0.5f, 2.0f});

  std::printf("⚠️ 「빼는 조건」으로 거르면 NaN 이 통과한다\n");
  const std::vector<float> tricky{N, 3.0f, 0.5f, 2.0f, INFINITY};
  std::vector<float> leaky;             // AI가 자주 주는 모양: 범위 밖이면 건너뛴다
  for (float r : tricky) {
    if (r < lo || r > hi) { continue; } // NaN 은 둘 다 거짓 → 안 걸러진다
    leaky.push_back(r);
  }
  show_min("빼는 조건   :", leaky);
  std::vector<float> kept;              // ③ 과 같은 「고르는 조건」 + isfinite
  std::copy_if(tricky.begin(), tricky.end(), std::back_inserter(kept), valid);
  show_min("고르는 조건 :", kept);
  return 0;
}

왜 begin()과 end()를 매번 써야 하나 — C++20이 없앤 불편

오늘 본 함수는 전부 (첫 칸, 끝 다음 칸) 두 개를 받는다. 배열 하나를 통째로 넘기는데도 두 번 쓰는 것이 번거롭다.

C++20에 std::ranges가 들어가면서 이게 짧아졌다. 

// 지금 (C++17)
std::sort(v.begin(), v.end());
// C++20
std::ranges::sort(v);

다만 우리는 C++17을 쓴다. ROS 2 Jazzy가 C++17 기준이기 때문이다. 학기 중에는 begin()·end()를 쓰면 된다. 나중에 다른 프로젝트에서 std::ranges::로 시작하는 코드를 보면 "아, 같은 건데 짧게 쓴 거구나"라고 알아보면 충분하다.

두 개를 받는 모양에는 이득도 있다. 배열의 일부만 넘길 수 있다. 예를 들어 라이다 배열에서 정면 30도만 보고 싶으면 이렇게 쓴다. 

// 0~29번 칸(정면 30도)에서만 최솟값을 찾는다
const auto it = std::min_element(ranges.begin(), ranges.begin() + 30);
std::sort는 안에서 무엇을 하나 — 한 문단만

값 개수가 적으면 간단한 방법으로, 많으면 빠른 방법으로, 그리고 운이 나쁜 입력이 들어오면 또 다른 방법으로 갈아탄다. 세 가지를 상황에 따라 섞어 쓰는 것이다. 이 내부 동작을 알 필요는 없다. 알아야 할 것은 하나다 — 직접 짠 정렬이 이것보다 나을 확률은 거의 없다. 위에서 잰 17.6배가 그 답이다.

다만 std::sort는 같은 값의 원래 순서를 지켜 주지 않는다. 순서를 지켜야 하면 std::stable_sort를 쓴다. 대신 조금 느리다. 이 과목에서는 거리 값을 정렬할 뿐이라 sort로 충분하다.
