로봇공학 · 21회 · 3부 ROS 2

서비스·파라미터·launch

오늘 답할 질문
  1. 코드에 적힌 속도 상한과 여유 거리를 노드를 끄지 않고 바꾸려면 코드에 무엇이 있어야 하나?
  2. ros2 param set이 Set parameter successful이라고 답했는데 거북이가 그대로다. 왜 그럴까?
  3. 튜닝해서 찾은 값은 어디에 남겨 두고, 노드를 켤 때 어떻게 읽게 하나?
  4. 「잠깐 멈춰라」 같은 한 번의 부탁을 내 노드가 받으려면, 또 남의 노드에 하려면 코드에 무엇이 있어야 하나?
  5. 터미널 여러 개에 나눠 치던 것을 파일 하나로 띄울 수 있나? 그 파일을 ros2 launch가 못 찾는다면 어디를 보나?

20회에 만든 turtle_drive는 지도의 1 ~ 10 안에서 무작위로 돌아다니다가, 그 범위를 벗어나면 중앙 쪽으로 돌아섰다. 그런데 실습 4번에서 여유를 2 m로 바꿔 보려고 했을 때, 숫자 하나를 고치고 다시 빌드하고 다시 띄워야 했다. 콘 트랙 앞에서 속도를 스무 번 바꿔 본다고 하면 그 일이 스무 번이다. 오늘은 같은 패키지 turtle_drive의 turtle_drive 노드를 다섯 단계(v3~v7)로 키우면서, 17회에서 개념으로만 본 파라미터와 서비스를 코드로 만든다.

순서는 이렇다. 먼저 속도 상한과 여유를 파라미터로 꺼내고(v3), 실행 중에 바꾼 값이 실제로 먹게 고치고(v4), 찾은 값을 YAML 파일로 남긴다. 그다음 「주행 켜기·끄기」를 받는 서비스 서버를 달고(v5), 거북이가 돌아설 때마다 turtlesim의 /turtle1/set_pen을 부르는 서비스 클라이언트를 단다(v6). 마지막으로 turtlesim과 turtle_drive를 파일 하나로 함께 띄우는 launch 파일을 만든다(v7).

각 단계에는 빌드는 되는데 기대대로 안 되는 자리가 하나씩 있다. param set은 성공했다는데 거북이가 그대로인 것, YAML 파일에 노드 이름을 틀리게 적어도 아무 말이 없는 것, 서비스 응답을 기다리다 노드 전체가 멈추는 것, launch 파일이 분명히 있는데 못 찾는 것. 오늘은 그 자리를 하나씩 직접 만나 보고, 무엇을 보면 알아챌 수 있는지 정리한다.

① turtle_drive v3~v7 🔴 사람이 한다

값을 바꿀 때마다 다시 빌드하는 방식은 무엇이 불편할까? 20회 실습 4번을 떠올려 보면 한 번에 네 가지 일을 했다 — margin_ 줄을 고치고, colcon build를 하고, 노드를 끄고, /reset으로 거북이를 되돌린 뒤 다시 띄웠다. 고친 숫자가 맞는지 보려면 이 네 가지를 또 해야 한다. 그리고 그사이 앞의 값으로 어떻게 움직였는지는 기억에만 남는다.

17회에서 그 해법이 파라미터라고 했다. 노드가 가진 이름 붙은 설정값이고, 밖에서 ros2 param get·set으로 읽고 바꿀 수 있다. 18회에서 turtlesim의 배경색을 그렇게 바꿨다. 오늘은 우리 노드에 그 창구를 만든다. 20회에서 숫자를 기본 멤버 초기화자로 모아 둔 것이 여기서 쓸모가 있다 — 바꿔 볼 값이 이미 한자리에 있다.

출발점 — 20회 v2 의 숫자 멤버 다섯 (const 가 붙어 있다)
  const double max_speed_ = 1.2;       // 앞으로 가는 속도의 상한 (m/s)
  const double margin_ = 1.0;          // 벽에서 이만큼 안쪽까지만 다닌다 (m) → 1 ~ 10
  const double map_size_ = 11.0;       // 지도 한 변의 길이 (m)
  const double center_ = 5.5;          // 지도 가운데 (x, y 모두)
  const double turn_tolerance_ = 0.35; // 중앙과 이 각(약 20°) 안이면 다시 출발한다 (rad)

다섯 중 max_speed_와 margin_은 로봇 앞에서 바꿔 볼 값이고, 나머지 셋은 지도의 크기와 「중앙을 본다」의 기준이라 바꿀 일이 드물다. 그래서 앞의 둘만 파라미터로 꺼낸다. 오늘 다섯 단계에서 무엇이 더해지는지 먼저 한 표로 본다.

② 파라미터 선언과 읽기 — declare_parameter · get_parameter (v3) 🟡 맡기되 검사

2-1 개념 — 노드가 밖에 내놓는 이름 붙은 설정값

멤버 변수 max_speed_도 이름 붙은 값인데, 왜 그것만으로는 밖에서 못 바꿀까? 멤버 변수는 프로그램 안에만 있다. 다른 프로세스(ros2 param 명령)는 그 메모리를 들여다볼 수 없다. 그래서 ROS 2는 노드마다 파라미터 저장소를 하나씩 두고, 노드가 「이 이름의 값을 밖에 내놓겠다」고 선언한 것만 그 저장소에 넣는다. 밖에서 get·set하는 것은 이 저장소다. 17회에서 「밖에서 읽고 바꾸는 일은 ROS가 서비스로 처리해 준다」고 했는데, 19회 ⑥절의 ros2 node info에 보이던 /hello_node/get_parameters·set_parameters처럼 이름에 parameter가 붙은 서비스 여섯 개가 그 창구다. 

// 선언 — 이름과 기본값. 이 순간 저장소에 "max_speed" 가 생기고 밖에서 보인다
this->declare_parameter("max_speed", 1.2);

// 읽기 — 저장소에서 지금 값을 꺼내 C++ 값으로 바꾼다
double max_speed = this->get_parameter("max_speed").as_double();
하는 일모양무엇을 보나
선언declare_parameter("이름", 기본값)기본값의 타입이 파라미터의 타입이 된다. 1.0 → double, 1 → 정수, true → bool, "abc" → 문자열
읽기get_parameter("이름").as_double()as_ 뒤가 선언한 타입과 같은가 (17회 표: 실수 파라미터는 언제나 double)
시작할 때 값 주기ros2 run … --ros-args -p 이름:=값기본값 대신 이 값으로 선언된다. 코드를 안 고친다
실행 중에 바꾸기ros2 param set /노드 이름 값저장소의 값이 바뀐다. 코드가 그 값을 언제 다시 읽나는 따로다 (③절)
해석: 첫 줄이 이 절의 함정을 품고 있다. 기본값을 1로 적으면 그 파라미터는 정수가 되고, 나중에 0.5를 넣으려 하면 「타입이 다르다」로 거절된다. C++에서 1과 1.0은 같은 수처럼 보이지만 파라미터에서는 다른 타입이다. 실수 파라미터의 기본값에는 소수점을 붙여 두면 이 문제를 처음부터 피할 수 있다.

2-2 예제에 적용 — const를 떼고 생성자에서 읽는다

max_speed_·margin_은 이제 생성자 안에서 파라미터 값으로 채워진다. 값이 나중에 들어오니 const를 뗀다. 기본값은 declare_parameter의 둘째 인자 한 곳에만 둔다 — 멤버 쪽에도 1.2를 적어 두면 두 숫자가 갈라졌을 때 어느 것이 진짜인지 헷갈린다. 멤버는 0.0으로 시작한다. map_size_·center_·turn_tolerance_는 그대로 const로 둔다. 시작 로그에는 두 값을 함께 찍어, 어떤 값으로 떴는지 바로 보이게 했다.

🆕 이 코드에서 처음 나오는 것

this->declare_parameter("이름", 기본값)
rclcpp::Node에서 물려받은 멤버 함수. 노드의 파라미터 저장소에 그 이름을 만들고, 시작할 때 따로 준 값이 없으면 기본값을 넣는다. 여기서는 max_speed를 double 1.2로, margin을 double 1.0으로 선언했다.
this->get_parameter("이름")
저장소에서 그 파라미터를 꺼낸다. 돌려받는 것은 rclcpp::Parameter 객체(이름 + 타입 + 값)이고, 그대로는 C++ 숫자가 아니다.
.as_double()
그 파라미터의 값을 double로 꺼낸다. 정수면 as_int(), bool이면 as_bool(), 문자열이면 as_string()이다. 선언한 타입과 다른 것으로 꺼내면 예외가 나서 노드가 죽는다.

CMakeLists.txt와 package.xml은 바뀌지 않는다. 파라미터 기능은 rclcpp 안에 있기 때문이다.

🆕 이 명령에서 처음 나오는 것

--ros-args -p 이름:=값
--ros-args는 17회에서 노드 이름을 바꿀 때(-r __node:=…) 본 「여기부터는 ROS에게 주는 인자」라는 표시다. -p는 그 뒤의 이름:=값을 파라미터 값으로 준다. 여기서는 margin을 2.0으로 시작했다 — 20회 실습에서 빌드를 다시 해야 했던 일을 명령 한 줄로 했다.
⚠️ 실수 파라미터에 정수를 주면 노드가 죽는다

소수점 하나를 빼고 margin:=2로 주면 이렇게 된다.

$ ros2 run turtle_drive turtle_drive --ros-args -p margin:=2
terminate called after throwing an instance of 'rclcpp::exceptions::InvalidParameterTypeException'
  what():  parameter 'margin' has invalid type: Wrong parameter type, parameter {margin} is of type {double}, setting it to {integer} is not allowed.
[ros2run]: Aborted

2는 정수로 읽히고, double로 선언한 파라미터에 정수를 넣는 것은 허락되지 않는다. 그래서 declare_parameter가 예외를 던지고 노드가 시작하자마자 끝난다. 18회에서 turtlesim에 background_r 1.5를 넣었을 때 Wrong parameter type이 난 것과 같은 규칙이 방향만 반대로 걸린 것이다. 실수 값에는 .0을 붙여 두면 덜 헤맨다 — 명령에서도, ④절의 YAML 파일에서도.

⚠️ 선언하지 않고 읽으면 시작하자마자 죽는다

v3에서 declare_parameter 두 줄만 지우고 빌드하면 빌드는 되고, 실행하면 이렇게 끝난다.

$ ros2 run turtle_drive turtle_drive
terminate called after throwing an instance of 'rclcpp::exceptions::ParameterNotDeclaredException'

④ YAML 파라미터 파일 — ros2 param dump · --params-file 🟡 맡기되 검사

4-1 개념 — 튜닝한 값을 파일로 남기고, 켤 때 읽게 한다

여유를 2.0으로 넓혀 보니 마음에 들었다. 그런데 노드를 껐다 켜면 어떻게 될까? 18회 함정 상자에서 본 대로 param set으로 바꾼 값은 노드를 끄면 사라진다. 다시 켜면 기본값 1.0으로 돌아간다. 매번 -p를 붙여 치는 것도 파라미터가 몇 개 넘으면 실수가 나온다.

그래서 값을 파일에 적어 두고, 노드를 켤 때 그 파일을 읽게 한다. 이 파일을 파라미터 파일이라고 하고, 형식은 YAML이다. 18회 ros2 param dump가 찍어 준 모양이 바로 그 형식이라, 지금 노드가 가진 값을 그대로 받아 적으면 된다. 

$ ros2 param dump /turtle_drive
/turtle_drive:
  ros__parameters:
    margin: 2.0
    max_speed: 1.2
    qos_overrides:
      /parameter_events:
        publisher:
          depth: 1000
          durability: volatile
          history: keep_last
          reliability: reliable
    start_type_description_service: true
    use_sim_time: false

③절에서 2.0으로 바꾼 값이 그대로 찍혔다(이름은 알파벳 순서로 나온다). 이 출력을 3회의 >로 파일에 받고, 우리가 고른 두 줄만 남기면 파라미터 파일이 된다. 나머지는 모든 노드에 있는 기본 파라미터라 파일에 둘 이유가 없다. 파일을 어느 폴더에 받는지는 바로 아래 4-2에서 정한다.

🆕 이 파일 형식에서 처음 나오는 것

YAML (와이엠엘)
「이름: 값」을 줄마다 적고, 들여쓰기로 안에 든 것을 나타내는 설정 파일 형식이다. 중괄호 대신 공백 두 칸이 「이 안에 있다」는 뜻이라 들여쓰기가 틀리면 뜻이 바뀐다(탭 문자는 쓰지 않는다). # 뒤는 주석이다.
/turtle_drive: → ros__parameters:
맨 위는 노드 이름, 그 아래 ros__parameters:(밑줄 두 개)는 「이 아래가 파라미터다」라는 정해진 표시, 그 아래가 「파라미터 이름: 값」이다. 노드 이름 자리에 /**를 쓰면 「모든 노드」라는 뜻이 되는데, 이 과목에서는 노드 이름을 적는다.
--ros-args --params-file 파일
②절 -p의 파일 판이다. 파일 안에서 이 노드 이름 아래 적힌 값들로 파라미터를 선언한다.

4-2 예제에 적용 — 패키지 안 config/turtle_drive.yaml

파일은 패키지 안에 config/ 폴더를 만들어 둔다. 노드와 그 노드의 설정값이 같은 패키지에 있어야 git으로 함께 관리되고, 나중에 launch 파일이 찾을 수 있다(⑧절). 값은 튜닝해서 찾았다고 치고 속도 상한 0.8, 여유 2.0으로 적었다 — 기본값(1.2·1.0)과 달라야 파일이 먹었는지 눈으로 구별된다. 이 두 숫자는 이 자료에서 둔 가정이다. 코드는 v4 그대로다. 파일을 읽는 것은 rclcpp가 declare_parameter 안에서 해 준다.

5-1 개념 — 요청을 받아 일하고 응답을 채우는 콜백

거북이를 잠깐 세웠다가 다시 달리게 하고 싶다. 노드를 끄면 되지 않을까? 20회 ⑥절에서 본 대로 끄면 마지막 명령으로 1초쯤 더 가고, 다시 켜면 파라미터를 다시 줘야 한다. 토픽으로 「서라」를 보내는 것도 어색하다 — 받았는지, 정말 섰는지 답을 못 듣는다. 17회 ⑥절의 고르는 질문으로 보면 「계속 새로 나오는가? 아니다. 오래 걸리나? 아니다」 → 서비스다.

18회에서는 turtlesim이 가진 서비스(/spawn·/clear)를 부르기만 했다. 이번에는 우리 노드가 서비스 서버가 된다. 서버는 서비스 이름과 타입으로 만들고, 요청이 올 때마다 불릴 콜백을 넘긴다. 구독자와 같은 모양인데, 콜백이 인자를 둘 받는다 — 읽을 요청과 채울 응답. 콜백이 끝나면 rclcpp가 채워진 응답을 요청한 쪽에 돌려보낸다. 

srv_ = this->create_service<서비스타입>(
  "서비스 이름",
  [this](const 서비스타입::Request::SharedPtr req,     // 읽기만 한다
         서비스타입::Response::SharedPtr res) {        // 여기에 답을 채운다
    /* req->… 를 보고 일을 한 뒤 res->… 를 채운다 */
  });

타입은 새로 만들지 않고 ROS 2에 이미 있는 것을 쓴다. 「켜기·끄기」에 맞춰 만들어진 것이 있다.

$ ros2 interface show std_srvs/srv/SetBool
bool data # e.g. for hardware enabling / disabling
---
bool success   # indicate successful run of triggered service
string message # informational, e.g. for error messages

18회에서 본 대로 --- 위가 요청, 아래가 응답이다. 요청은 bool 하나(data — 주석에 「하드웨어를 켜고 끄는 데」라고 적혀 있다), 응답은 성공 여부(success)와 사람이 읽을 문장(message)이다. /clear의 std_srvs/srv/Empty와 같은 std_srvs 패키지에 들어 있다.

5-2 예제에 적용 — enabled_ 하나와 타이머 콜백 맨 앞 네 줄

노드에 「주행이 켜져 있나」를 뜻하는 enabled_(처음에는 켜짐)를 두고, 서비스 콜백은 그 값만 바꾼다. 실제로 세우는 일은 지금처럼 타이머 콜백이 한다 — 맨 앞에서 「꺼져 있으면 0인 Twist(20회의 「서라」)만 보내고 돌아간다」를 넣는다. 서비스 콜백에서 직접 0인 Twist를 보내도 되지만, 그러면 0.5초 뒤 타이머가 또 무작위 속도를 보낸다. 속도 명령을 보내는 곳은 타이머 콜백 한 곳으로 두는 편이 무엇이 언제 나가는지 읽기 쉽다.

// 21회 turtle_drive — v5 (5단계: create_service — ~/enable 서비스(std_srvs/srv/SetBool)로 주행을 켜고 끈다)
#include <algorithm>
#include <chrono>
#include <cmath>
#include <memory>
#include <random>

#include "rclcpp/rclcpp.hpp"
#include "geometry_msgs/msg/twist.hpp"
#include "turtlesim/msg/pose.hpp"
#include "std_srvs/srv/set_bool.hpp"

using namespace std::chrono_literals;

class TurtleDrive : public rclcpp::Node
{
public:
  TurtleDrive()
  : Node("turtle_drive")
  {
    // 파라미터를 선언한다 — 이름과 기본값. 타입은 기본값에서 정해진다 (1.2 이므로 double)
    this->declare_parameter("max_speed", 1.2);
    this->declare_parameter("margin", 1.0);
    read_parameters();

    cmd_pub_ = this->create_publisher<geometry_msgs::msg::Twist>("/turtle1/cmd_vel", 10);
    pose_sub_ = this->create_subscription<turtlesim::msg::Pose>(
      "/turtle1/pose", 10,
      [this](turtlesim::msg::Pose::ConstSharedPtr msg) { on_pose(msg); });
    enable_srv_ = this->create_service<std_srvs::srv::SetBool>(
      "~/enable",
      [this](const std_srvs::srv::SetBool::Request::SharedPtr req,
             std_srvs::srv::SetBool::Response::SharedPtr res) { on_enable(req, res); });
    timer_ = this->create_wall_timer(500ms, [this]() { on_timer(); });
    RCLCPP_INFO(this->get_logger(), "max_speed = %.2f m/s, margin = %.2f m (%.1f ~ %.1f 안에서 돌아다닙니다)",
                max_speed_, margin_, margin_, map_size_ - margin_);
  }

private:
  // 파라미터의 지금 값을 읽어 멤버에 넣는다 — 생성자에서 한 번, 그 뒤로는 타이머가 부를 때마다
  void read_parameters()
  {
    max_speed_ = this->get_parameter("max_speed").as_double();
    margin_ = this->get_parameter("margin").as_double();
  }

  // /turtle1/pose 가 올 때마다 불린다 — 받은 것을 들고 있기만 한다
  void on_pose(turtlesim::msg::Pose::ConstSharedPtr msg)
  {
    pose_ = msg;
  }

  // ~/enable 서비스가 불릴 때마다 — 요청의 data 가 true 면 달리고 false 면 선다
  void on_enable(const std_srvs::srv::SetBool::Request::SharedPtr req,
                 std_srvs::srv::SetBool::Response::SharedPtr res)
  {
    enabled_ = req->data;
    res->success = true;
    res->message = enabled_ ? "주행을 켭니다" : "주행을 끕니다";
    RCLCPP_INFO(this->get_logger(), "~/enable 요청: %s", res->message.c_str());
  }

  // 타이머가 0.5초마다 부른다 — 판단하고 명령을 보낸다
  void on_timer()
  {
    if (!pose_) {                                // 아직 자세를 한 번도 못 받았다
      return;
    }
    if (!enabled_) {                             // 주행이 꺼졌다 — 0 인 명령(「서라」)만 보낸다
      cmd_pub_->publish(geometry_msgs::msg::Twist());
      return;
    }
    read_parameters();                           // 밖에서(ros2 param set) 바뀌었을 수 있으니 판단 전에 다시 읽는다
    const double lo = margin_;
    const double hi = map_size_ - margin_;
    const bool outside = pose_->x < lo || pose_->x > hi || pose_->y < lo || pose_->y > hi;
    const double angle = angle_to_center(*pose_);
    const bool turn_back = outside && angle > turn_tolerance_;   // 범위 밖인데 중앙을 안 보고 있다

    if (turn_back && !turning_) {
      RCLCPP_INFO(this->get_logger(), "범위 밖 (x = %.2f, y = %.2f) — 중앙 쪽으로 돕니다", pose_->x, pose_->y);
    }
    if (!turn_back && turning_) {
      RCLCPP_INFO(this->get_logger(), "중앙을 봅니다 — 다시 출발합니다");
    }
    turning_ = turn_back;

    geometry_msgs::msg::Twist cmd;               // 여섯 칸이 전부 0 으로 시작한다
    if (turn_back) {
      cmd.angular.z = 1.0;                       // 제자리에서 왼쪽으로 돈다 (linear.x 는 0)
    } else {
      cmd.linear.x = random_between(0.2, max_speed_);
      cmd.angular.z = random_between(-1.0, 1.0);
    }
    cmd_pub_->publish(cmd);
  }

  // 바라보는 방향과 「중앙으로 가는 방향」 사이의 각 (0 ~ π rad)
  double angle_to_center(const turtlesim::msg::Pose & p) const
  {
    const double dx = center_ - p.x;             // 중앙으로 가는 방향
    const double dy = center_ - p.y;
    const double hx = std::cos(p.theta);         // 바라보는 방향 (길이 1)
    const double hy = std::sin(p.theta);
    const double cos_angle = (dx * hx + dy * hy) / std::hypot(dx, dy);   // 내적 ÷ 두 길이의 곱
    return std::acos(std::clamp(cos_angle, -1.0, 1.0));
  }

  // lo 와 hi 사이의 실수 하나를 고르게 뽑는다
  double random_between(double lo, double hi)
  {
    std::uniform_real_distribution<double> dist(lo, hi);
    return dist(gen_);
  }

  double max_speed_ = 0.0;             // 파라미터 max_speed 에서 읽는다 (m/s)
  double margin_ = 0.0;                // 파라미터 margin 에서 읽는다 (m)
  const double map_size_ = 11.0;       // 지도 한 변의 길이 (m)
  const double center_ = 5.5;          // 지도 가운데 (x, y 모두)
  const double turn_tolerance_ = 0.35; // 중앙과 이 각(약 20°) 안이면 다시 출발한다 (rad)
  bool turning_ = false;               // 지금 돌아서는 중인가 — 로그를 바뀔 때만 찍는 데 쓴다
  bool enabled_ = true;                // ~/enable 서비스로 바뀐다. 처음에는 켜져 있다

  std::mt19937 gen_{std::random_device{}()};   // 난수 생성기 — 실행할 때마다 다른 씨앗으로 시작한다
  rclcpp::Publisher<geometry_msgs::msg::Twist>::SharedPtr cmd_pub_;
  rclcpp::Subscription<turtlesim::msg::Pose>::SharedPtr pose_sub_;
  rclcpp::Service<std_srvs::srv::SetBool>::SharedPtr enable_srv_;
  rclcpp::TimerBase::SharedPtr timer_;
  turtlesim::msg::Pose::ConstSharedPtr pose_;  // 마지막으로 받은 자세 (처음에는 비어 있다)
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  auto node = std::make_shared<TurtleDrive>();
  rclcpp::spin(node);            // 타이머·구독 콜백은 이 안에서 불린다
  rclcpp::shutdown();
  return 0;
}

6-1 개념 — 요청을 보내 두고, 응답은 콜백으로 받는다

이번에는 반대 방향이다. 우리 노드가 남의 서비스를 부른다. turtlesim에는 거북이가 그리는 선의 색과 굵기를 바꾸는 서비스가 있다.

요청은 색(r·g·b, 0~255)과 굵기(width), 펜을 들지(off가 1이면 선을 안 그린다)이고, --- 아래 응답은 비어 있다. 그래도 응답은 돌아온다 — SetPen_Response()가 찍혔다. 빈 응답이 「처리했다」는 신호다.

코드에서 서비스를 부르는 쪽을 서비스 클라이언트라고 한다. 서비스 이름과 타입으로 만들고, 요청 메시지를 채워 보낸다. 여기서 하나를 정해야 한다. 보낸 뒤 응답이 올 때까지 그 자리에서 기다릴까? 우리 노드에서 요청을 보내는 곳은 타이머 콜백 안이다. 20회 ③절의 규칙 — 기본 spin은 콜백을 한 번에 하나씩 부른다 — 을 떠올리면, 콜백 안에서 기다리는 동안에는 다른 콜백이 하나도 불리지 않는다. 그런데 응답을 받아 넘겨주는 일도 spin이 한다. 그래서 rclcpp 클라이언트는 보내고 바로 돌아오는 함수 하나만 준다.

req->r = 255;
pen_client_->async_send_request(req, [this](rclcpp::Client<turtlesim::srv::SetPen>::SharedFuture) {

      RCLCPP_INFO(this->get_logger(), "범위 밖 (x = %.2f, y = %.2f) — 중앙 쪽으로 돕니다", pose_->x, pose_->y);
      change_pen();
    }
  // …
  // /turtle1/set_pen 에 무작위 펜 색을 요청한다 — 다시 출발하면 그 색으로 선이 그려진다
  void change_pen()
  {
    if (!pen_client_->service_is_ready()) {   // 서버(turtlesim)가 아직 없으면 이번에는 건너뛴다
      RCLCPP_WARN(this->get_logger(), "/turtle1/set_pen 서비스가 아직 없습니다");
      return;
    }
    auto req = std::make_shared<turtlesim::srv::SetPen::Request>();
    req->r = random_int_between(0, 255);       // 빨강·초록·파랑 세 값이 각각 0 ~ 255
    req->g = random_int_between(0, 255);
    req->b = random_int_between(0, 255);
    req->width = 5;                            // 선 굵기 (기본은 3)
    RCLCPP_INFO(this->get_logger(), "펜 색 (%d, %d, %d) 을 요청합니다", req->r, req->g, req->b);
    // 보내고 바로 돌아온다. 응답이 오면 spin 이 이 람다를 불러 준다
    pen_client_->async_send_request(
      req, [this](rclcpp::Client<turtlesim::srv::SetPen>::SharedFuture) {
        RCLCPP_INFO(this->get_logger(), "펜 색을 바꿨다는 응답이 왔습니다");
      });
  }

  // lo 와 hi 사이의 정수 하나를 고르게 뽑는다 (lo 와 hi 도 나올 수 있다)
  int random_int_between(int lo, int hi)
  {
    std::uniform_int_distribution<int> dist(lo, hi);
    return dist(gen_);
  }
  // … 멤버
  rclcpp::Client<turtlesim::srv::SetPen>::SharedPtr pen_client_;

🆕 이 코드에서 처음 나오는 것

this->create_client<T>("이름")
T 타입 서비스를 부르는 클라이언트를 만든다. 만드는 것만으로는 아무것도 보내지 않는다. 멤버 타입은 rclcpp::Client<T>::SharedPtr.
pen_client_->service_is_ready()
그 이름의 서버가 지금 떠 있으면 true. 기다리지 않고 바로 답한다. turtlesim이 꺼졌을 때 보내지 않으려고 썼다.
async_send_request(req, 콜백)
요청을 보내고 바로 돌아온다(async = 비동기, 「기다리지 않는다」). 응답이 도착하면 spin이 둘째 인자의 콜백을 부른다. 여기서는 보내기 직전에 「요청합니다」를, 응답이 오면 「응답이 왔습니다」를 찍어 둘의 순서가 보이게 했다.
rclcpp::Client<T>::SharedFuture
응답 콜백이 받는 인자. 「나중에 채워질 응답」을 담는 상자(future)이고, 콜백이 불릴 때는 이미 채워져 있어 .get()으로 응답을 꺼낼 수 있다. SetPen은 응답이 비어 있어서 꺼내지 않았다.
std::uniform_int_distribution<int>(lo, hi)
20회 uniform_real_distribution의 정수판. 생성기가 낸 수를 「lo와 hi 사이에 고르게 퍼진 정수」로 바꾼다. 실수판과 달리 hi도 나온다 — (0, 255)면 0부터 255까지 256가지다. 생성기 gen_은 20회의 것을 그대로 같이 쓴다.

SetPen의 r·g·b는 uint8(0~255를 담는 부호 없는 8비트 정수) 필드라서, 실수를 뽑는 random_between 대신 정수를 뽑는 random_int_between을 하나 더 두었다. 뽑은 int는 대입할 때 필드 타입으로 바뀐다. 람다의 캡처 목록은 20회와 같은 [this]다. 색은 보내기 전에 req에서 찍었으니 응답 콜백이 색을 알 필요가 없다. SetPen은 이미 의존성에 있는 turtlesim 패키지의 타입이라 CMakeLists.txt·package.xml은 그대로다.

⚠️ 콜백 안에서 응답을 기다리면 노드 전체가 멈춘다

「응답을 받은 뒤에 로그를 찍고 싶다」는 생각으로 change_pen()의 끝을 이렇게 바꾸는 코드를 AI에게서 자주 받는다. 빌드는 된다. 

    // 보내고, 응답이 올 때까지 여기서 기다린다
    auto future = pen_client_->async_send_request(req);
    future.wait();
    RCLCPP_INFO(this->get_logger(), "펜 색을 바꿨다는 응답이 왔습니다");

future.wait()가 타이머 콜백 안에서 응답을 기다린다. 응답은 컴퓨터에 도착했지만, 그것을 꺼내 future를 채워 주는 일은 spin이 하고, spin은 지금 이 콜백이 끝나기를 기다리고 있다. 서로가 서로를 기다리는 이 상태를 교착(deadlock)이라고 한다. Ctrl+C는 signal_handler 줄이 찍히듯 받아들여지지만, spin이 돌아오려면 지금 도는 콜백이 먼저 끝나야 해서 프로그램이 끝나지 않는다(여러분 터미널에서 이렇게 되면 그 터미널 창을 닫는다). 타이머도 다시 안 불리니 cmd_vel이 끊기고(hz가 조용하다), ~/enable 요청도 처리되지 않는다. 거북이는 「돌아라」를 받기 전에 노드가 멈춰서, 마지막 무작위 명령대로 조금 더 가다가 turtlesim의 타임아웃(20회 ⑥절)으로 y = 10.84에 섰다. 서비스 이름이 맞는데(service list에 있는데) call이 응답 없이 서 있으면, 18회의 「이름을 틀렸다」가 아니라 서버 노드가 막혀 있는 것이다.

turtle_drive/src/turtle_drive.cpp
// 21회 turtle_drive — v6 (6단계: create_client · async_send_request — 돌아설 때마다 /turtle1/set_pen 으로 펜 색을 바꾼다)
#include <algorithm>
#include <chrono>
#include <cmath>
#include <memory>
#include <random>

#include "rclcpp/rclcpp.hpp"
#include "geometry_msgs/msg/twist.hpp"
#include "turtlesim/msg/pose.hpp"
#include "std_srvs/srv/set_bool.hpp"
#include "turtlesim/srv/set_pen.hpp"

using namespace std::chrono_literals;

class TurtleDrive : public rclcpp::Node
{
public:
  TurtleDrive()
  : Node("turtle_drive")
  {
    // 파라미터를 선언한다 — 이름과 기본값. 타입은 기본값에서 정해진다 (1.2 이므로 double)
    this->declare_parameter("max_speed", 1.2);
    this->declare_parameter("margin", 1.0);
    read_parameters();

    cmd_pub_ = this->create_publisher<geometry_msgs::msg::Twist>("/turtle1/cmd_vel", 10);
    pose_sub_ = this->create_subscription<turtlesim::msg::Pose>(
      "/turtle1/pose", 10,
      [this](turtlesim::msg::Pose::ConstSharedPtr msg) { on_pose(msg); });
    enable_srv_ = this->create_service<std_srvs::srv::SetBool>(
      "~/enable",
      [this](const std_srvs::srv::SetBool::Request::SharedPtr req,
             std_srvs::srv::SetBool::Response::SharedPtr res) { on_enable(req, res); });
    pen_client_ = this->create_client<turtlesim::srv::SetPen>("/turtle1/set_pen");
    timer_ = this->create_wall_timer(500ms, [this]() { on_timer(); });
    RCLCPP_INFO(this->get_logger(), "max_speed = %.2f m/s, margin = %.2f m (%.1f ~ %.1f 안에서 돌아다닙니다)",
                max_speed_, margin_, margin_, map_size_ - margin_);
  }

private:
  // 파라미터의 지금 값을 읽어 멤버에 넣는다 — 생성자에서 한 번, 그 뒤로는 타이머가 부를 때마다
  void read_parameters()
  {
    max_speed_ = this->get_parameter("max_speed").as_double();
    margin_ = this->get_parameter("margin").as_double();
  }

  // /turtle1/pose 가 올 때마다 불린다 — 받은 것을 들고 있기만 한다
  void on_pose(turtlesim::msg::Pose::ConstSharedPtr msg)
  {
    pose_ = msg;
  }

  // ~/enable 서비스가 불릴 때마다 — 요청의 data 가 true 면 달리고 false 면 선다
  void on_enable(const std_srvs::srv::SetBool::Request::SharedPtr req,
                 std_srvs::srv::SetBool::Response::SharedPtr res)
  {
    enabled_ = req->data;
    res->success = true;
    res->message = enabled_ ? "주행을 켭니다" : "주행을 끕니다";
    RCLCPP_INFO(this->get_logger(), "~/enable 요청: %s", res->message.c_str());
  }

  // 타이머가 0.5초마다 부른다 — 판단하고 명령을 보낸다
  void on_timer()
  {
    if (!pose_) {                                // 아직 자세를 한 번도 못 받았다
      return;
    }
    if (!enabled_) {                             // 주행이 꺼졌다 — 0 인 명령(「서라」)만 보낸다
      cmd_pub_->publish(geometry_msgs::msg::Twist());
      return;
    }
    read_parameters();                           // 밖에서(ros2 param set) 바뀌었을 수 있으니 판단 전에 다시 읽는다
    const double lo = margin_;
    const double hi = map_size_ - margin_;
    const bool outside = pose_->x < lo || pose_->x > hi || pose_->y < lo || pose_->y > hi;
    const double angle = angle_to_center(*pose_);
    const bool turn_back = outside && angle > turn_tolerance_;   // 범위 밖인데 중앙을 안 보고 있다

    if (turn_back && !turning_) {
      RCLCPP_INFO(this->get_logger(), "범위 밖 (x = %.2f, y = %.2f) — 중앙 쪽으로 돕니다", pose_->x, pose_->y);
      change_pen();
    }
    if (!turn_back && turning_) {
      RCLCPP_INFO(this->get_logger(), "중앙을 봅니다 — 다시 출발합니다");
    }
    turning_ = turn_back;

    geometry_msgs::msg::Twist cmd;               // 여섯 칸이 전부 0 으로 시작한다
    if (turn_back) {
      cmd.angular.z = 1.0;                       // 제자리에서 왼쪽으로 돈다 (linear.x 는 0)
    } else {
      cmd.linear.x = random_between(0.2, max_speed_);
      cmd.angular.z = random_between(-1.0, 1.0);
    }
    cmd_pub_->publish(cmd);
  }

  // /turtle1/set_pen 에 무작위 펜 색을 요청한다 — 다시 출발하면 그 색으로 선이 그려진다
  void change_pen()
  {
    if (!pen_client_->service_is_ready()) {   // 서버(turtlesim)가 아직 없으면 이번에는 건너뛴다
      RCLCPP_WARN(this->get_logger(), "/turtle1/set_pen 서비스가 아직 없습니다");
      return;
    }
    auto req = std::make_shared<turtlesim::srv::SetPen::Request>();
    req->r = random_int_between(0, 255);       // 빨강·초록·파랑 세 값이 각각 0 ~ 255
    req->g = random_int_between(0, 255);
    req->b = random_int_between(0, 255);
    req->width = 5;                            // 선 굵기 (기본은 3)
    RCLCPP_INFO(this->get_logger(), "펜 색 (%d, %d, %d) 을 요청합니다", req->r, req->g, req->b);
    // 보내고 바로 돌아온다. 응답이 오면 spin 이 이 람다를 불러 준다
    pen_client_->async_send_request(
      req, [this](rclcpp::Client<turtlesim::srv::SetPen>::SharedFuture) {
        RCLCPP_INFO(this->get_logger(), "펜 색을 바꿨다는 응답이 왔습니다");
      });
  }

  // 바라보는 방향과 「중앙으로 가는 방향」 사이의 각 (0 ~ π rad)
  double angle_to_center(const turtlesim::msg::Pose & p) const
  {
    const double dx = center_ - p.x;             // 중앙으로 가는 방향
    const double dy = center_ - p.y;
    const double hx = std::cos(p.theta);         // 바라보는 방향 (길이 1)
    const double hy = std::sin(p.theta);
    const double cos_angle = (dx * hx + dy * hy) / std::hypot(dx, dy);   // 내적 ÷ 두 길이의 곱
    return std::acos(std::clamp(cos_angle, -1.0, 1.0));
  }

  // lo 와 hi 사이의 실수 하나를 고르게 뽑는다
  double random_between(double lo, double hi)
  {
    std::uniform_real_distribution<double> dist(lo, hi);
    return dist(gen_);
  }

  // lo 와 hi 사이의 정수 하나를 고르게 뽑는다 (lo 와 hi 도 나올 수 있다)
  int random_int_between(int lo, int hi)
  {
    std::uniform_int_distribution<int> dist(lo, hi);
    return dist(gen_);
  }

  double max_speed_ = 0.0;             // 파라미터 max_speed 에서 읽는다 (m/s)
  double margin_ = 0.0;                // 파라미터 margin 에서 읽는다 (m)
  const double map_size_ = 11.0;       // 지도 한 변의 길이 (m)
  const double center_ = 5.5;          // 지도 가운데 (x, y 모두)
  const double turn_tolerance_ = 0.35; // 중앙과 이 각(약 20°) 안이면 다시 출발한다 (rad)
  bool turning_ = false;               // 지금 돌아서는 중인가 — 로그를 바뀔 때만 찍는 데 쓴다
  bool enabled_ = true;                // ~/enable 서비스로 바뀐다. 처음에는 켜져 있다

// 21회 turtle_drive — v6 변형 (응답을 타이머 콜백 안에서 기다리는 판 · 빌드는 되고 처음 돌아설 때 멈춘다)
#include <algorithm>
#include <chrono>
#include <cmath>
#include <memory>
#include <random>

#include "rclcpp/rclcpp.hpp"
#include "geometry_msgs/msg/twist.hpp"
#include "turtlesim/msg/pose.hpp"
#include "std_srvs/srv/set_bool.hpp"
#include "turtlesim/srv/set_pen.hpp"

using namespace std::chrono_literals;

class TurtleDrive : public rclcpp::Node
{
public:
  TurtleDrive()
  : Node("turtle_drive")
  {
    // 파라미터를 선언한다 — 이름과 기본값. 타입은 기본값에서 정해진다 (1.2 이므로 double)
    this->declare_parameter("max_speed", 1.2);
    this->declare_parameter("margin", 1.0);
    read_parameters();

    cmd_pub_ = this->create_publisher<geometry_msgs::msg::Twist>("/turtle1/cmd_vel", 10);
    pose_sub_ = this->create_subscription<turtlesim::msg::Pose>(
      "/turtle1/pose", 10,
      [this](turtlesim::msg::Pose::ConstSharedPtr msg) { on_pose(msg); });
    enable_srv_ = this->create_service<std_srvs::srv::SetBool>(
      "~/enable",
      [this](const std_srvs::srv::SetBool::Request::SharedPtr req,
             std_srvs::srv::SetBool::Response::SharedPtr res) { on_enable(req, res); });
    pen_client_ = this->create_client<turtlesim::srv::SetPen>("/turtle1/set_pen");
    timer_ = this->create_wall_timer(500ms, [this]() { on_timer(); });
    RCLCPP_INFO(this->get_logger(), "max_speed = %.2f m/s, margin = %.2f m (%.1f ~ %.1f 안에서 돌아다닙니다)",
                max_speed_, margin_, margin_, map_size_ - margin_);
  }

private:
  // 파라미터의 지금 값을 읽어 멤버에 넣는다 — 생성자에서 한 번, 그 뒤로는 타이머가 부를 때마다
  void read_parameters()
  {
    max_speed_ = this->get_parameter("max_speed").as_double();
    margin_ = this->get_parameter("margin").as_double();
  }

  // /turtle1/pose 가 올 때마다 불린다 — 받은 것을 들고 있기만 한다
  void on_pose(turtlesim::msg::Pose::ConstSharedPtr msg)
  {
    pose_ = msg;
  }

  // ~/enable 서비스가 불릴 때마다 — 요청의 data 가 true 면 달리고 false 면 선다
  void on_enable(const std_srvs::srv::SetBool::Request::SharedPtr req,
                 std_srvs::srv::SetBool::Response::SharedPtr res)
  {
    enabled_ = req->data;
    res->success = true;
    res->message = enabled_ ? "주행을 켭니다" : "주행을 끕니다";
    RCLCPP_INFO(this->get_logger(), "~/enable 요청: %s", res->message.c_str());
  }

  // 타이머가 0.5초마다 부른다 — 판단하고 명령을 보낸다
  void on_timer()
  {
    if (!pose_) {                                // 아직 자세를 한 번도 못 받았다
      return;
    }
    if (!enabled_) {                             // 주행이 꺼졌다 — 0 인 명령(「서라」)만 보낸다
      cmd_pub_->publish(geometry_msgs::msg::Twist());
      return;
    }
    read_parameters();                           // 밖에서(ros2 param set) 바뀌었을 수 있으니 판단 전에 다시 읽는다
    const double lo = margin_;
    const double hi = map_size_ - margin_;
    const bool outside = pose_->x < lo || pose_->x > hi || pose_->y < lo || pose_->y > hi;
    const double angle = angle_to_center(*pose_);
    const bool turn_back = outside && angle > turn_tolerance_;   // 범위 밖인데 중앙을 안 보고 있다

    if (turn_back && !turning_) {
      RCLCPP_INFO(this->get_logger(), "범위 밖 (x = %.2f, y = %.2f) — 중앙 쪽으로 돕니다", pose_->x, pose_->y);
      change_pen();
    }
    if (!turn_back && turning_) {
      RCLCPP_INFO(this->get_logger(), "중앙을 봅니다 — 다시 출발합니다");
    }
    turning_ = turn_back;

    geometry_msgs::msg::Twist cmd;               // 여섯 칸이 전부 0 으로 시작한다
    if (turn_back) {
      cmd.angular.z = 1.0;                       // 제자리에서 왼쪽으로 돈다 (linear.x 는 0)
    } else {
      cmd.linear.x = random_between(0.2, max_speed_);
      cmd.angular.z = random_between(-1.0, 1.0);
    }
    cmd_pub_->publish(cmd);
  }

  // /turtle1/set_pen 에 무작위 펜 색을 요청한다 — 다시 출발하면 그 색으로 선이 그려진다
  void change_pen()
  {
    if (!pen_client_->service_is_ready()) {   // 서버(turtlesim)가 아직 없으면 이번에는 건너뛴다
      RCLCPP_WARN(this->get_logger(), "/turtle1/set_pen 서비스가 아직 없습니다");
      return;
    }
    auto req = std::make_shared<turtlesim::srv::SetPen::Request>();
    req->r = random_int_between(0, 255);       // 빨강·초록·파랑 세 값이 각각 0 ~ 255
    req->g = random_int_between(0, 255);
    req->b = random_int_between(0, 255);
    req->width = 5;                            // 선 굵기 (기본은 3)
    RCLCPP_INFO(this->get_logger(), "펜 색 (%d, %d, %d) 을 요청합니다", req->r, req->g, req->b);
    // 보내고, 응답이 올 때까지 여기서 기다린다
    auto future = pen_client_->async_send_request(req);
    future.wait();
    RCLCPP_INFO(this->get_logger(), "펜 색을 바꿨다는 응답이 왔습니다");
  }

  // 바라보는 방향과 「중앙으로 가는 방향」 사이의 각 (0 ~ π rad)
  double angle_to_center(const turtlesim::msg::Pose & p) const
  {
    const double dx = center_ - p.x;             // 중앙으로 가는 방향
    const double dy = center_ - p.y;
    const double hx = std::cos(p.theta);         // 바라보는 방향 (길이 1)
    const double hy = std::sin(p.theta);
    const double cos_angle = (dx * hx + dy * hy) / std::hypot(dx, dy);   // 내적 ÷ 두 길이의 곱
    return std::acos(std::clamp(cos_angle, -1.0, 1.0));
  }

  // lo 와 hi 사이의 실수 하나를 고르게 뽑는다
  double random_between(double lo, double hi)
  {
    std::uniform_real_distribution<double> dist(lo, hi);
    return dist(gen_);
  }

  // lo 와 hi 사이의 정수 하나를 고르게 뽑는다 (lo 와 hi 도 나올 수 있다)
  int random_int_between(int lo, int hi)
  {
    std::uniform_int_distribution<int> dist(lo, hi);
    return dist(gen_);
  }

  double max_speed_ = 0.0;             // 파라미터 max_speed 에서 읽는다 (m/s)
  double margin_ = 0.0;                // 파라미터 margin 에서 읽는다 (m)
  const double map_size_ = 11.0;       // 지도 한 변의 길이 (m)
  const double center_ = 5.5;          // 지도 가운데 (x, y 모두)
  const double turn_tolerance_ = 0.35; // 중앙과 이 각(약 20°) 안이면 다시 출발한다 (rad)
  bool turning_ = false;               // 지금 돌아서는 중인가 — 로그를 바뀔 때만 찍는 데 쓴다
  bool enabled_ = true;                // ~/enable 서비스로 바뀐다. 처음에는 켜져 있다

  std::mt19937 gen_{std::random_device{}()};   // 난수 생성기 — 실행할 때마다 다른 씨앗으로 시작한다
  rclcpp::Publisher<geometry_msgs::msg::Twist>::SharedPtr cmd_pub_;
  rclcpp::Subscription<turtlesim::msg::Pose>::SharedPtr pose_sub_;
  rclcpp::Service<std_srvs::srv::SetBool>::SharedPtr enable_srv_;
  rclcpp::Client<turtlesim::srv::SetPen>::SharedPtr pen_client_;
  rclcpp::TimerBase::SharedPtr timer_;
  turtlesim::msg::Pose::ConstSharedPtr pose_;  // 마지막으로 받은 자세 (처음에는 비어 있다)
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  auto node = std::make_shared<TurtleDrive>();
  rclcpp::spin(node);            // 타이머·구독 콜백은 이 안에서 불린다
  rclcpp::shutdown();
  return 0;
}

7-1 개념 — 무엇을 어떤 설정으로 띄울지 적어 둔 파일

지금 turtle_drive를 시험하려면 무엇을 쳐야 할까? 터미널 1에서 turtlesim, 터미널 2에서 source install/setup.bash를 하고 turtle_drive를 --params-file과 함께. 두 개라 아직 할 만하다. 그런데 기말 프로젝트에서는 로봇 쪽 bringup, 내 주행 노드, rviz2까지 셋이 넘고, 그것을 시험할 때마다 친다. 한 번이라도 파라미터 파일을 빠뜨리고 띄우면 기본값으로 달린다 — ④절에서 본 대로 아무 말 없이. 「매번 같은 것을 같은 순서로 친다」는 것은 스크립트로 적어 둘 일이라는 신호다(3회의 쉘 스크립트와 같은 생각).

ROS 2에서 그 역할을 하는 것이 launch 파일이다. 「어느 패키지의 어느 실행 파일을, 어떤 이름과 파라미터로 띄울지」를 노드마다 적어 두면 ros2 launch 패키지 파일 한 줄이 그 노드들을 한꺼번에 띄우고, Ctrl+C 한 번에 한꺼번에 끈다. launch 파일은 파이썬·XML·YAML 세 형식으로 쓸 수 있는데, 공식 문서의 예제와 AI가 주는 답은 대부분 파이썬(.launch.py)이다. 이 과목에서는 파이썬을 배우지 않았으니 쓰는 것은 에이전트에게 맡기고, 우리는 읽고 검사한다. 읽는 데 필요한 것은 아래 몇 줄이면 된다.

들여쓰기 · 콜론 :
파이썬에는 중괄호가 없다. def …: 다음 줄부터 들여 쓴 줄들이 그 함수의 몸이다. 그래서 들여쓰기를 바꾸면 뜻이 바뀐다 — ④절 YAML과 같은 규칙이다.
이름=값 (keyword argument)
인자를 순서가 아니라 이름으로 넘긴다. Node(package='turtlesim', …)는 「package 칸에 'turtlesim'」이다. 순서를 바꿔 적어도 같다. 마지막 인자 뒤의 쉼표는 있어도 된다.
'문자열' · [목록]
작은따옴표도 큰따옴표처럼 문자열이다. 대괄호는 목록(C++의 vector와 비슷)이다 — parameters=[params]는 원소 하나짜리 목록이다. 파라미터 파일을 여럿 줄 수 있어서 목록을 받는다.
get_package_share_directory('turtle_drive')
그 패키지의 설치된 share/ 폴더 경로를 돌려준다. 16회의 ros2 pkg prefix가 찾던 자리 아래의 share/turtle_drive다. 그 폴더에 YAML이 설치돼 있어야 이 경로가 의미가 있다 — ⑧절.
os.path.join(a, b, c)
폴더 이름들을 /로 이어 경로 하나를 만든다.

파이썬 자체는 이 과목에서 다루지 않는다. launch 파일은 이 표 수준으로 읽을 수 있으면 된다.

파일 이름 turtle_drive.launch.py와 노드 이름 turtle_drive, 패키지 이름 turtle_drive가 모두 같은 글자라 헷갈릴 수 있다. package=는 패키지, executable=은 ros2 pkg executables에 보이는 실행 파일, name=은 그래프에 뜰 노드 이름이다. 셋이 같은 이름인 것은 우리가 그렇게 지었기 때문이다.

이 launch 파일을 줄마다 읽어 줘. 표로 「줄 · 하는 일 · 같은 일을 터미널에서 하면 어떤 명령인가」를 적어 줘. 특히 각 Node 가 실제로 어떤 ros2 run … --ros-args … 명령이 되는지, parameters 로 주는 YAML 파일의 실제 경로가 어디인지, 그 파일이 지금 install/ 아래에 정말 있는지 ls 로 확인해서 보여 줘.

7-3 7단계 (v7) — 파일 둘을 설치하고, launch 실행 의존성을 적는다

launch 파일을 만들었다고 바로 ros2 launch turtle_drive turtle_drive.launch.py가 되지는 않는다. ros2 launch는 그 파일을 설치된 자리(install/turtle_drive/share/turtle_drive/)에서 찾기 때문이다. 19회 「조금 더 알아두면」에서 예고한 install()의 두 번째 모양이 여기서 나온다. 그리고 launch는 실행할 때만 필요한 도구라 package.xml에 exec_depend로 적는다.

install(TARGETS hello_node turtle_drive
  DESTINATION lib/${PROJECT_NAME})

🆕 이 파일에서 처음 나오는 것

install(TARGETS …)가 빌드 결과물을 옮겼다면 이것은 폴더를 통째로 옮긴다. launch/와 config/가 install/turtle_drive/share/turtle_drive/launch/·…/config/로 복사된다. 실행 파일은 lib/, 나머지 파일은 share/다.

// 21회 turtle_drive — v7 (7단계: launch 파일로 turtlesim 과 함께 띄운다. 이 파일은 v6 과 같다)
#include <algorithm>
#include <chrono>
#include <cmath>
#include <memory>
#include <random>

#include "rclcpp/rclcpp.hpp"
#include "geometry_msgs/msg/twist.hpp"
#include "turtlesim/msg/pose.hpp"
#include "std_srvs/srv/set_bool.hpp"
#include "turtlesim/srv/set_pen.hpp"

using namespace std::chrono_literals;

class TurtleDrive : public rclcpp::Node
{
public:
  TurtleDrive()
  : Node("turtle_drive")
  {
    // 파라미터를 선언한다 — 이름과 기본값. 타입은 기본값에서 정해진다 (1.2 이므로 double)
    this->declare_parameter("max_speed", 1.2);
    this->declare_parameter("margin", 1.0);
    read_parameters();

    cmd_pub_ = this->create_publisher<geometry_msgs::msg::Twist>("/turtle1/cmd_vel", 10);
    pose_sub_ = this->create_subscription<turtlesim::msg::Pose>(
      "/turtle1/pose", 10,
      [this](turtlesim::msg::Pose::ConstSharedPtr msg) { on_pose(msg); });
    enable_srv_ = this->create_service<std_srvs::srv::SetBool>(
      "~/enable",
      [this](const std_srvs::srv::SetBool::Request::SharedPtr req,
             std_srvs::srv::SetBool::Response::SharedPtr res) { on_enable(req, res); });
    pen_client_ = this->create_client<turtlesim::srv::SetPen>("/turtle1/set_pen");
    timer_ = this->create_wall_timer(500ms, [this]() { on_timer(); });
    RCLCPP_INFO(this->get_logger(), "max_speed = %.2f m/s, margin = %.2f m (%.1f ~ %.1f 안에서 돌아다닙니다)",
                max_speed_, margin_, margin_, map_size_ - margin_);
  }

private:
  // 파라미터의 지금 값을 읽어 멤버에 넣는다 — 생성자에서 한 번, 그 뒤로는 타이머가 부를 때마다
  void read_parameters()
  {
    max_speed_ = this->get_parameter("max_speed").as_double();
    margin_ = this->get_parameter("margin").as_double();
  }

  // /turtle1/pose 가 올 때마다 불린다 — 받은 것을 들고 있기만 한다
  void on_pose(turtlesim::msg::Pose::ConstSharedPtr msg)
  {
    pose_ = msg;
  }

  // ~/enable 서비스가 불릴 때마다 — 요청의 data 가 true 면 달리고 false 면 선다
  void on_enable(const std_srvs::srv::SetBool::Request::SharedPtr req,
                 std_srvs::srv::SetBool::Response::SharedPtr res)
  {
    enabled_ = req->data;
    res->success = true;
    res->message = enabled_ ? "주행을 켭니다" : "주행을 끕니다";
    RCLCPP_INFO(this->get_logger(), "~/enable 요청: %s", res->message.c_str());
  }

  // 타이머가 0.5초마다 부른다 — 판단하고 명령을 보낸다
  void on_timer()
  {
    if (!pose_) {                                // 아직 자세를 한 번도 못 받았다
      return;
    }
    if (!enabled_) {                             // 주행이 꺼졌다 — 0 인 명령(「서라」)만 보낸다
      cmd_pub_->publish(geometry_msgs::msg::Twist());
      return;
    }
    read_parameters();                           // 밖에서(ros2 param set) 바뀌었을 수 있으니 판단 전에 다시 읽는다
    const double lo = margin_;
    const double hi = map_size_ - margin_;
    const bool outside = pose_->x < lo || pose_->x > hi || pose_->y < lo || pose_->y > hi;
    const double angle = angle_to_center(*pose_);
    const bool turn_back = outside && angle > turn_tolerance_;   // 범위 밖인데 중앙을 안 보고 있다

    if (turn_back && !turning_) {
      RCLCPP_INFO(this->get_logger(), "범위 밖 (x = %.2f, y = %.2f) — 중앙 쪽으로 돕니다", pose_->x, pose_->y);
      change_pen();
    }
    if (!turn_back && turning_) {
      RCLCPP_INFO(this->get_logger(), "중앙을 봅니다 — 다시 출발합니다");
    }
    turning_ = turn_back;

    geometry_msgs::msg::Twist cmd;               // 여섯 칸이 전부 0 으로 시작한다
    if (turn_back) {
      cmd.angular.z = 1.0;                       // 제자리에서 왼쪽으로 돈다 (linear.x 는 0)
    } else {
      cmd.linear.x = random_between(0.2, max_speed_);
      cmd.angular.z = random_between(-1.0, 1.0);
    }
    cmd_pub_->publish(cmd);
  }

  // /turtle1/set_pen 에 무작위 펜 색을 요청한다 — 다시 출발하면 그 색으로 선이 그려진다
  void change_pen()
  {
    if (!pen_client_->service_is_ready()) {   // 서버(turtlesim)가 아직 없으면 이번에는 건너뛴다
      RCLCPP_WARN(this->get_logger(), "/turtle1/set_pen 서비스가 아직 없습니다");
      return;
    }
    auto req = std::make_shared<turtlesim::srv::SetPen::Request>();
    req->r = random_int_between(0, 255);       // 빨강·초록·파랑 세 값이 각각 0 ~ 255
    req->g = random_int_between(0, 255);
    req->b = random_int_between(0, 255);
    req->width = 5;                            // 선 굵기 (기본은 3)
    RCLCPP_INFO(this->get_logger(), "펜 색 (%d, %d, %d) 을 요청합니다", req->r, req->g, req->b);
    // 보내고 바로 돌아온다. 응답이 오면 spin 이 이 람다를 불러 준다
    pen_client_->async_send_request(
      req, [this](rclcpp::Client<turtlesim::srv::SetPen>::SharedFuture) {
        RCLCPP_INFO(this->get_logger(), "펜 색을 바꿨다는 응답이 왔습니다");
      });
  }

  // 바라보는 방향과 「중앙으로 가는 방향」 사이의 각 (0 ~ π rad)
  double angle_to_center(const turtlesim::msg::Pose & p) const
  {
    const double dx = center_ - p.x;             // 중앙으로 가는 방향
    const double dy = center_ - p.y;
    const double hx = std::cos(p.theta);         // 바라보는 방향 (길이 1)
    const double hy = std::sin(p.theta);
    const double cos_angle = (dx * hx + dy * hy) / std::hypot(dx, dy);   // 내적 ÷ 두 길이의 곱
    return std::acos(std::clamp(cos_angle, -1.0, 1.0));
  }

  // lo 와 hi 사이의 실수 하나를 고르게 뽑는다
  double random_between(double lo, double hi)
  {
    std::uniform_real_distribution<double> dist(lo, hi);
    return dist(gen_);
  }

  // lo 와 hi 사이의 정수 하나를 고르게 뽑는다 (lo 와 hi 도 나올 수 있다)
  int random_int_between(int lo, int hi)
  {
    std::uniform_int_distribution<int> dist(lo, hi);
    return dist(gen_);
  }

  double max_speed_ = 0.0;             // 파라미터 max_speed 에서 읽는다 (m/s)
  double margin_ = 0.0;                // 파라미터 margin 에서 읽는다 (m)
  const double map_size_ = 11.0;       // 지도 한 변의 길이 (m)
  const double center_ = 5.5;          // 지도 가운데 (x, y 모두)
  const double turn_tolerance_ = 0.35; // 중앙과 이 각(약 20°) 안이면 다시 출발한다 (rad)
  bool turning_ = false;               // 지금 돌아서는 중인가 — 로그를 바뀔 때만 찍는 데 쓴다
  bool enabled_ = true;                // ~/enable 서비스로 바뀐다. 처음에는 켜져 있다

  std::mt19937 gen_{std::random_device{}()};   // 난수 생성기 — 실행할 때마다 다른 씨앗으로 시작한다
  rclcpp::Publisher<geometry_msgs::msg::Twist>::SharedPtr cmd_pub_;
  rclcpp::Subscription<turtlesim::msg::Pose>::SharedPtr pose_sub_;
  rclcpp::Service<std_srvs::srv::SetBool>::SharedPtr enable_srv_;
  rclcpp::Client<turtlesim::srv::SetPen>::SharedPtr pen_client_;
  rclcpp::TimerBase::SharedPtr timer_;
  turtlesim::msg::Pose::ConstSharedPtr pose_;  // 마지막으로 받은 자세 (처음에는 비어 있다)
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  auto node = std::make_shared<TurtleDrive>();
  rclcpp::spin(node);            // 타이머·구독 콜백은 이 안에서 불린다
  rclcpp::shutdown();
  return 0;
}

~/ros_ws/src/turtle_drive 패키지를 아래 여덟 기준으로 검사해 줘. 고치지는 말고, 기준마다 「통과/어긋남」과 근거가 되는 파일·줄을 표로 보여 줘. (1) 속도·거리 같은 튜닝 값이 declare_parameter 로 선언돼 있다 (2) 실수 파라미터의 기본값에 소수점이 있다 (3) get_parameter 가 생성자뿐 아니라 실행 중(타이머 콜백 등)에도 불리거나 파라미터 콜백으로 멤버가 갱신된다 (4) config/*.yaml 맨 윗줄 노드 이름이 노드 생성자의 이름·launch 의 name 과 같다 (5) 어떤 콜백 안에도 future.wait, future.get, spin_until_future_complete, wait_for_service 반복이 없다 (6) CMakeLists.txt 에 install(DIRECTORY launch config DESTINATION share/${PROJECT_NAME}) 가 있다 (7) #include 하는 ROS 패키지가 package.xml 과 CMakeLists.txt 양쪽에 있고 launch 파일이 있으면 exec_depend ros2launch 가 있다 (8) launch 파일의 package·executable 이 실제 패키지·실행 파일 이름과 같다.

// 21회 연습문제 — wall_watch 원본 (파라미터·서비스·launch 가 없다. 숫자를 바꾸려면 다시 빌드해야 한다)
#include <algorithm>
#include <chrono>
#include <memory>

#include "rclcpp/rclcpp.hpp"
#include "turtlesim/msg/pose.hpp"

using namespace std::chrono_literals;

class WallWatch : public rclcpp::Node
{
public:
  WallWatch()
  : Node("wall_watch")
  {
    pose_sub_ = this->create_subscription<turtlesim::msg::Pose>(
      "/turtle1/pose", 10,
      [this](turtlesim::msg::Pose::ConstSharedPtr msg) { pose_ = msg; });
    timer_ = this->create_wall_timer(500ms, [this]() { on_timer(); });
  }

private:
  // 0.5초마다 가장 가까운 벽까지 거리를 알린다. warn_distance_ 보다 가까우면 경고로 찍는다
  void on_timer()
  {
    if (!pose_) {
      return;
    }
    const double nearest = std::min(std::min(pose_->x, world_size_ - pose_->x),
                                    std::min(pose_->y, world_size_ - pose_->y));
    if (nearest < warn_distance_) {
      RCLCPP_WARN(this->get_logger(), "벽이 가깝습니다: %.2f m", nearest);
    } else {
      RCLCPP_INFO(this->get_logger(), "가장 가까운 벽까지 %.2f m", nearest);
    }
  }

  const double warn_distance_ = 1.5;  // 이보다 가까우면 경고 (m)
  const float world_size_ = 11.0889f;  // turtlesim 창 한 변의 길이 (m)
  rclcpp::Subscription<turtlesim::msg::Pose>::SharedPtr pose_sub_;
  rclcpp::TimerBase::SharedPtr timer_;
  turtlesim::msg::Pose::ConstSharedPtr pose_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  auto node = std::make_shared<WallWatch>();
  rclcpp::spin(node);
  rclcpp::shutdown();
  return 0;
}

용어코드에서 이렇게 보인다이것만 알면 된다

// 21회 turtle_drive — v4 다른 판 (파라미터 콜백 — 바뀔 때만 검사하고 멤버에 넣는다)
#include <algorithm>
#include <chrono>
#include <cmath>
#include <memory>
#include <random>
#include <vector>

#include "rclcpp/rclcpp.hpp"
#include "geometry_msgs/msg/twist.hpp"
#include "turtlesim/msg/pose.hpp"

using namespace std::chrono_literals;

class TurtleDrive : public rclcpp::Node
{
public:
  TurtleDrive()
  : Node("turtle_drive")
  {
    // 파라미터를 선언한다 — 이름과 기본값. 타입은 기본값에서 정해진다 (1.2 이므로 double)
    this->declare_parameter("max_speed", 1.2);
    this->declare_parameter("margin", 1.0);
    // 지금 값을 읽어 멤버에 넣는다
    max_speed_ = this->get_parameter("max_speed").as_double();
    margin_ = this->get_parameter("margin").as_double();
    // ① 바꾸기 전에 불린다 — 받아들일 값인지 검사만 한다. successful = false 면 set 이 실패한다
    on_set_handle_ = this->add_on_set_parameters_callback(
      [](const std::vector<rclcpp::Parameter> & params) {
        rcl_interfaces::msg::SetParametersResult result;
        result.successful = true;
        for (const auto & p : params) {
          if ((p.get_name() == "max_speed" || p.get_name() == "margin") && p.as_double() < 0.0) {
            result.successful = false;
            result.reason = p.get_name() + " 은 0 이상이어야 합니다";
          }
        }
        return result;
      });
    // ② 바뀐 뒤에 불린다 — 새 값을 멤버에 넣는다
    post_set_handle_ = this->add_post_set_parameters_callback(
      [this](const std::vector<rclcpp::Parameter> & params) {
        for (const auto & p : params) {
          if (p.get_name() == "max_speed") { max_speed_ = p.as_double(); }
          if (p.get_name() == "margin") { margin_ = p.as_double(); }
          RCLCPP_INFO(this->get_logger(), "%s = %.2f 로 바뀌었습니다", p.get_name().c_str(), p.as_double());
        }
      });

    cmd_pub_ = this->create_publisher<geometry_msgs::msg::Twist>("/turtle1/cmd_vel", 10);
    pose_sub_ = this->create_subscription<turtlesim::msg::Pose>(
      "/turtle1/pose", 10,
      [this](turtlesim::msg::Pose::ConstSharedPtr msg) { on_pose(msg); });
    timer_ = this->create_wall_timer(500ms, [this]() { on_timer(); });
    RCLCPP_INFO(this->get_logger(), "max_speed = %.2f m/s, margin = %.2f m (%.1f ~ %.1f 안에서 돌아다닙니다)",
                max_speed_, margin_, margin_, map_size_ - margin_);
  }

private:
  // /turtle1/pose 가 올 때마다 불린다 — 받은 것을 들고 있기만 한다
  void on_pose(turtlesim::msg::Pose::ConstSharedPtr msg)
  {
    pose_ = msg;
  }

  // 타이머가 0.5초마다 부른다 — 판단하고 명령을 보낸다
  void on_timer()
  {
    if (!pose_) {                                // 아직 자세를 한 번도 못 받았다
      return;
    }
    const double lo = margin_;
    const double hi = map_size_ - margin_;
    const bool outside = pose_->x < lo || pose_->x > hi || pose_->y < lo || pose_->y > hi;
    const double angle = angle_to_center(*pose_);
    const bool turn_back = outside && angle > turn_tolerance_;   // 범위 밖인데 중앙을 안 보고 있다

    if (turn_back && !turning_) {
      RCLCPP_INFO(this->get_logger(), "범위 밖 (x = %.2f, y = %.2f) — 중앙 쪽으로 돕니다", pose_->x, pose_->y);
    }
    if (!turn_back && turning_) {
      RCLCPP_INFO(this->get_logger(), "중앙을 봅니다 — 다시 출발합니다");
    }
    turning_ = turn_back;

    geometry_msgs::msg::Twist cmd;               // 여섯 칸이 전부 0 으로 시작한다
    if (turn_back) {
      cmd.angular.z = 1.0;                       // 제자리에서 왼쪽으로 돈다 (linear.x 는 0)
    } else {
      cmd.linear.x = random_between(0.2, max_speed_);
      cmd.angular.z = random_between(-1.0, 1.0);
    }
    cmd_pub_->publish(cmd);
  }

  // 바라보는 방향과 「중앙으로 가는 방향」 사이의 각 (0 ~ π rad)
  double angle_to_center(const turtlesim::msg::Pose & p) const
  {
    const double dx = center_ - p.x;             // 중앙으로 가는 방향
    const double dy = center_ - p.y;
    const double hx = std::cos(p.theta);         // 바라보는 방향 (길이 1)
    const double hy = std::sin(p.theta);
    const double cos_angle = (dx * hx + dy * hy) / std::hypot(dx, dy);   // 내적 ÷ 두 길이의 곱
    return std::acos(std::clamp(cos_angle, -1.0, 1.0));
  }

  // lo 와 hi 사이의 실수 하나를 고르게 뽑는다
  double random_between(double lo, double hi)
  {
    std::uniform_real_distribution<double> dist(lo, hi);
    return dist(gen_);
  }

  double max_speed_ = 0.0;             // 파라미터 max_speed 에서 읽는다 (m/s)
  double margin_ = 0.0;                // 파라미터 margin 에서 읽는다 (m)
  const double map_size_ = 11.0;       // 지도 한 변의 길이 (m)
  const double center_ = 5.5;          // 지도 가운데 (x, y 모두)
  const double turn_tolerance_ = 0.35; // 중앙과 이 각(약 20°) 안이면 다시 출발한다 (rad)
  bool turning_ = false;               // 지금 돌아서는 중인가 — 로그를 바뀔 때만 찍는 데 쓴다

  std::mt19937 gen_{std::random_device{}()};   // 난수 생성기 — 실행할 때마다 다른 씨앗으로 시작한다
  rclcpp::Publisher<geometry_msgs::msg::Twist>::SharedPtr cmd_pub_;
  rclcpp::Subscription<turtlesim::msg::Pose>::SharedPtr pose_sub_;
  rclcpp::TimerBase::SharedPtr timer_;
  rclcpp::node_interfaces::OnSetParametersCallbackHandle::SharedPtr on_set_handle_;
  rclcpp::node_interfaces::PostSetParametersCallbackHandle::SharedPtr post_set_handle_;
  turtlesim::msg::Pose::ConstSharedPtr pose_;  // 마지막으로 받은 자세 (처음에는 비어 있다)
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  auto node = std::make_shared<TurtleDrive>();
  rclcpp::spin(node);            // 타이머·구독 콜백은 이 안에서 불린다
  rclcpp::shutdown();
  return 0;
}
파라미터에 범위 붙이기 — describe의 Constraints

18회 turtlesim의 background_r은 describe에 Min value: 0·Max value: 255가 있었고, 범위 밖의 값은 param set이 거절했다. 우리 파라미터의 Constraints가 비어 있는 것은 그것을 정하지 않았기 때문이다. declare_parameter에 셋째 인자로 파라미터 설명(rcl_interfaces::msg::ParameterDescriptor)을 주면 설명 문장과 실수 범위(floating_point_range)를 붙일 수 있다. 위의 「바꾸기 전 콜백」으로 거절하는 것과 같은 일을 선언 한 자리에서 하는 셈이다. 필요해지면 에이전트에게 「이 파라미터에 0.0~2.0 범위를 붙여 줘」라고 시키고 describe로 확인한다.

XML·YAML launch 파일, launch 인자

같은 내용을 XML로도 쓸 수 있다. 아래 파일을 ros2 launch에 경로로 주어 띄워 보니 v7과 똑같이 max_speed = 0.80 m/s, margin = 2.00 m로 시작했다.

<launch>
  <node pkg="turtlesim" exec="turtlesim_node" name="turtlesim"/>
  <node pkg="turtle_drive" exec="turtle_drive" name="turtle_drive" output="screen">
    <param from="$(find-pkg-share turtle_drive)/config/turtle_drive.yaml"/>
  </node>
</launch>

$(find-pkg-share 패키지)가 파이썬 판의 get_package_share_directory다. 파이썬보다 짧고 읽기 쉽다. 다만 인터넷 예제와 AI의 답이 대부분 파이썬이라 이 과목은 파이썬 판을 본으로 했다. 어느 형식이든 ros2 launch로 띄우고, install(DIRECTORY launch …)이 필요한 것도 같다.

프로젝트에서는 「시뮬레이터로 띄울지, 실물 로봇에 붙을지」를 launch를 칠 때 고르고 싶어진다. 이것을 launch 인자라고 하고, ros2 launch 패키지 파일 이름:=값 모양으로 준다. launch 파일 쪽 코드(DeclareLaunchArgument)는 에이전트에게 맡기고, 받은 뒤 ros2 launch 패키지 파일 --show-args로 어떤 인자가 있는지 확인하면 된다. 오늘의 v7에 쳐 보면 인자가 없으니 No arguments.가 나온다.

같은 노드를 둘 띄우면 — ~/와 노드 이름

launch 파일에서 같은 실행 파일을 name만 바꿔 두 번 띄울 수 있다(17회의 -r __node:=와 같다). 그러면 파라미터 저장소도 노드마다 따로 생기고, ~/enable은 각각 /이름1/enable·/이름2/enable이 된다. 서비스 이름을 "/enable"처럼 /로 시작하게 적어 두었다면 두 노드가 같은 이름을 쓰려다 부딪힌다. 그래서 「이 노드의 것」인 서비스에는 ~/를 붙인다. 대신 YAML 파일의 맨 윗줄도 노드 이름을 따라 둘로 적어야 한다(④절 함정).
