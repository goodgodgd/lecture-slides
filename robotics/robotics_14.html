람다·const·C++17 — AI에게 명세를 주는 법

오늘 답할 질문
  1. [lo, hi](float r) { ... } 처럼 생긴 것은 대체 무엇인가?
  2. 대괄호 안에 [=]를 쓰면 왜 위험한가? [&]는 안전한가?
  3. 500ms라고 쓰는 것과 500이라고 쓰는 것은 무엇이 다른가?
  4. "값이 없다"를 -1로 표현하면 무엇이 잘못되나?
  5. AI에게 더 나은 코드를 받아내려면 요구를 어떻게 바꿔야 하나?

2부의 마지막이다. 오늘 배우는 것들은 서로 달라 보이지만 하나로 묶인다 — 전부 "내 의도를 코드에 적어 두는 방법"이다.

const는 "이 함수는 상태를 안 바꾼다"는 약속이고, std::optional은 "값이 없을 수도 있다"는 경고이고, 500ms는 "이건 밀리초다"라는 표시다. 셋 다 주석이 아니라 코드로 적는다. 그래서 컴파일러가 검사해 준다.

그리고 이것이 이 강의의 결론과 이어진다. AI에게 잘 시키는 법은 결국 명세를 잘 쓰는 법이다. "효율적으로 짜 줘"는 명세가 아니다. "실패할 수 있는 함수는 std::optional로 반환해 줘"는 명세다.

한 장 요약 — 학기가 끝나도 이 표만 남으면 된다

무엇을 먼저 볼지: 오른쪽 「무엇을 막아 주나」 열이다. 왼쪽은 그 수단일 뿐이다.

이걸 쓴다무슨 뜻인가무엇을 막아 주나수준
[this] 캡처이 객체의 멤버를 쓴다무엇을 쓰는지 코드에 드러난다[요구]
[&x] 캡처x만 원본을 가리킨다필요 없는 것까지 끌고 오지 않는다[요구]
[=] 캡처 🔴바깥의 모든 것을 복사한다— 큰 것이 통째로 복사된다[판단]
500ms500밀리초짜리 시간 값초인지 밀리초인지 헷갈리는 것[요구]
const 멤버 함수이 함수는 상태를 안 바꾼다실수로 멤버를 고치는 것 — 컴파일이 막는다[요구]
std::optional<T>값이 있을 수도, 없을 수도-1을 거리로 읽는 것[요구]
구조적 바인딩 auto [x, y]묶여 온 값을 한 줄로 푼다.first·.second를 헷갈리는 것[판단]
if (auto p = ...; ...)이 if 안에서만 사는 변수이름이 밖으로 새는 것[알아보기]
해석: 세 번째 줄만 🔴다. [=]는 쓰지 말라는 뜻이 아니라 "왜 [=]인지 말할 수 있어야 한다"는 뜻이다. 실제로 오늘 함정 상자에서는 [=]가 맞는 답인 경우가 나온다. 나머지 일곱 줄은 전부 AI에게 그대로 요구할 수 있는 것들이다.

① 이름 없는 함수를 그 자리에서 만드는 것이 람다다 🟡 맡기되 검사

언제 이게 필요해지나

표준 알고리즘에 조건을 넘겨야 할 때가 있다. "거리 범위 안에 들어오는 것만 세어 줘"라고 하려면 그 「범위 안에 들어오는가」를 어딘가에 적어야 한다. 함수를 하나 따로 만들 수도 있다.

함수를 따로 만들면 이렇게 된다 🔴
float g_lo = 0.16f;                 // 함수 밖에 값을 꺼내 놔야 한다
float g_hi = 8.0f;

bool is_valid(float r) { return r >= g_lo && r <= g_hi; }

// ... 한참 아래에서
const auto n = std::count_if(ranges.begin(), ranges.end(), is_valid);

조건 하나 때문에 함수 하나와 전역 변수 둘이 생겼다. 조건을 확인하려면 위로 스크롤해서 is_valid를 찾아야 한다. 그리고 g_lo는 아무나 고칠 수 있다.

람다로 쓰면
const float lo = 0.16f, hi = 8.0f;

const auto n = std::count_if(ranges.begin(), ranges.end(),
                             [lo, hi](float r) { return r >= lo && r <= hi; });

🆕 이 코드에서 처음 나오는 것

[lo, hi](float r) { return ...; }
이름 없이 그 자리에서 만드는 작은 함수다. 세 칸으로 나뉜다 — 대괄호(바깥에서 무엇을 가져올지), 괄호(무엇을 받을지), 중괄호(무엇을 할지). 여기서는 "값 하나를 받아 범위 안인지 참·거짓으로 답하는" 함수를 만들었다.
auto is_close = [](float r) { return r < 0.5f; };
만든 람다에 이름을 붙여 둘 수도 있다. 그러면 보통 함수처럼 is_close(0.42f)로 부른다. 타입 이름을 적을 수 없으므로 auto로만 받을 수 있다.

실제로 돌려 보면 이렇게 된다.

① 이름 없는 함수를 그 자리에서 만든다
   is_close(0.42) = 참,  is_close(1.24) = 거짓

쓸 때 / 안 쓸 때

이렇게 한다언제
람다를 그 자리에 쓴다기본값. 그 조건을 한 군데서만 쓸 때
람다에 이름을 붙인다 (auto f = ...)같은 조건을 한 함수 안에서 두세 번 쓸 때
보통 함수로 뺀다여러 파일에서 쓰거나, 조건이 열 줄을 넘어갈 때
해석: 판단 기준은 「이 조건을 몇 군데서 쓰나」 하나다. 한 군데면 람다, 여러 군데면 함수. 길이는 그다음 문제다.
이 조건을 여러 군데서 쓰고 있으면 이름 붙인 함수로 빼 주고, 한 군데서만 쓰면 그 자리에 람다로 남겨 줘. 어느 쪽을 골랐는지 한 줄로 알려 줘.

② 대괄호 안에 무엇을 적느냐가 이 회차의 알맹이다 🔴 사람이 판단

대괄호를 캡처(capture)라고 부른다. "바깥에 있는 것 중 무엇을 가져다 쓸지" 적는 칸이다. 네 가지가 있고, AI는 거의 항상 넷 중 하나를 습관적으로 고른다. 

class Driver {
public:
  Driver() : limit_(0.5f), ranges_{0.83f, 0.42f, 1.24f, 0.31f, 2.05f} {}

  // [this] — 이 객체의 멤버를 쓰겠다
  int close_count_this()
  {
    return static_cast<int>(
      std::count_if(ranges_.begin(), ranges_.end(),
                    [this](float r) { return r < limit_; }));
  }

  // [&] — 바깥의 모든 것을 참조로 가져다 쓰겠다
  int close_count_amp()
  {
    return static_cast<int>(
      std::count_if(ranges_.begin(), ranges_.end(),
                    [&](float r) { return r < limit_; }));
  }

private:
  float limit_;
  std::vector<float> ranges_;
};

🆕 이 코드에서 처음 나오는 것

[this]
"이 객체 자체를 가져오겠다"는 뜻이다. 그러면 람다 안에서 limit_처럼 멤버 이름을 그냥 쓸 수 있다. 여기서는 limit_ 하나를 쓰려고 넣었다. ROS 2 노드의 콜백에서 가장 많이 보게 될 모양이다.
static_cast<int>(...)
한 타입의 값을 다른 타입으로 대놓고 바꾼다. count_if가 돌려주는 것은 int보다 큰 타입이라 여기서는 그것을 int로 줄이는 데 썼다. 그냥 대입하면 컴파일러가 "값이 잘릴 수 있다"고 경고한다.

둘 다 돌려 보면 결과는 같다.

② 캡처 — 바깥 변수를 무엇으로 가져오나
   [this] 로 센 것: 2개
   [&]    로 센 것: 2개   (결과는 같지만 무엇을 쓰는지 안 보인다)
해석: 결과가 같은데도 [this]가 나은 이유는 읽는 사람 때문이다. [&]는 "뭔가 바깥 것을 쓴다"까지만 알려 주고, 무엇을 쓰는지는 중괄호 안을 다 읽어야 안다. 람다가 스무 줄이 되면 그 차이가 커진다.

🔴 [=]는 큰 것을 통째로 복사한다 — 세어 봤다

[=]는 "바깥의 모든 것을 값으로 가져온다"는 뜻이다. 값으로 가져온다는 것은 복사한다는 뜻이다. 복사 생성자에 세는 코드를 넣고 실제로 세어 봤다. 

int g_copies = 0;
struct Big {
  std::vector<float> buf = std::vector<float>(360, 1.0f);
  Big() = default;
  Big(const Big & o) : buf(o.buf) { ++g_copies; }
};

Big big;
g_copies = 0;
auto by_copy = [=]()     { return big.buf.size(); };   // 여기서 Big 이 복사된다
g_copies = 0;
auto by_ref  = [&big]()  { return big.buf.size(); };   // 복사가 없다
③ [=] 는 값으로 복사한다 — 큰 것이 통째로 복사된다
   [=] 로 캡처한 순간 Big 복사 1회 (buf 360칸)
   [&big] 로 캡처하면 복사 0회 (buf 360칸)

무엇을 먼저 볼지: "캡처한 순간"이라는 말이다. 람다를 부를 때가 아니라 만들 때 복사된다.

해석: 잰 곳은 컨테이너(우분투 24.04.4, g++ 13.3.0 -O2)다. float 360개짜리 객체 하나에 복사 1회다. 이것이 라이다 콜백 안이라면 초당 5번씩 360개를 아무 이득 없이 새로 만드는 것이다. 그런데도 [=]를 써야 하는 경우가 있다. 바로 아래 함정이 그 경우다.
⚠️ 가리키던 것이 먼저 사라지면 — 이 회차의 백미

아래 코드는 컴파일 경고도 없고 크래시도 안 난다. 그런데 돌릴 때마다 다른 답이 나온다. 

std::function<float()> make_reader()
{
  std::vector<float> ranges{0.83f, 0.42f, 1.24f};   // 이 함수 안에서만 사는 값
  return [&ranges]() { return ranges.at(0); };      // 그 값을 「가리키는」 함수를 돌려준다
}

int main()
{
  auto read = make_reader();      // make_reader 가 끝나는 순간 ranges 는 사라졌다
  std::printf("읽은 값: %.2f\n", read());   // 사라진 것을 읽는다
}

🆕 이 코드에서 처음 나오는 것

std::function<float()>
"인자 없이 float를 돌려주는 함수"를 값처럼 담아 두는 그릇이다. 람다는 저마다 타입이 달라서 auto로만 받을 수 있는데, 함수 밖으로 돌려주거나 멤버로 저장하려면 이런 그릇이 필요하다. <functional>에 들어 있다.

그냥 빌드해서 두 번 돌린 결과다.

$ g++ -std=c++17 -O2 -o dangling_plain dangling_capture.cpp
$ ./dangling_plain
읽은 값: -0.00
$ ./dangling_plain
읽은 값: -18523820.00

종료 코드는 0이다. 프로그램은 자기가 성공했다고 생각한다. 로봇이라면 -18523820 m를 거리로 받아 판단한다.

주소 검사기를 켜면 무엇이 잘못됐는지 알려 준다.

$ g++ -std=c++17 -g -fsanitize=address -o dangling dangling_capture.cpp
$ ./dangling

무엇을 먼저 볼지: 첫 줄의 stack-use-after-return이다. "함수가 끝난 뒤에 그 함수의 값을 읽었다"는 뜻이다.

고치는 방법은 대괄호 안을 [&ranges]에서 [ranges]로 한 글자 바꾸는 것이다.

$ sed 's/\[&ranges\]/[ranges]/' dangling_capture.cpp > fixed.cpp
$ g++ -std=c++17 -O2 -o fixed fixed.cpp && ./fixed
읽은 값: 0.83

여기서는 복사가 정답이다. 값을 들고 나가야 하니까 복사해야 한다. 앞 절에서 [=]가 비싸다고 했는데 여기서는 복사가 유일한 답이다. 그래서 [=]가 🔴인 이유는 "쓰지 마라"가 아니라 "왜 그걸 골랐는지 말할 수 있어야 한다"는 것이다.

람다가 어디에 사나무엇으로 캡처하나
그 자리에서 만들어 그 자리에서 쓰고 버린다 (count_if에 넘기는 것)[&x]나 [this] — 복사가 필요 없다
저장해 뒀다가 나중에 부른다 (콜백, 타이머, std::function 멤버)값으로 캡처한다. 가리키던 것이 먼저 사라질 수 있다

AI는 이 구분을 잘 못한다. 두 경우에 똑같이 [&]나 [=]를 쓴다. 받은 코드에서 람다가 어디에 저장되는지를 먼저 보고 판단해야 한다.

이 람다는 만들어서 바로 쓰고 버리는 건가, 저장해 뒀다가 나중에 부르는 건가? 저장하는 거라면 참조 캡처가 위험하지 않은지 확인해 줘.

③ 500ms라고 쓰면 단위를 헷갈릴 수 없다 🟡 맡기되 검사

ROS 2 예제 코드에는 500ms 같은 표기가 늘 나온다. 숫자 뒤에 글자가 붙은 이 모양은 C++의 보통 문법이 아니라 std::chrono가 준 것이다. 

#include <chrono>
using namespace std::chrono_literals;   // 이 줄이 있어야 500ms 라고 쓸 수 있다

const auto period = 500ms;
std::printf("500ms 는 %ld 밀리초짜리 시간 값이다\n",
            std::chrono::duration_cast<std::chrono::milliseconds>(period).count());

🆕 이 코드에서 처음 나오는 것

using namespace std::chrono_literals;
500ms·2s·1min 같은 표기를 쓸 수 있게 해 준다. 이 한 줄이 없으면 500ms는 컴파일이 안 된다. 여기서는 시간 값을 읽기 쉽게 적으려고 넣었다.
std::chrono::duration_cast<milliseconds>(t)
시간 값을 다른 단위로 바꿔 준다. 여기서는 500ms가 정말 500밀리초인지 확인해 보려고 밀리초로 바꿔 찍었다.
.count()
시간 값에서 숫자만 꺼낸다. 화면에 찍으려면 필요하다.

제대로 다루는 곳: 22회(콜백 시간을 std::chrono로 재기)

④ 500ms 표기 — std::chrono 가 준 것이다
   500ms 는 500 밀리초짜리 시간 값이다
   0.5 라고 쓰면 초인지 밀리초인지 코드만 봐서는 알 수 없다
이렇게 쓰면무슨 일이 생기나
create_wall_timer(500, ...)500이 초인지 밀리초인지 함수 설명을 찾아봐야 안다
create_wall_timer(0.5, ...)같은 문제. 게다가 소수라서 더 헷갈린다
create_wall_timer(500ms, ...)읽는 순간 알 수 있다. 그리고 단위를 잘못 넣으면 컴파일이 안 된다
해석: 세 번째 줄의 뒷문장이 핵심이다. 단위 실수가 「돌아가는 버그」에서 「컴파일 오류」로 바뀐다. 오늘 배우는 것들이 전부 이런 종류의 이득이다 — 틀릴 자리를 컴파일러에게 넘긴다.

④ const 멤버 함수는 AI에게 주는 명세다 🟡 맡기되 검사

함수 뒤에 const를 붙이면 "이 함수는 객체의 상태를 바꾸지 않는다"는 약속이 된다. 주석과 다른 점은 컴파일러가 그 약속을 검사한다는 것이다. 

class Tracker {
public:
  Tracker() : hits_(0), ranges_{1.0f, 0.4f, 2.2f} {}

  // const 가 붙었다 = "이 함수는 객체의 상태를 바꾸지 않는다"
  int count_close(float limit) const
  {
    int n = 0;
    for (float r : ranges_) { if (r < limit) { ++n; } }
    // ++hits_;   // ← 이 줄의 주석을 풀면 컴파일이 안 된다. const 가 막아 준다
    return n;
  }

  void record(float limit) { hits_ += count_close(limit); }   // 상태를 바꾸는 함수
  int hits() const { return hits_; }

private:
  int hits_;
  std::vector<float> ranges_;
};
count_close(0.5) = 1  (상태는 그대로)
hits = 0
record 한 뒤 hits = 1
const 객체에서도 count_close 는 부를 수 있다: 1
frozen.record(0.5f) 는 컴파일이 안 된다 — 상태를 바꾸는 함수이기 때문이다

마지막 줄을 실제로 시켜 보면 이런 오류가 난다

const Tracker frozen;
frozen.record(0.5f);   // ← 이 줄을 넣고 빌드하면
error: passing ‘const Tracker’ as ‘this’ argument discards qualifiers [-fpermissive]
   36 |   frozen.record(0.5f);
      |   ~~~~~~~~~~~~~^~~~~~
note:   in call to ‘void Tracker::record(float)’
   18 |   void record(float limit) { hits_ += count_close(limit); }

무엇을 먼저 볼지: discards qualifiers라는 말이다. "const라는 자격을 버리려 한다"는 뜻이고, 실전에서 이 메시지를 꽤 자주 보게 된다.

해석: 이 오류를 만나면 둘 중 하나다 — ① 그 함수에 const를 붙였어야 하는데 안 붙였다 (대개 이쪽이다) ② 정말로 상태를 바꿔야 하는데 const 객체로 받았다. 먼저 ①을 의심하라. AI는 읽기만 하는 함수에도 const를 자주 빠뜨린다.
이 클래스에서 상태를 바꾸지 않는 멤버 함수에 전부 const를 붙여 줘. 붙일 수 없는 함수가 있으면 왜인지 알려 줘.

⑤ 로봇에서는 로그가 유일한 단서다 🔴 사람이 한다

콘솔 프로그램은 이상하면 멈춰 세우고 들여다볼 수 있다. 주행 중인 로봇은 그럴 수 없다. 로봇은 바닥을 굴러가고 있고, 무슨 일이 있었는지 알려 주는 것은 그때 남긴 로그뿐이다.

이렇게 찍으면무엇이 아쉬운가
std::printf("error\n");언제 났는지, 어느 노드인지, 얼마나 심각한지가 없다
std::cout << d << "\n";같은 문제. 게다가 여러 노드가 같이 찍으면 섞인다
RCLCPP_ERROR(get_logger(), "유효한 거리 값이 없다");시각·노드 이름·심각도가 자동으로 붙는다. 파일로도 남는다

🆕 여기서 처음 나오는 것

RCLCPP_ERROR(logger, "...") / RCLCPP_WARN / RCLCPP_INFO
ROS 2가 주는 로그 찍기 도구다. 뒤 이름이 심각도다 — INFO(그냥 알림) · WARN(이상하다) · ERROR(뭔가 잘못됐다). 여기서는 "거리 값이 하나도 안 들어왔다"처럼 나중에 원인을 찾을 때 필요한 사실을 남기는 데 쓴다.

제대로 다루는 곳: 22회(로깅과 throttle — 초당 수십 번 찍히는 로그를 줄이는 법)

해석: 오늘 여기서 알아야 할 것은 딱 하나다 — "값이 없다"·"범위를 벗어났다" 같은 판단을 조용히 넘기지 말고 로그로 남긴다. 그 판단이 바로 다음 절의 std::optional과 짝이다. 값이 없을 때 nullopt를 돌려주고, 받는 쪽에서 RCLCPP_WARN을 찍는다.

⑥ "값이 없음"을 -1로 말하면 받는 쪽이 검사를 빠뜨린다 🟡 맡기되 검사

AI가 보통 주는 코드 🔴
// 실패하면 -1 을 돌려준다
float nearest(const std::vector<float> & r)
{
  std::vector<float> good;
  for (float x : r) { if (std::isfinite(x) && x >= 0.16f && x <= 8.0f) { good.push_back(x); } }
  if (good.empty()) { return -1.0f; }
  return *std::min_element(good.begin(), good.end());
}

무엇이 문제인가

받는 쪽에서 if (d < 0)를 빠뜨려도 컴파일이 된다. 그리고 라이다 값이 전부 inf·NaN인 순간은 실제로 생긴다 — 로봇이 아무것도 없는 방향을 향했을 때다. 그때 -1을 거리로 읽으면 로봇은 "뒤쪽 1 m에 뭔가 있다"고 판단한다.

C++17로 짜 줘. 실패할 수 있는 함수는 -1 대신 std::optional로 반환해 줘.
받은 코드
#include <optional>

std::optional<float> nearest(const std::vector<float> & r)
{
  std::vector<float> good;
  for (float x : r) { if (std::isfinite(x) && x >= 0.16f && x <= 8.0f) { good.push_back(x); } }
  if (good.empty()) { return std::nullopt; }
  return *std::min_element(good.begin(), good.end());
}

🆕 이 코드에서 처음 나오는 것

std::optional<float>
"float 하나가 있을 수도 있고 아예 없을 수도 있다"는 뜻의 타입이다. 여기서는 "가장 가까운 거리"를 못 구할 수 있다는 사실을 타입에 적어 두는 데 썼다.
std::nullopt
"값이 없다"는 것을 나타내는 값이다. 여기서는 쓸 만한 거리가 하나도 없을 때 돌려줬다.
v.has_value() / if (!v)
값이 들어 있는지 묻는다. if (!v)는 if (!v.has_value())의 짧은 꼴이다. 여기서는 값을 꺼내기 전에 확인하는 데 썼다.
*v
안에 든 값을 꺼낸다. 비어 있는데 꺼내면 안 된다 — 먼저 검사해야 한다.

둘을 나란히 돌려 본 결과다. 입력은 전부 못 쓰는 값(inf·NaN·범위 밖)만 넣었다.

① std::optional — "값이 없음"을 -1 로 표현하지 않는다
   옛날 방식 반환값: -1.0   ← 이게 거리인지 실패인지 코드만 봐서는 모른다
   optional 반환값 : 값 없음(nullopt)
   → if (!v) 한 줄로 걸러진다. 검사를 빠뜨리기 어렵다

쓸 때 / 안 쓸 때

이렇게 한다언제
std::optional<T>실패가 정상적인 일일 때. "값이 없을 수 있다"가 버그가 아니라 상황일 때
그냥 T실패할 일이 없을 때. 억지로 optional을 씌우면 받는 쪽만 번거로워진다
예외를 던진다정말 있어서는 안 되는 일일 때. 이 과목에서는 쓰지 않는다 — 콜백 안에서 예외가 나면 노드가 통째로 죽는다

⑦ 묶여 온 값은 한 줄로 푼다 🟢 맡긴다

함수가 값을 두 개 돌려줘야 할 때가 있다. 극좌표를 직교좌표로 펴면 x와 y가 나온다. 

#include <utility>

std::pair<float, float> to_xy(float r, float th)
{
  return {r * std::cos(th), r * std::sin(th)};
}

// 옛날 방식 — 무엇이 x 이고 무엇이 y 인지 이름이 없다
const auto p = to_xy(1.5f, 0.5236f);
const float x1 = p.first;
const float y1 = p.second;

// C++17 — 받는 자리에서 이름을 붙인다
const auto [x, y] = to_xy(1.5f, 0.5236f);

🆕 이 코드에서 처음 나오는 것

std::pair<A, B>
값 두 개를 하나로 묶어 주는 그릇이다. 꺼낼 때는 .first·.second다. 여기서는 x와 y를 한 번에 돌려주는 데 썼다.
const auto [x, y] = ...;
구조적 바인딩. 묶여 온 값을 받는 자리에서 풀어 이름을 붙인다. 여기서는 .first가 무엇이었는지 기억하지 않아도 되게 만들었다.
std::cos / std::sin
각도를 받아 코사인·사인을 돌려준다. 각도는 도(°)가 아니라 라디안이다 — 30°는 0.5236이다. <cmath>에 들어 있다.

제대로 다루는 곳: 25회(좌표계와 변환 — 극좌표를 펴다)

② 구조적 바인딩 — 묶여 온 값을 한 줄로 푼다
   r=1.50 m, θ=30° → x=1.299, y=0.750

if 안에서 변수를 선언하면 그 이름이 밖으로 새지 않는다

if (auto it = std::find_if(mixed.begin(), mixed.end(),
                           [](float r) { return r < 0.5f; });
    it != mixed.end())
{
  std::printf("   0.5m 안쪽 값 %.2f 를 찾았다\n", *it);
}
// 여기서는 it 를 쓸 수 없다
③ if 안에서 변수를 선언한다 — 그 변수는 if 밖으로 새지 않는다
   0.5m 안쪽 값 0.42 를 찾았다
   여기서는 it 를 쓸 수 없다 — 이름이 새지 않으니 다음 if 에서 또 쓸 수 있다
해석: 이득은 같은 이름을 여러 번 쓸 수 있다는 것이다. 찾는 코드가 세 번 나오면 it1·it2·it3를 만들 필요가 없다. 번호가 붙은 변수 이름은 그 자체로 실수의 씨앗이다.

제출물무엇을 적나배점
① 처음 요구와 받은 코드막연하게 물어본 것. "라이다 값에서 가장 가까운 거리를 구해 줘" 정도
② 두 번째 요구와 받은 코드"효율적으로 짜 줘" 같은 막연한 개선 요구를 붙인 것
③ 세 번째 요구와 받은 코드무엇이 문제인지 짚은 요구. "inf·NaN을 걸러 줘", "실패하면 optional로 돌려줘", "콜백은 const 참조로 받아 줘"
④ 무엇이 달라졌는지 세 줄 ← 여기가 점수다①→②와 ②→③에서 코드의 어느 줄이 바뀌었나. 바뀐 이유를 자기 말로
⑤ AI가 끝까지 안 고친 것 ← 가점세 번 물어도 안 고쳐진 것이 있으면 그것과 이유가점
해석: ④가 점수인 이유가 있다. 연구에 따르면 막연한 요구("효율적으로 짜 줘")는 효율 점수를 0.294 → 0.342로 올렸지만, 무엇이 문제인지 짚은 요구는 0.385까지 올렸다(만점 1.0 기준, 31% 개선). "더 잘해 줘"는 명세가 아니다. ③에서 그 차이를 직접 만들어 보는 것이 이 과제다.

✅ 오늘의 점검

조금 더 알아두면 시험 범위 아님

템플릿을 만드는 법 — 이 과목에서는 만들 일이 없다

std::vector<float>처럼 꺾쇠를 쓰는 일은 매일 있지만, 꺾쇠를 만드는 일은 이 과목에 없다. 그래도 모양은 알아 두면 코드를 읽을 때 덜 놀란다. 

// "어떤 타입이든 받아서 그 타입 그대로 돌려주는" 함수를 만든다
template<typename T>
T clamp_value(T v, T lo, T hi)
{
  if (v < lo) { return lo; }
  if (v > hi) { return hi; }
  return v;
}

// 쓸 때는 타입을 안 적어도 컴파일러가 알아낸다
const float speed = clamp_value(1.2f, 0.0f, 0.22f);   // 0.22f
const int   n     = clamp_value(15, 0, 10);           // 10

template<typename T>는 "아래 함수에서 T는 나중에 정해진다"는 뜻이다. 쓰는 쪽에서 float를 넣으면 float판이, int를 넣으면 int판이 만들어진다. 같은 코드를 타입마다 복사하지 않아도 되는 것이 이득 전부다.

실제로는 위 함수를 만들 필요도 없다. std::clamp가 이미 있다(<algorithm>). 27회에서 속도 명령을 한계 안으로 눌러 줄 때 그걸 쓴다.

템플릿 오류 메시지 읽는 법 — 첫 줄과 마지막 줄만 본다

템플릿을 잘못 쓰면 오류가 수백 줄 나온다. 화면을 가득 채우고 어디부터 봐야 할지 막막하다. 규칙은 간단하다.

어디를 보나무엇이 있나
첫 번째 error: 줄진짜 원인. 여기가 90%다
마지막 몇 줄의 required from here내 코드의 어느 줄에서 시작됐는지
가운데 수백 줄표준 라이브러리 내부 사정. 읽지 않는다

그래도 안 풀리면 첫 error: 줄과 required from here 줄만 잘라서 AI에게 주면 된다. 수백 줄을 통째로 붙이면 오히려 답이 나빠진다.

C++20·C++23이 준 것 — 우리는 C++17을 쓴다

ROS 2 Jazzy는 C++17 기준이다. 아래는 다른 프로젝트에서 봤을 때 알아보기만 하면 되는 것들이다.

무엇어떻게 생겼나무엇이 좋아지나
std::ranges (C++20)std::ranges::sort(v);begin()·end()를 안 쓴다
std::format (C++20)std::format("{:.2f} m", d)printf의 타입 실수가 사라진다
