클래스 — 노드가 상태를 갖는 방식

오늘 답할 질문
  1. 함수만으로도 되는데 왜 굳이 클래스로 묶나?
  2. 생성자 본문에서 대입하는 것과 멤버 초기화 리스트로 넣는 것은 무엇이 다른가?
  3. 멤버 함수 이름 뒤에 붙은 const는 무슨 약속인가?
  4. 클래스 하나를 .hpp와 .cpp로 나누면 CMakeLists.txt는 어떻게 달라지나?

ROS 2 코드는 거의 전부가 클래스다. 라이다에서 값을 받는 프로그램 하나가 class LidarNode : public rclcpp::Node로 시작한다. 3부에 가서 그 코드를 검사하려면 클래스가 무엇을 하는 문법인지부터 알아야 한다.

클래스를 배우는 이유는 「객체지향」이라는 말 때문이 아니다. 로봇 프로그램은 값을 계속 들고 있어야 하기 때문이다. 라이다 값이 들어올 때마다 「거리 범위는 얼마인지」, 「지금까지 몇 개를 버렸는지」를 알고 있어야 한다. 그 값을 어디에 둘 것인가가 오늘의 질문이다.

오늘은 용어 일곱 개를 다룬다. 절마다 먼저 그 문법이 무엇이고 왜 생겼는지를 설명하고, 그다음에 라이다 값에서 못 쓰는 것을 걸러내는 작은 필터 프로그램에 그것을 적용한다. 프로그램은 클래스 없이 먼저 짜 두고, 절이 넘어갈 때마다 문법 하나씩으로 고쳐 간다.

한 장 요약 — 학기가 끝나도 이 표만 남으면 된다

무엇을 먼저 볼지: 맨 오른쪽 「이것만 알면 된다」 열만 읽어도 오늘 수업은 끝난다. 순서는 오늘 프로그램에 적용하는 순서다.

용어코드에서 이렇게 보인다이것만 알면 된다
클래스 · 객체 class RangeFilter { ... }; / RangeFilter front(...) 클래스는 값과 그 값을 다루는 함수를 묶은 타입이고, 객체는 그 타입의 변수다. 객체마다 자기 값을 따로 가진다
멤버 변수 · 멤버 함수 float lo_; / keep_valid(...) 클래스 안에 선언한 변수와 함수. 멤버 함수 안에서는 멤버 변수를 이름만으로 쓴다
생성자 · 소멸자 RangeFilter(...) / ~RangeFilter() 객체가 만들어질 때와 사라질 때 자동으로 불리는 멤버 함수. 아무도 직접 부르지 않는다
멤버 초기화 리스트 🔴 : name_(name), lo_(lo), hi_(hi) 생성자 본문이 아니라 콜론 뒤에서 멤버를 초기화한다. AI가 가장 자주 빠뜨리는 자리다
public · private 클래스 안의 구역 표시 멤버 변수는 전부 private. 밖에서 읽을 것만 함수로 연다
const 멤버 함수 int dropped() const; 이름 뒤의 const는 「이 함수는 멤버를 안 바꾼다」는 약속이다. 읽기만 하는 함수에 붙인다
헤더 / 소스 분리 range_filter.hpp + range_filter.cpp 클래스 정의는 헤더에, 멤버 함수의 내용은 소스에. 소스가 둘이면 add_executable에 둘 다 적는다
해석: 넷째 줄에만 🔴가 붙어 있다. 나머지는 빠뜨리면 컴파일러가 알려 준다. 멤버 초기화 리스트만 다르다 — 빠뜨려도 빌드가 되고 출력도 같다. 그래서 사람이 눈으로 보는 검사 목록에 올려 둔다.

① 오늘 만들 것 — 라이다 값 필터, 클래스 없이 먼저 🟡 맡기되 검사

무엇을 만드나

라이다 거리 값 중에서 못 쓰는 것을 걸러내는 필터다. 너무 가까운 값(0.10)과 너무 먼 값(9.90)은 버리고, 라이다가 측정에 실패했을 때 보내는 INFINITY와 NAN도 버린다. 걸러내려면 기준값 두 개(가장 가까운 거리, 가장 먼 거리)가 필요하고, 몇 개를 버렸는지도 세어 둔다. 입력 7개 중 남아야 할 것은 0.83 1.24 2.05 세 개다.

읽는 법

  • 먼저 이 프로그램을 클래스 없이 짠다. 이대로도 돌아간다.
  • ②절부터는 절마다 「개념」이 먼저 온다 — 그 문법이 무엇이고 어떤 문제를 풀려고 생겼는지. 그다음 「예제에 적용」에서 지금 프로그램의 어디가 불편한지를 보고, 그 문법으로 고친다.
  • 고치는 자리는 고치기 전(붉은 테두리)과 고친 뒤(푸른 테두리)를 따로 놓는다.
  • 그 아래 📄 「전체 코드」 상자를 누르면 그 단계의 파일 전체가 나온다. 파일 첫 줄의 주석에 버전(v1, v2, …)이 적혀 있다. 어느 버전을 펼쳐도 그대로 빌드되고 돌아간다.
  • 빌드는 전부 CMake로 한다. 8회에서 읽은 그 네 줄이다. ⑦절에서 소스가 둘이 되면 한 줄이 달라진다.

1단계 (v1) — 클래스 없이

기준값과 버린 개수를 함수 밖의 변수에 두고, 거르는 함수 하나가 그것을 읽고 고친다. 이렇게 함수 밖에 놓여 프로그램 어디에서나 보이는 변수를 전역 변수(global variable)라고 하고, 이름 앞에 g_를 붙여 표시했다. 

std::string g_name = "front";    // 이 필터가 어느 라이다 것인가
float g_lo = 0.16f;              // 이보다 가까우면 버린다
float g_hi = 8.0f;               // 이보다 멀면 버린다
int g_dropped = 0;               // 지금까지 버린 개수

std::vector<float> keep_valid(const std::vector<float> & ranges)
{
  std::vector<float> good;
  for (const float r : ranges) {
    if (std::isfinite(r) && r >= g_lo && r <= g_hi) { good.push_back(r); }
    else { ++g_dropped; }
  }
  return good;
}

🆕 이 코드에서 처음 나오는 것

good.push_back(r)
컨테이너 뒤에 원소를 하나 더 붙인다. 여기서는 쓸 만하다고 판단한 거리 값만 골라 담는 데 썼다.
NAN
「숫자가 아니다」(Not a Number)를 뜻하는 실수 값이다. INFINITY처럼 라이다가 측정에 실패했을 때 보내는 값이고, std::isfinite가 둘 다 거짓으로 판정한다.

실제로 나온 출력

$ cmake -S . -B build
$ cmake --build build
$ ./build/range_filter
front: 원본 7개 → 남은 값 3개, 버린 값 4개

돌아가는데 무엇이 불편한가

무엇을 먼저 볼지: 오른쪽 열이 「언제 터지나」다. 지금이 아니라 나중에 터진다.

무엇이 걸리나언제 터지나
라이다를 두 개 달면 이 코드는 못 쓴다기준값이 한 벌뿐이라 앞 라이다와 뒤 라이다를 따로 못 쓴다
g_dropped를 아무나 고칠 수 있다다른 파일에서 실수로 g_dropped = 0;을 해도 컴파일이 된다
어떤 값이 어떤 함수와 짝인지 코드에 안 적혀 있다함수가 열 개로 늘면 사람이 외우고 있어야 한다
해석: 클래스는 이 세 줄을 한꺼번에 푸는 문법이다 — 값과 그 값을 다루는 함수를 한 타입으로 묶고(②), 만들 때 반드시 값을 채우게 하고(③④), 밖에서는 못 건드리게 한다(⑤).

② 클래스와 객체 — 값과 함수를 한 타입으로 묶는다 🟢 맡긴다

개념 — 클래스는 사용자가 정의하는 타입이다

클래스(class)는 값 여러 개와 그 값을 다루는 함수를 하나로 묶어 만든 새 타입이다. 클래스 안에 선언한 변수를 멤버 변수(member variable), 함수를 멤버 함수(member function)라고 한다. 그 타입으로 만든 변수가 객체(object)다. int로 변수를 여럿 만들 수 있듯이 클래스 하나로 객체를 여럿 만들 수 있고, 객체마다 멤버 변수를 자기 것으로 따로 가진다.

7회의 구조체(struct Scan)도 클래스다. C++에서 struct와 class는 같은 문법이고, 다른 것은 ⑤절에서 볼 기본 접근 권한 하나뿐이다. 7회에서는 값만 묶었고, 오늘은 함수까지 같이 묶는다.

모양은 이렇다. 끝의 세미콜론까지가 클래스 정의다.

class 이름
{
public:
  타입 멤버변수_;                         // 객체마다 하나씩 생긴다
  반환타입 멤버함수(인자) { ... }         // 안에서는 멤버변수_ 를 이름만으로 쓴다
};

이름 객체{값, 값};                        // 객체를 만든다
객체.멤버함수(인자);                      // 멤버 접근 연산자 . 로 부른다 (7회 ⑦절과 같다)

멤버 함수 안에서 멤버 변수를 이름만으로 쓰면 「이 함수가 불린 그 객체의 것」을 뜻한다. front.keep_valid(raw)라고 부르면 함수 안의 lo_는 front의 lo_이고, rear.keep_valid(raw)라고 부르면 rear의 것이다. 함수는 한 벌인데 값은 객체마다 다르다.

멤버 변수 이름 뒤의 밑줄(lo_)은 문법이 아니라 약속이다. 코드 어디를 봐도 그것이 멤버인지 그 자리 변수인지 바로 보이게 하려는 것이고, ROS 2 코드 스타일이 이 방식을 쓴다.

예제에 적용 — 라이다가 둘이면 필터도 둘이어야 한다

v1의 전역 변수 네 개는 이 필터의 값이고 keep_valid는 그 값을 쓰는 함수다. 짝이 맞으니 한 클래스로 묶는다. 묶고 나면 앞 라이다용과 뒤 라이다용 객체 둘을 기준값을 다르게 해서 만들 수 있다. 버린 개수도 객체마다 따로 센다.

🆕 이 코드에서 처음 나오는 것

RangeFilter front{"front", 0.16f, 8.0f};
7회 ⑦절의 Scan scan{...}과 같은 중괄호 초기화다. 멤버 변수를 선언한 순서대로 채운다. 네 번째 멤버 dropped_는 적지 않았으니 클래스에 적어 둔 = 0으로 시작한다.
int dropped_ = 0;
멤버 변수를 선언하면서 기본값을 같이 적은 것이다(기본 멤버 초기화자, default member initializer). 객체를 만들 때 따로 값을 안 주면 이 값으로 시작한다.

main.cpp
// 9회 라이다 값 필터 — v2 (2단계: 클래스 RangeFilter 로 묶는다. 라이다가 둘이어도 된다)
#include <cmath>
#include <iostream>
#include <string>
#include <vector>

class RangeFilter
{
public:
  std::string name_;      // 이 필터가 어느 라이다 것인가
  float lo_;              // 이보다 가까우면 버린다
  float hi_;              // 이보다 멀면 버린다
  int dropped_ = 0;       // 지금까지 버린 개수

  std::vector<float> keep_valid(const std::vector<float> & ranges)
  {
    std::vector<float> good;
    for (const float r : ranges) {
      if (std::isfinite(r) && r >= lo_ && r <= hi_) { good.push_back(r); }
      else { ++dropped_; }
    }
    return good;
  }
};

int main()
{
  const std::vector<float> raw{0.10f, 0.83f, INFINITY, 1.24f, 9.90f, NAN, 2.05f};

  RangeFilter front{"front", 0.16f, 8.0f};   // 앞 라이다 — 멀리까지 본다
  RangeFilter rear{"rear", 0.30f, 1.50f};    // 뒤 라이다 — 가까운 것만 본다

  const std::vector<float> good_f = front.keep_valid(raw);
  const std::vector<float> good_r = rear.keep_valid(raw);
  std::cout << front.name_ << ": 남은 값 " << good_f.size() << "개, 버린 값 " << front.dropped_ << "개\n";
  std::cout << rear.name_  << ": 남은 값 " << good_r.size() << "개, 버린 값 " << rear.dropped_  << "개\n";
  return 0;
}

③ 생성자와 소멸자 — 만들어질 때와 사라질 때 자동으로 불린다 🟡 맡기되 검사

개념 — 이름이 정해진 특별한 멤버 함수 둘

생성자(constructor)는 객체가 만들어질 때 자동으로 불리는 멤버 함수다. 이름은 클래스 이름과 같고, 반환 타입을 적지 않는다. 인자를 받을 수 있으므로 객체를 만들면서 필요한 값을 넘겨받는 자리가 된다. 생성자를 하나라도 적어 두면 ②절의 중괄호 초기화는 더 이상 쓸 수 없고, 객체는 반드시 생성자를 거쳐서만 만들어진다. 만들 때 값을 빠뜨리면 컴파일이 안 되게 만드는 것이 생성자를 두는 이유다.

소멸자(destructor)는 객체가 사라질 때 자동으로 불리는 멤버 함수다. 이름은 클래스 이름 앞에 물결표를 붙인 ~RangeFilter()이고, 인자도 반환 타입도 없다. 객체가 들고 있던 것을 정리하는 자리다.

그러면 객체는 언제 사라지나. 중괄호 한 쌍이 만드는 범위를 스코프(scope)라고 한다. 스코프 안에서 만든 객체는 그 중괄호가 닫힐 때 사라진다. 이것이 객체의 수명(lifetime)이다. 한 스코프에서 여럿을 만들었으면 나중에 만든 것이 먼저 사라진다.

무엇을 먼저 볼지: 오른쪽 열이 「내가 부르나」다. 전부 「아니다」다.

언제무엇이 불리나내가 코드를 써야 하나
RangeFilter front(...)라고 쓴 줄생성자아니다. 만들면 자동이다
중괄호를 닫는 줄소멸자아니다. 나가면 자동이다
함수가 return하는 줄그 함수 안에서 만든 것들의 소멸자아니다
중간에 오류로 함수를 빠져나갈 때소멸자 (그래도 불린다)아니다
해석: 마지막 줄이 이 문법의 값어치다. 오류가 나서 중간에 튀어나가도 소멸자는 불린다. 정리하는 일을 사람이 기억하지 않아도 되게 만드는 것이 C++의 사고방식이고, 10회에서 이것만 따로 다룬다.

④ 멤버 초기화 리스트 — 생성자 본문에서 대입하지 않는다 🔴 사람이 한다

개념 — 초기화와 대입은 다른 일이다

변수를 만들면서 값을 넣는 것이 초기화(initialization)이고, 이미 있는 변수에 값을 넣는 것이 대입(assignment)이다. float x = 1.0f;는 초기화이고, 그다음 줄의 x = 2.0f;는 대입이다.

생성자에는 멤버 변수를 초기화하는 전용 자리가 있다. 생성자의 인자 목록과 본문 사이, 콜론 뒤에 멤버 이름과 값을 나열하는 것이고, 이것을 멤버 초기화 리스트(member initializer list)라고 한다. 

클래스이름(인자들)
: 멤버1_(값), 멤버2_(값), 멤버3_(값)     // ← 멤버 초기화 리스트. 멤버를 만들면서 값을 넣는다
{
  // 본문. 여기서 멤버에 = 로 넣는 것은 대입이다 — 멤버는 이미 만들어진 뒤다
}

생성자 본문이 시작되는 시점에 멤버 변수는 이미 다 만들어져 있다. 그래서 본문에서 name_ = name;이라고 쓰면 name_은 빈 문자열로 한 번 만들어진 뒤 그 위에 값이 덮어씌워진다 — 두 번 일한다. 멤버 초기화 리스트에 name_(name)이라고 쓰면 처음부터 그 값으로 만들어진다 — 한 번에 끝난다.

어느 쪽으로 써도 컴파일되고 출력도 같다. 그래서 AI가 아무 쪽이나 고르고, 사람이 읽어야만 잡힌다. 「항상 멤버 초기화 리스트」를 규칙으로 두면 const 멤버나 참조 멤버처럼 대입 자체가 안 되는 경우를 따로 기억할 필요가 없다.

#include <iostream>
#include <string>

struct Assigned {          // 생성자 본문에서 대입한다 — 빈 문자열을 만든 뒤 덮어쓴다
  std::string name_;

};
struct Initialized {       // 멤버 초기화 리스트 — 값을 넣은 채로 한 번에 만든다
  std::string name_;
  explicit Initialized(const std::string & n) : name_(n) {}
};

template<typename T>
double measure(const char * label, int loops)
{
  const std::string src("velodyne_lidar_front_left_link");   // 짧은 문자열 최적화를 넘기는 길이

  for (int i = 0; i < loops; ++i) {
    T obj(src);
    sink += obj.name_.size();
  }
  const auto t1 = std::chrono::steady_clock::now();
  const double ms = std::chrono::duration<double, std::milli>(t1 - t0).count();

}

개념 — 누가 멤버를 건드릴 수 있는지 정한다

클래스 안의 public:과 private:는 접근 지정자(access specifier)다. 그 아래에 적은 멤버가 그 구역에 들어간다. public 멤버는 클래스 밖 어디서나 쓸 수 있고, private 멤버는 그 클래스의 멤버 함수 안에서만 쓸 수 있다. 밖에서 건드리면 컴파일이 막힌다.

struct와 class의 유일한 차이가 여기 있다 — 접근 지정자를 안 적었을 때 struct는 public, class는 private로 시작한다.

멤버 변수를 private에 두고 멤버 함수만 public에 두는 것을 캡슐화(encapsulation)라고 한다. 값을 바꿀 수 있는 코드가 이 클래스 안으로 한정되므로, 값이 이상해졌을 때 찾아야 할 범위가 프로그램 전체에서 파일 하나로 줄어든다. v1의 g_dropped가 가진 문제가 이것으로 사라진다. 밖에서 값을 읽기만 해야 할 때는 그 값을 돌려주는 짧은 멤버 함수를 하나 둔다. 이런 함수를 접근자(accessor)라고 한다.

무엇을 먼저 볼지: 오른쪽 열이 판단 기준이다.

구역무엇을 넣나판단 기준
public:생성자, 소멸자, keep_valid, 접근자 name()·dropped()밖에서 쓸 일이 있는 것만
private:name_, lo_, hi_, dropped_멤버 변수는 기본적으로 전부 여기

⑥ const 멤버 함수 — 멤버를 안 바꾼다는 약속 🟡 맡기되 검사

개념 — 7회의 const가 객체에도 적용된다

7회 ⑥절에서 const는 「안 바꾼다」는 약속이고 어기면 컴파일러가 막는다고 했다. 그때는 인자에 붙였다. 멤버 함수에도 붙일 수 있는데, 자리는 인자 목록 뒤다. 

int dropped() const { return dropped_; }   // ← 이 const: 「이 함수는 이 객체의 멤버를 안 바꾼다」

이것을 const 멤버 함수(const member function)라고 한다. 약속의 대상은 이 함수가 불린 객체다. 컴파일러는 이 약속을 두 방향으로 검사한다.

  • const 멤버 함수 안에서 멤버 변수를 바꾸면 컴파일이 안 된다.
  • const로 잡은 객체 — 예를 들어 const RangeFilter & f로 받은 인자 — 에서는 const 멤버 함수만 부를 수 있다. const가 없는 멤버 함수는 「바꿀지도 모르는 함수」라서 막힌다.

그래서 규칙은 한 줄이다. 멤버를 읽기만 하는 함수에는 const를 붙이고, 바꾸는 함수에는 안 붙인다. 붙일 수 있는데 안 붙이면 7회 규칙(읽기만 할 인자는 const &로 받는다)과 부딪치는 자리가 바로 생긴다. 아래에서 그것을 겪는다.

오늘 클래스의 멤버 함수를 이 규칙으로 나누면 이렇다.

멤버 함수멤버를 바꾸나const

name(), dropped()안 바꾼다 — 값을 돌려주기만 한다붙인다

무엇이 문제인가

discards qualifiers는 「const라는 한정자를 버리게 된다」는 뜻이다. f는 const로 잡혀 있는데 name()은 const 멤버 함수가 아니다. 컴파일러 입장에서 name()은 멤버를 바꿀지도 모르는 함수이므로, const 객체에서 부르게 둘 수 없다. 고칠 곳은 report가 아니라 클래스 쪽이다 — 읽기만 하는 함수라고 클래스에 적어 주면 된다.

#include <cmath>
#include <iostream>
#include <string>
#include <vector>

class RangeFilter
{
public:
  RangeFilter(const std::string & name, float lo, float hi)
  : name_(name), lo_(lo), hi_(hi)     // 멤버 초기화 리스트 — 만들면서 바로 값을 넣는다
  {
    std::cout << "[생성] " << name_ << " 필터 (" << lo_ << "~" << hi_ << " m)\n";
  }
  ~RangeFilter()
  {
    std::cout << "[소멸] " << name_ << " 필터, 버린 값 " << dropped_ << "개\n";
  }

  std::vector<float> keep_valid(const std::vector<float> & ranges) const   // 안 바꾼다고 약속했는데

    for (const float r : ranges) {
      if (std::isfinite(r) && r >= lo_ && r <= hi_) { good.push_back(r); }
      else { ++dropped_; }
    }
    return good;

「안 바꾼다」고 약속해 놓고 바꾸려 했으니 막혔다. 어느 쪽으로 틀려도 컴파일러가 잡아 준다는 것이 이 문법의 값어치다. AI에게 const를 붙이라고 시켰을 때 「붙일 수 없는 함수」가 나오면, 그 함수가 멤버를 바꾸고 있다는 뜻이다.

이렇게 말하면 된다

이 클래스에서 멤버를 바꾸지 않는 멤버 함수에 전부 const를 붙여 줘. 붙일 수 없는 함수가 있으면 고치지 말고 어느 멤버를 바꾸는지 알려 줘.

⑦ 헤더와 소스로 나눈다 — 클래스는 .hpp에, 함수 내용은 .cpp에 🟡 맡기되 검사

개념 — 클래스도 선언과 정의로 나뉜다

7회 ⑩절에서 함수 하나를 선언(헤더)과 정의(소스)로 나눴다. 클래스도 같은 규칙이다. 클래스 정의(class definition) — 어떤 멤버 변수와 멤버 함수가 있는지의 목록 — 는 헤더에 두고, 멤버 함수의 내용은 소스에 둔다. 헤더 안의 멤버 함수는 세미콜론으로 끝나는 선언이 된다.

소스에서 멤버 함수를 정의할 때는 어느 클래스의 것인지를 이름 앞에 밝혀야 한다. 7회 ⑧절의 범위 지정 연산자 ::가 그 자리다. 

// 헤더 (.hpp) — 목록
class RangeFilter
{
public:
  int dropped() const;                    // 선언. 세미콜론으로 끝난다
  // …
};

// 소스 (.cpp) — 내용
int RangeFilter::dropped() const { return dropped_; }   // RangeFilter:: 가 「이 클래스의 그 함수」라는 표시

헤더는 여러 소스가 #include하므로 같은 헤더가 한 파일에 두 번 들어오는 일이 생긴다 — 헤더 A가 C를 읽고 B도 C를 읽으면, A와 B를 둘 다 읽는 파일에 C가 두 번 들어온다. 클래스가 두 번 정의되면 redefinition 오류다. 그래서 헤더 맨 위아래에 포함 보호(include guard) 세 줄을 둔다. 「이 이름을 아직 못 봤으면 아래를 읽고, 이미 봤으면 통째로 건너뛰라」는 전처리기 지시문이다.

무엇을 먼저 볼지: 왼쪽 열이 헤더에 남는 것이다. 헤더 쪽이 짧아야 정상이다.

아래는 정면 거리의 최근 3개 평균을 내는 프로그램이다. 값이 하나 들어올 때마다 최근 값 목록에 넣고 평균을 찍는다. 측정 실패는 세어만 두고 건너뛴다. 오늘 프로그램의 v1처럼 클래스 없이 짰다. 이대로도 돌아간다.

연습문제 — 클래스 없이 짠 원본 (main.cpp + CMakeLists.txt)

빌드해서 돌리는 법: cmake -S . -B build && cmake --build build && ./build/running_mean

main.cpp
// 9회 연습문제 — 정면 거리의 이동 평균. 클래스 없이 짠 코드
#include <cmath>
#include <iostream>
#include <string>
#include <vector>

std::string g_label = "front_mean";   // 이 평균기의 이름
int g_window = 3;                     // 최근 몇 개를 평균 내나
std::vector<float> g_recent;          // 최근 값들
int g_skipped = 0;                    // 측정 실패라 건너뛴 개수

void add(float r)
{
  if (!std::isfinite(r)) { ++g_skipped; return; }
  g_recent.push_back(r);
  if (static_cast<int>(g_recent.size()) > g_window) { g_recent.erase(g_recent.begin()); }
}

float mean()
{
  if (g_recent.empty()) { return -1.0f; }
  float sum = 0.0f;
  for (const float r : g_recent) { sum += r; }
  return sum / g_recent.size();
}

int main()
{
  const std::vector<float> stream{0.90f, 0.85f, INFINITY, 0.80f, 0.70f, NAN, 0.60f};
  for (const float r : stream) {
    add(r);
    std::cout << g_label << ": 최근 " << g_recent.size() << "개 평균 " << mean() << " m\n";
  }
  std::cout << "건너뛴 값 " << g_skipped << "개\n";
  return 0;
}

이 코드를 오늘 프로그램이 v1에서 v7로 간 것과 같은 길로 고친다. 출력은 끝까지 같아야 한다. 직접 쳐도 되고 에이전트에게 시켜도 된다 — 단, 받은 코드에서 아래 항목이 전부 됐는지는 사람이 확인한다.

고칠 것오늘 어디서 했나확인하는 법
전역 변수 넷과 함수 둘을 클래스 RunningMean으로 묶는다②파일에 g_로 시작하는 이름이 없다
이름과 창 크기(window)는 생성자로 받는다③RunningMean fm("front_mean", 3);으로 만든다
생성자는 멤버 초기화 리스트를 쓴다④생성자 본문에 =가 없다
멤버 변수는 전부 private. 밖에서 읽을 것(개수·평균·건너뛴 수)은 접근자로⑤main에서 fm.recent_처럼 멤버 변수를 직접 읽는 줄이 없다
읽기만 하는 멤버 함수에 const⑥const RunningMean &로 받는 report 함수를 만들어도 빌드된다
헤더·소스로 나누고 CMakeLists.txt에 소스 둘⑦running_mean.hpp의 멤버 함수가 전부 세미콜론으로 끝난다. 포함 보호가 있다
이 코드의 전역 변수와 함수를 RunningMean 클래스로 묶어 줘. 이름과 창 크기는 생성자로 받고 멤버 초기화 리스트를 써 줘. 멤버 변수는 전부 private으로 하고, 개수·평균·건너뛴 수는 const 접근자로 열어 줘. 헤더와 소스로 나누고 CMakeLists.txt도 고쳐 줘. 출력은 지금과 같아야 하고, 한 항목 고칠 때마다 빌드가 되는지 확인해 줘.

이럴 때이렇게 말한다
전역 변수가 보일 때"함수 밖에 있는 전역 변수들을 클래스의 멤버로 옮겨 줘. 어떤 값이 어떤 함수와 짝인지를 기준으로 묶어 줘."
생성자가 이상할 때"생성자 본문에서 멤버에 대입하는 자리가 있으면 전부 멤버 초기화 리스트로 옮겨 줘. 선언 순서와 초기화 순서도 맞춰 줘."
멤버가 밖에 열려 있을 때"멤버 변수를 전부 private으로 옮기고, 밖에서 읽어야 하는 것만 const 접근자로 열어 줘."
const가 안 보일 때"멤버를 바꾸지 않는 멤버 함수에 전부 const를 붙여 줘. 붙일 수 없는 함수가 있으면 고치지 말고 어느 멤버를 바꾸는지 알려 줘."
클래스를 만들게 할 때"헤더(.hpp)와 소스(.cpp)로 나눠 줘. 헤더에는 선언만 넣고 포함 보호도 넣어 줘. CMakeLists.txt의 add_executable에 소스를 다 적어 줘."
빌드가 안 될 때"이 오류 전체를 붙일게. cmake 단계인지, 컴파일 단계인지, 링크 단계인지 먼저 알려 주고 고칠 곳을 짚어 줘."

✅ 오늘의 점검

조금 더 알아두면 시험 범위 아님

#pragma once — 포함 보호의 짧은 판 
#pragma once      // 이 한 줄이 #ifndef / #define / #endif 세 줄을 대신한다
class RangeFilter { ... };

요즘 컴파일러는 대부분 이것을 알아듣는다. 짧고, 이름을 짓지 않아도 되고, 이름이 겹칠 일도 없다. 다만 C++ 표준에 없는 것이라 여러 환경에서 빌드돼야 하는 라이브러리는 아직 #ifndef 방식을 쓴다. ROS 2 코드에서는 둘 다 보인다. 어느 쪽이든 있기만 하면 된다.

this — 멤버 함수 안에서 「이 객체」를 가리키는 포인터

②절에서 멤버 함수 안의 lo_는 「이 함수가 불린 그 객체의 것」이라고 했다. 그 객체를 가리키는 포인터에 이름이 있다 — this다. lo_라고 쓰는 것은 this->lo_를 줄여 쓴 것이다. 

int RangeFilter::dropped() const { return this->dropped_; }   // dropped_ 와 같은 뜻

평소에는 안 적는다. 인자 이름과 멤버 이름이 같을 때 구별하려고 적는 경우가 있는데, 멤버 이름 뒤에 밑줄을 붙이면 그럴 일이 없다. ROS 2 코드에서 this->create_subscription(...)처럼 보이면 「이 노드의」라고 읽으면 된다.

상속 — 다음 회차에서 만날 : public rclcpp::Node 
class LidarNode : public rclcpp::Node
{
public:
  LidarNode() : Node("lidar_node") { ... }
};

클래스 이름 뒤의 : public rclcpp::Node는 「이 클래스는 Node가 가진 것을 전부 물려받는다」는 뜻이다(상속). 생성자의 : Node("lidar_node")는 오늘 배운 멤버 초기화 리스트와 같은 자리다 — 멤버 대신 물려받은 쪽을 초기화하고 있다. 10회에서 상속만 따로 다룬다.
