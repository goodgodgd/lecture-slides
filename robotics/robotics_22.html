QoS와 콜백 처리 시간, 디버깅 도구

오늘 답할 질문
  1. 빌드도 되고 노드도 떴고 ros2 topic echo로 보면 값도 오는데, 내 노드의 콜백은 한 번도 안 불린다. 무엇을 보면 원인이 보이나?
  2. 센서 토픽은 왜 「다시 보내 주지 않는」 방식으로 보낼까? 받는 쪽은 그것을 코드 어디에서 맞추나?
  3. 콜백 하나가 처리하는 데 오래 걸리면 로봇에는 실제로 무슨 일이 생기나? 큐를 크게 잡으면 안전해질까?
  4. 콜백마다 로그를 찍으면 무엇이 문제이고, 무엇으로 바꾸나?
  5. 값이 시간에 따라 어떻게 변했는지, 방금 그 장면을 로봇 없이 다시 볼 수는 없나?

18회 ⑦절에서 「이름도 맞고 개수도 맞는데 안 붙는」 짝을 봤다. 그때는 ros2 topic pub에 옵션을 붙여 일부러 만든 것이라 「QoS는 22회에서 제대로」라고 미뤘다. 오늘은 그것을 우리 코드에서 만난다. 같은 패키지 turtle_drive에 센서처럼 거리를 보내는 노드 front_range를 더하고(v9), wall_stop이 그 거리를 받아 서게 바꾸면(v10) — AI가 흔히 주는 모양 그대로 구독을 만들었을 때 — 거북이가 출발조차 하지 않는다.

고친 뒤에는 콜백이 얼마나 오래 걸리는지 잰다(v11). 21회 ⑥절에서 콜백 안에서 기다리면 노드 전체가 멈추는 것을 봤다. 아주 멈추지는 않더라도 콜백이 느리면 무엇이 달라지는지를 거북이가 벽 앞에서 서는 자리로 확인한다. 그다음 콜백마다 찍던 로그를 정리하고(v12), 마지막으로 rqt_plot·ros2 bag·rviz2로 값을 보는 방법을 익힌다. 3부의 마지막 회차라 끝에서 15~22회에 쌓은 것을 한 표로 정리한다.

② QoS 정책 — Reliability · History와 Depth · Durability 🔴 사람이 한다

같은 토픽인데 왜 보내는 방식을 따로 정하게 했을까? 토픽마다 바라는 것이 다르기 때문이다. 속도 명령 「서라」는 하나라도 잃으면 곤란하다. 라이다 스캔은 초당 수십 장이 오고, 한 장을 잃으면 다음 장이 곧 온다 — 잃은 것을 다시 받느라 늦어지는 쪽이 더 곤란하다. 그래서 ROS 2는 토픽을 만들 때 어떤 방식으로 주고받을지를 설정 묶음으로 고르게 했다. 18회에서 이 묶음을 QoS(Quality of Service)라고 불렀다. QoS는 여러 정책(policy)으로 이루어지고, 이 과목에서 볼 것은 셋이다.

Reliability — 잃은 메시지를 다시 보내나

RELIABLE은 받는 쪽이 「받았다」고 확인해 주고, 확인이 안 온 메시지는 보내는 쪽이 다시 보낸다. 늦어지더라도 빠짐없이 가는 쪽이다. BEST_EFFORT는 한 번 보내고 끝이다. 네트워크에서 하나가 사라지면 그대로 사라진다. 대신 다시 보내는 일로 뒤 메시지가 늦어지지 않는다. 무선(Wi-Fi)으로 로봇과 노트북이 이어진 경우처럼 잃는 일이 실제로 생기는 곳에서 차이가 커진다.

History와 Depth — 밀린 메시지를 몇 개까지 쌓아 두나

20회 🆕에서 create_publisher(…, 10)의 10을 큐 깊이라고 했다. 정확히는 두 정책이다. History는 쌓는 방식이고, 보통은 KEEP_LAST(최근 N개만 둔다)다. 그 N이 Depth다. 받는 쪽 콜백이 아직 앞 메시지를 처리하는 동안 새 메시지가 오면 큐에 쌓이고, N개가 넘으면 가장 오래된 것부터 버린다. History를 KEEP_ALL로 두면 버리지 않고 다 쌓지만, 이 과목에서는 쓸 일이 거의 없다.

Durability — 늦게 온 구독자에게 지난 메시지를 주나

VOLATILE은 구독자가 붙은 뒤에 보낸 것만 준다. 대부분의 토픽이 이것이다. TRANSIENT_LOCAL은 보내는 쪽이 마지막 몇 개를 들고 있다가 나중에 붙은 구독자에게도 준다. 지도나 로봇 모양처럼 「한 번 보내 두고 잘 안 바뀌는」 토픽에 쓴다(4부에서 만난다). 오늘은 이름만 봐 둔다.

해석: 둘째 인자에 숫자 10만 주면 그 숫자는 Depth이고, 나머지 둘은 기본값 — RELIABLE · VOLATILE — 이 된다. 숫자 하나가 Reliability까지 정하고 있다는 것이 오늘의 함정의 씨앗이다. 오른쪽 열 SensorDataQoS는 rclcpp가 미리 만들어 둔 센서용 묶음이다(값은 rmw/qos_profiles.h의 rmw_qos_profile_sensor_data). 라이다·카메라 드라이버 대부분이 이 묶음이나 비슷한 best effort로 보낸다.

③ QoS 호환성 — Reliability와 Durability의 짝 🔴 사람이 한다

보내는 쪽과 받는 쪽이 QoS를 서로 다르게 골랐다면 어떻게 될까? ROS 2는 「보내는 쪽이 약속하는 것이 받는 쪽이 요구하는 것보다 같거나 강해야 붙는다」는 규칙으로 정한다. 「다시 보내 주겠다」(reliable)를 약속한 쪽은 「안 보내 줘도 된다」(best effort)를 요구하는 쪽과 붙을 수 있다. 거꾸로 「다시 보내 줘야 한다」를 요구하는 쪽에 「다시 안 보낸다」는 쪽은 붙을 수 없다.

보내는 쪽 (발행)받는 쪽 (구독)붙나
RELIABLERELIABLE붙는다
RELIABLEBEST_EFFORT붙는다 — 받는 쪽은 다시 보내 달라고 하지 않을 뿐이다
BEST_EFFORTRELIABLE안 붙는다 — 메시지가 하나도 안 간다
BEST_EFFORTBEST_EFFORT붙는다

Durability도 같은 모양이다. VOLATILE로 보내는 쪽에 TRANSIENT_LOCAL을 요구하면 안 붙는다. Depth는 짝을 따지지 않는다 — 양쪽이 각자 자기 큐 깊이를 갖는다. 둘째 줄(reliable을 best effort로 받는 짝)은 실제로 붙는다. turtlesim의 /turtle1/pose는 RELIABLE로 나오는데, 받는 쪽을 best effort로 정해 받아 보면 값이 온다.

🆕 이 명령에서 처음 나오는 것

ros2 topic echo --qos-reliability best_effort
18회에 topic pub에서 본 옵션을 받는 쪽에 붙인 것이다. echo는 보통 이 옵션 없이도 보내는 쪽에 맞춰 알아서 고른다(18회 ⑦절). 여기서는 「reliable 발행 + best effort 구독」 짝을 일부러 만들려고 붙였다.
해석: 그러면 받는 쪽은 늘 best effort로 두면 안전할까? 그 짝은 언제나 붙기는 한다. 다만 reliable로 오는 명령 토픽을 best effort로 받으면 잃은 메시지를 다시 받지 못한다. 그래서 규칙은 「받는 쪽은 보내는 쪽에 맞춘다」다 — 센서 토픽은 센서용 QoS로, 명령 토픽은 기본값으로. 누가 어떻게 보내는지는 ros2 topic info -v가 알려 준다.

새 파일 src/front_range.cpp — 생성자와 콜백
#include "sensor_msgs/msg/range.hpp"
  // …
  FrontRange()
  : Node("front_range")
  {
    // 센서 데이터용 QoS 로 발행한다 — best effort, 깊이 5 (실제 라이다·초음파 드라이버가 대개 이렇게 보낸다)
    range_pub_ = this->create_publisher<sensor_msgs::msg::Range>(
      "/turtle1/front_range", rclcpp::SensorDataQoS());
    pose_sub_ = this->create_subscription<turtlesim::msg::Pose>(
      "/turtle1/pose", 10,
      [this](turtlesim::msg::Pose::ConstSharedPtr msg) { on_pose(msg); });
  }
  // 자세가 올 때마다(초당 62.5번) 앞 벽까지 거리를 계산해 Range 메시지로 내보낸다
  void on_pose(turtlesim::msg::Pose::ConstSharedPtr msg)
  {
    sensor_msgs::msg::Range r;
    r.header.stamp = this->now();        // 이 값을 잰 시각
    r.header.frame_id = "turtle1";       // 거북이에 붙은 센서라는 뜻
    r.radiation_type = sensor_msgs::msg::Range::ULTRASOUND;
    r.field_of_view = 0.2;               // 앞쪽 0.2 rad(약 11도) 부채꼴
    r.min_range = 0.0;
    r.max_range = 16.0;                  // 창의 대각선(약 15.7 m)보다 조금 길게
    r.range = static_cast<float>(front_distance(*msg));
    range_pub_->publish(r);
  }

메시지 정의 안의 상수(uint8 ULTRASOUND=0)가 C++에서는 이렇게 클래스 안의 이름으로 보인다. 숫자 0을 직접 쓰는 것보다 뜻이 읽힌다.
static_cast<float>(…)
front_distance()는 double을, range 필드는 float32(float)를 쓴다. 정밀도가 줄어드는 변환이라 「알고 바꾼다」고 적어 둔 것이다.

launch 파일에도 front_range 노드를 한 덩어리 더해 셋이 함께 뜨게 했다(📄 상자). wall_stop은 아직 이 토픽을 안 쓰므로 거북이는 v8과 똑같이 움직인다.

// 22회 앞 거리 센서 — front_range v9 (9단계: 거북이 자세로 앞 벽까지 거리를 재서 센서처럼 best effort 로 발행한다)
#include <algorithm>
#include <cmath>
#include <limits>
#include <memory>

#include "rclcpp/rclcpp.hpp"
#include "sensor_msgs/msg/range.hpp"
#include "turtlesim/msg/pose.hpp"

class FrontRange : public rclcpp::Node
{
public:
  FrontRange()
  : Node("front_range")
  {
    // 센서 데이터용 QoS 로 발행한다 — best effort, 깊이 5 (실제 라이다·초음파 드라이버가 대개 이렇게 보낸다)
    range_pub_ = this->create_publisher<sensor_msgs::msg::Range>(
      "/turtle1/front_range", rclcpp::SensorDataQoS());
    pose_sub_ = this->create_subscription<turtlesim::msg::Pose>(
      "/turtle1/pose", 10,
      [this](turtlesim::msg::Pose::ConstSharedPtr msg) { on_pose(msg); });
    RCLCPP_INFO(this->get_logger(), "/turtle1/front_range 를 발행합니다");
  }

private:
  // 자세가 올 때마다(초당 62.5번) 앞 벽까지 거리를 계산해 Range 메시지로 내보낸다
  void on_pose(turtlesim::msg::Pose::ConstSharedPtr msg)
  {
    sensor_msgs::msg::Range r;
    r.header.stamp = this->now();        // 이 값을 잰 시각
    r.header.frame_id = "turtle1";       // 거북이에 붙은 센서라는 뜻
    r.radiation_type = sensor_msgs::msg::Range::ULTRASOUND;
    r.field_of_view = 0.2;               // 앞쪽 0.2 rad(약 11도) 부채꼴
    r.min_range = 0.0;
    r.max_range = 16.0;                  // 창의 대각선(약 15.7 m)보다 조금 길게
    r.range = static_cast<float>(front_distance(*msg));
    range_pub_->publish(r);
  }

  // 지금 바라보는 방향으로 곧장 가면 벽까지 몇 m 남았나 (20회 wall_stop 에서 옮겨 왔다)
  double front_distance(const turtlesim::msg::Pose & p) const
  {
    const double c = std::cos(p.theta);
    const double s = std::sin(p.theta);
    double d = std::numeric_limits<double>::infinity();
    if (c > 1e-6)  { d = std::min(d, (world_size_ - p.x) / c); }   // 오른쪽 벽
    if (c < -1e-6) { d = std::min(d, (0.0 - p.x) / c); }           // 왼쪽 벽
    if (s > 1e-6)  { d = std::min(d, (world_size_ - p.y) / s); }   // 위쪽 벽
    if (s < -1e-6) { d = std::min(d, (0.0 - p.y) / s); }           // 아래쪽 벽
    return d;
  }

  const double world_size_ = 11.0889; // turtlesim 창 한 변의 길이 (m)

  rclcpp::Publisher<sensor_msgs::msg::Range>::SharedPtr range_pub_;
  rclcpp::Subscription<turtlesim::msg::Pose>::SharedPtr pose_sub_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<FrontRange>());
  rclcpp::shutdown();
  return 0;
}

// 22회 벽 앞 정지 — v10 변형 (구독 QoS 를 큐 깊이 10 = 기본값으로 둔 판 · 빌드는 되는데 콜백이 한 번도 안 불린다)
#include <chrono>
#include <cstdint>
#include <memory>
#include <vector>

#include "rclcpp/rclcpp.hpp"
#include "geometry_msgs/msg/twist.hpp"
#include "sensor_msgs/msg/range.hpp"
#include "std_srvs/srv/set_bool.hpp"
#include "turtlesim/srv/set_pen.hpp"

using namespace std::chrono_literals;

class WallStop : public rclcpp::Node
{
public:
  WallStop()
  : Node("wall_stop")
  {
    // 파라미터를 선언한다 — 이름과 기본값. 타입은 기본값에서 정해진다 (1.0 이므로 double)
    this->declare_parameter("speed", 1.0);
    this->declare_parameter("wall_margin", 1.0);
    read_parameters();

    cmd_pub_ = this->create_publisher<geometry_msgs::msg::Twist>("/turtle1/cmd_vel", 10);
    range_sub_ = this->create_subscription<sensor_msgs::msg::Range>(
      "/turtle1/front_range", 10,
      [this](sensor_msgs::msg::Range::ConstSharedPtr msg) { on_range(msg); });
    enable_srv_ = this->create_service<std_srvs::srv::SetBool>(
      "~/enable",
      [this](const std_srvs::srv::SetBool::Request::SharedPtr req,
             std_srvs::srv::SetBool::Response::SharedPtr res) { on_enable(req, res); });
    pen_client_ = this->create_client<turtlesim::srv::SetPen>("/turtle1/set_pen");
    timer_ = this->create_wall_timer(100ms, [this]() { on_timer(); });
    RCLCPP_INFO(this->get_logger(), "speed = %.2f m/s, wall_margin = %.2f m", speed_, wall_margin_);
  }

private:
  // 파라미터의 지금 값을 읽어 멤버에 넣는다 — 생성자에서 한 번, 그 뒤로는 타이머가 부를 때마다
  void read_parameters()
  {
    speed_ = this->get_parameter("speed").as_double();
    wall_margin_ = this->get_parameter("wall_margin").as_double();
  }

  // /turtle1/front_range 가 올 때마다 불린다 — 받은 것을 들고 있기만 한다
  void on_range(sensor_msgs::msg::Range::ConstSharedPtr msg)
  {
    range_ = msg;
  }

  // ~/enable 서비스가 불릴 때마다 — 요청의 data 가 true 면 달리고 false 면 선다
  void on_enable(const std_srvs::srv::SetBool::Request::SharedPtr req,
                 std_srvs::srv::SetBool::Response::SharedPtr res)
  {
    enabled_ = req->data;
    res->success = true;
    res->message = enabled_ ? "주행을 켭니다" : "주행을 끕니다";
    RCLCPP_INFO(this->get_logger(), "~/enable 요청: %s", res->message.c_str());
  }

  // 타이머가 0.1초마다 부른다 — 판단하고 명령을 보낸다
  void on_timer()
  {
    if (!range_) {                   // 아직 거리를 한 번도 못 받았다
      return;
    }
    read_parameters();               // 밖에서(ros2 param set) 바뀌었을 수 있으니 판단 전에 다시 읽는다
    const double front = range_->range;   // 앞 벽까지 거리 — front_range 가 재서 보내 준 값
    const bool near_wall = front < wall_margin_;
    const bool stop = near_wall || !enabled_;   // 벽 앞이거나, 주행이 꺼졌으면 선다
    if (stop && !stopped_) {
      RCLCPP_INFO(this->get_logger(), "섭니다 — %s (앞 벽까지 %.2f m)",
                  near_wall ? "벽 앞" : "주행 꺼짐", front);
      change_pen();
    }
    stopped_ = stop;

    geometry_msgs::msg::Twist cmd;   // 여섯 칸이 전부 0 — 이대로 보내면 「서라」
    if (!stop) {
      cmd.linear.x = speed_;
    }
    cmd_pub_->publish(cmd);
  }

  // /turtle1/set_pen 에 다음 펜 색을 요청한다 — 다시 달리기 시작하면 그 색으로 선이 그려진다
  void change_pen()
  {
    if (!pen_client_->service_is_ready()) {   // 서버(turtlesim)가 아직 없으면 이번에는 건너뛴다
      RCLCPP_WARN(this->get_logger(), "/turtle1/set_pen 서비스가 아직 없습니다");
      return;
    }
    const PenColor c = pen_colors_[stop_count_ % pen_colors_.size()];
    ++stop_count_;

    auto req = std::make_shared<turtlesim::srv::SetPen::Request>();
    req->r = c.r;
    req->g = c.g;
    req->b = c.b;
    req->width = 5;                  // 선 굵기 (기본은 3)
    // 보내고 바로 돌아온다. 응답이 오면 spin 이 이 람다를 불러 준다
    pen_client_->async_send_request(
      req, [this, c](rclcpp::Client<turtlesim::srv::SetPen>::SharedFuture) {
        RCLCPP_INFO(this->get_logger(), "펜 색을 (%d, %d, %d) 로 바꿨습니다", c.r, c.g, c.b);
      });
  }

  double speed_ = 0.0;                // 파라미터 speed 에서 읽는다 (m/s)
  double wall_margin_ = 0.0;          // 파라미터 wall_margin 에서 읽는다 (m)
  bool stopped_ = false;
  bool enabled_ = true;               // ~/enable 서비스로 바뀐다. 처음에는 켜져 있다

  struct PenColor { std::uint8_t r; std::uint8_t g; std::uint8_t b; };
  const std::vector<PenColor> pen_colors_ = {{255, 70, 70}, {60, 220, 60}, {255, 210, 0}};   // 빨강 → 초록 → 노랑

  void on_timer()
  {

      return;

    read_parameters();               // 밖에서(ros2 param set) 바뀌었을 수 있으니 판단 전에 다시 읽는다

개념 — 처리 시간이 주기보다 길면

콜백이 조금 느리면 무엇이 달라질까? 20회 ②절의 규칙을 다시 적으면 — 기본 spin은 콜백을 한 번에 하나씩 부른다. 21회 ⑥절은 그 극단이었다. 콜백 안에서 응답을 기다리자 다른 콜백이 하나도 안 불리고 노드가 멈췄다. 오늘 보는 것은 멈추지는 않고 느리기만 한 경우다. 거리는 16 ms마다(초당 62.5번) 오는데 콜백 하나가 50 ms 걸린다면, 콜백이 하나를 처리하는 동안 세 개쯤이 더 도착한다.

구독 큐 깊이처리하는 동안 도착한 메시지는콜백이 다음에 받는 값
1가장 최근 하나만 남고 나머지는 버려진다최신 값 — 대신 사이 값들을 못 본다

100백 개까지 쌓인다큐에서 가장 오래된 것 — 쌓일수록 점점 옛날 값으로 밀린다

그래서 재야 할 것은 둘이다. 하나는 콜백 처리 시간 — 콜백 앞뒤의 시각 차이다. 6회에서 for문의 시간을 잴 때, 13회에서 직접 짠 for문과 STL을 비교할 때 쓴 std::chrono::steady_clock을 그대로 쓴다. 다른 하나는 받은 값의 나이, 보통 지연(latency)이라고 부르는 것이다. front_range가 header.stamp에 잰 시각을 적어 보냈으니, 콜백이 그 값을 손에 쥔 순간의 시각에서 빼면 「이 값이 몇 ms 묵었나」가 나온다.

메시지의 stamp(초 + 나노초 두 칸)를 rclcpp::Time으로 바꾼다. this->now()와 빼기를 할 수 있게 된다.
(시각 − 시각).seconds()
두 rclcpp::Time의 차이(rclcpp::Duration)를 초 단위 double로 꺼낸다. 1000을 곱해 ms로 찍었다. 같은 컴퓨터 안의 두 노드라 시계가 같아서 뺄 수 있다.
std::chrono::milliseconds(work_ms_)
정수를 「그만큼의 ms」라는 시간 값으로 만든다. 14회의 500ms는 숫자를 코드에 바로 적을 때 쓰는 모양이고, 변수에 든 숫자는 이렇게 감싼다.

⚠️ 처리 시간만 재면 늦음이 안 보인다

위 네 판 모두 처리 50.1 ms로 같다. 처리 시간만 찍었다면 깊이 100이 왜 벽에 닿았는지 알 수 없다. 차이를 보여 준 것은 나이(now() - header.stamp)였다. 받은 코드에 시간 측정이 있으면 무엇을 재고 있는지 본다 — 콜백 안의 시간인지, 데이터가 묵은 시간인지. ros2 topic hz(18회 ⑬ 6번)는 보내는 쪽의 주기를 보여 줄 뿐이라, 이 경우에도 62.5 Hz로 멀쩡하게 나온다.

빌드해서 돌리는 법: cd ~/ros2_ws && colcon build --packages-select turtle_drive && source install/setup.bash && ros2 run turtle_drive wall_stop --ros-args -p work_ms:=50 -p range_depth:=100

turtle_drive/src/wall_stop.cpp
// 22회 벽 앞 정지 — v11 (11단계: std::chrono::steady_clock 으로 콜백 처리 시간을 재고, 받은 값의 나이를 찍는다)
#include <chrono>
#include <cstdint>
#include <memory>
#include <thread>
#include <vector>

#include "rclcpp/rclcpp.hpp"
#include "geometry_msgs/msg/twist.hpp"
#include "sensor_msgs/msg/range.hpp"
#include "std_srvs/srv/set_bool.hpp"
#include "turtlesim/srv/set_pen.hpp"

using namespace std::chrono_literals;

class WallStop : public rclcpp::Node
{
public:
  WallStop()
  : Node("wall_stop")
  {
    // 파라미터를 선언한다 — 이름과 기본값. 타입은 기본값에서 정해진다 (1.0 이므로 double)
    this->declare_parameter("speed", 1.0);
    this->declare_parameter("wall_margin", 1.0);
    read_parameters();
    // 실험용 파라미터 둘 — 구독을 만들 때만 쓰므로 생성자에서 한 번만 읽는다 (둘 다 정수)
    this->declare_parameter("work_ms", 0);       // 거리 콜백 안에서 일부러 쉬는 시간 (ms)
    this->declare_parameter("range_depth", 5);   // 거리 구독의 큐 깊이 — SensorDataQoS 의 기본이 5
    work_ms_ = this->get_parameter("work_ms").as_int();
    const auto depth = this->get_parameter("range_depth").as_int();

    cmd_pub_ = this->create_publisher<geometry_msgs::msg::Twist>("/turtle1/cmd_vel", 10);
    // 센서처럼 best effort 로 오는 토픽이다 — 받는 쪽도 센서 데이터용 QoS 로 맞춘다
    range_sub_ = this->create_subscription<sensor_msgs::msg::Range>(
      "/turtle1/front_range", rclcpp::SensorDataQoS().keep_last(depth),
      [this](sensor_msgs::msg::Range::ConstSharedPtr msg) { on_range(msg); });
    enable_srv_ = this->create_service<std_srvs::srv::SetBool>(
      "~/enable",
      [this](const std_srvs::srv::SetBool::Request::SharedPtr req,
             std_srvs::srv::SetBool::Response::SharedPtr res) { on_enable(req, res); });
    pen_client_ = this->create_client<turtlesim::srv::SetPen>("/turtle1/set_pen");
    timer_ = this->create_wall_timer(100ms, [this]() { on_timer(); });
    RCLCPP_INFO(this->get_logger(), "speed = %.2f m/s, wall_margin = %.2f m, work_ms = %ld, range_depth = %ld",
                speed_, wall_margin_, work_ms_, depth);
  }

private:
  // 파라미터의 지금 값을 읽어 멤버에 넣는다 — 생성자에서 한 번, 그 뒤로는 타이머가 부를 때마다
  void read_parameters()
  {
    speed_ = this->get_parameter("speed").as_double();
    wall_margin_ = this->get_parameter("wall_margin").as_double();
  }

  // /turtle1/front_range 가 올 때마다 불린다 — 처리하고 들고 있는다. 처리 시간과 받은 값의 나이를 잰다
  void on_range(sensor_msgs::msg::Range::ConstSharedPtr msg)
  {
    const auto t0 = std::chrono::steady_clock::now();
    // 이 값은 몇 ms 전에 잰 것인가 — 지금 시각에서 메시지에 찍힌 시각을 뺀다
    const double age_ms = (this->now() - rclcpp::Time(msg->header.stamp)).seconds() * 1000.0;

    // 무거운 처리(필터·인식 등)를 흉내 낸다 — work_ms 만큼 쉰다. 기본값 0 이면 안 쉰다
    std::this_thread::sleep_for(std::chrono::milliseconds(work_ms_));
    range_ = msg;

    const auto t1 = std::chrono::steady_clock::now();
    const double took_ms = std::chrono::duration<double, std::milli>(t1 - t0).count();
    RCLCPP_INFO(this->get_logger(), "거리 %.2f m · 나이 %.1f ms · 처리 %.1f ms", msg->range, age_ms, took_ms);
  }

  // ~/enable 서비스가 불릴 때마다 — 요청의 data 가 true 면 달리고 false 면 선다
  void on_enable(const std_srvs::srv::SetBool::Request::SharedPtr req,
                 std_srvs::srv::SetBool::Response::SharedPtr res)
  {
    enabled_ = req->data;
    res->success = true;
    res->message = enabled_ ? "주행을 켭니다" : "주행을 끕니다";
    RCLCPP_INFO(this->get_logger(), "~/enable 요청: %s", res->message.c_str());
  }

  // 타이머가 0.1초마다 부른다 — 판단하고 명령을 보낸다
  void on_timer()
  {
    if (!range_) {                   // 아직 거리를 한 번도 못 받았다
      return;
    }
    read_parameters();               // 밖에서(ros2 param set) 바뀌었을 수 있으니 판단 전에 다시 읽는다
    const double front = range_->range;   // 앞 벽까지 거리 — front_range 가 재서 보내 준 값
    const bool near_wall = front < wall_margin_;
    const bool stop = near_wall || !enabled_;   // 벽 앞이거나, 주행이 꺼졌으면 선다
    if (stop && !stopped_) {
      RCLCPP_INFO(this->get_logger(), "섭니다 — %s (앞 벽까지 %.2f m)",
                  near_wall ? "벽 앞" : "주행 꺼짐", front);
      change_pen();
    }
    stopped_ = stop;

    geometry_msgs::msg::Twist cmd;   // 여섯 칸이 전부 0 — 이대로 보내면 「서라」
    if (!stop) {
      cmd.linear.x = speed_;
    }
    cmd_pub_->publish(cmd);
  }

  // /turtle1/set_pen 에 다음 펜 색을 요청한다 — 다시 달리기 시작하면 그 색으로 선이 그려진다
  void change_pen()
  {
    if (!pen_client_->service_is_ready()) {   // 서버(turtlesim)가 아직 없으면 이번에는 건너뛴다
      RCLCPP_WARN(this->get_logger(), "/turtle1/set_pen 서비스가 아직 없습니다");
      return;
    }
    const PenColor c = pen_colors_[stop_count_ % pen_colors_.size()];
    ++stop_count_;

    auto req = std::make_shared<turtlesim::srv::SetPen::Request>();
    req->r = c.r;
    req->g = c.g;
    req->b = c.b;
    req->width = 5;                  // 선 굵기 (기본은 3)
    // 보내고 바로 돌아온다. 응답이 오면 spin 이 이 람다를 불러 준다
    pen_client_->async_send_request(
      req, [this, c](rclcpp::Client<turtlesim::srv::SetPen>::SharedFuture) {
        RCLCPP_INFO(this->get_logger(), "펜 색을 (%d, %d, %d) 로 바꿨습니다", c.r, c.g, c.b);
      });
  }

  double speed_ = 0.0;                // 파라미터 speed 에서 읽는다 (m/s)
  double wall_margin_ = 0.0;          // 파라미터 wall_margin 에서 읽는다 (m)
  std::int64_t work_ms_ = 0;          // 파라미터 work_ms 에서 읽는다 (ms)
  bool stopped_ = false;
  bool enabled_ = true;               // ~/enable 서비스로 바뀐다. 처음에는 켜져 있다

  struct PenColor { std::uint8_t r; std::uint8_t g; std::uint8_t b; };
  const std::vector<PenColor> pen_colors_ = {{255, 70, 70}, {60, 220, 60}, {255, 210, 0}};   // 빨강 → 초록 → 노랑
  std::size_t stop_count_ = 0;        // 지금까지 선 횟수 — 다음 색을 고르는 데 쓴다

  rclcpp::Publisher<geometry_msgs::msg::Twist>::SharedPtr cmd_pub_;
  rclcpp::Subscription<sensor_msgs::msg::Range>::SharedPtr range_sub_;
  rclcpp::Service<std_srvs::srv::SetBool>::SharedPtr enable_srv_;
  rclcpp::Client<turtlesim::srv::SetPen>::SharedPtr pen_client_;
  rclcpp::TimerBase::SharedPtr timer_;
  sensor_msgs::msg::Range::ConstSharedPtr range_;   // 마지막으로 받은 앞 거리 (처음에는 비어 있다)
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  auto node = std::make_shared<WallStop>();
  rclcpp::spin(node);            // 타이머·구독 콜백은 이 안에서 불린다
  rclcpp::shutdown();
  return 0;
}

⑦ 로깅 — RCLCPP_INFO_THROTTLE · RCLCPP_DEBUG · --log-level (v12) 🟡 맡기되 검사

개념 — 로그 수준과 주기 제한

v11의 터미널은 읽을 수 있었나? 처리 0 ms일 때 1초에 63줄이 올라갔다. 10초면 600줄이고, 그 사이에 「섭니다」 한 줄이 묻힌다. 실물 로봇에서는 SSH로 붙은 터미널(28회)이 이 속도를 못 따라가기도 한다. 한 줄 찍는 데 드는 시간도 0은 아니다. 검증용으로 RCLCPP_INFO 한 줄의 앞뒤를 재 보니 평균 약 40 µs였고, 찍지 않은 판은 0.1 µs였다(같은 컨테이너, 출력을 파일로 보낸 경우 — 화면에 그리는 터미널은 더 느릴 수 있다). 초당 62번이면 작지만, 1 kHz로 오는 IMU 토픽이라면 1초에 40 ms를 로그에 쓰는 셈이다.

그래서 로그는 두 가지로 줄인다. 하나는 수준(severity)이다. 19회에 RCLCPP_INFO, 14회에 RCLCPP_ERROR, 21회에 RCLCPP_WARN을 썼는데, 그 아래에 DEBUG가 있다. 노드는 기본으로 INFO 이상만 찍으므로 DEBUG 줄은 평소에 안 보인다. 다른 하나는 주기 제한(throttle)이다. 같은 자리의 로그를 「N ms에 한 번만」 찍게 한다.

수준매크로기본으로 보이나쓰는 자리
DEBUGRCLCPP_DEBUG안 보인다콜백마다의 자세한 값 — 문제를 찾을 때만 켠다
INFORCLCPP_INFO · RCLCPP_INFO_THROTTLE보인다시작 설정, 상태가 바뀐 순간(「섭니다」), 1초 요약
WARN · ERRORRCLCPP_WARN · RCLCPP_ERROR보인다이상한 상황 — 이것도 콜백마다 나면 _THROTTLE을 붙인다

RCLCPP_DEBUG(로거, "형식", 값…)
모양은 RCLCPP_INFO와 같고 수준만 DEBUG다. 그 로거의 수준이 DEBUG로 내려가 있을 때만 찍힌다.
RCLCPP_INFO_THROTTLE(로거, 시계, 간격ms, "형식", 값…)
이 줄이 지난번에 찍힌 뒤 간격 ms가 안 지났으면 건너뛴다. 시간을 재려면 시계가 필요해서 둘째 인자로 노드의 시계를 넘긴다. WARN·ERROR·DEBUG에도 _THROTTLE판이 있다.
*this->get_clock()
get_clock()은 노드의 시계를 shared_ptr로 돌려준다. 매크로는 시계 객체 자체(참조)를 받으므로 *로 꺼내 넘긴다(11회 스마트 포인터의 *).
%zu
std::size_t 값을 찍는 형식 지정자다. %d로 찍으면 컴파일러가 경고한다.

// 22회 벽 앞 정지 — v12 (12단계: 콜백마다 찍던 로그를 RCLCPP_DEBUG 로 내리고, 요약은 RCLCPP_INFO_THROTTLE 로 1초에 한 번)
#include <chrono>
#include <cstdint>
#include <memory>
#include <thread>
#include <vector>

#include "rclcpp/rclcpp.hpp"
#include "geometry_msgs/msg/twist.hpp"
#include "sensor_msgs/msg/range.hpp"
#include "std_srvs/srv/set_bool.hpp"
#include "turtlesim/srv/set_pen.hpp"

using namespace std::chrono_literals;

class WallStop : public rclcpp::Node
{
public:
  WallStop()
  : Node("wall_stop")
  {
    // 파라미터를 선언한다 — 이름과 기본값. 타입은 기본값에서 정해진다 (1.0 이므로 double)
    this->declare_parameter("speed", 1.0);
    this->declare_parameter("wall_margin", 1.0);
    read_parameters();
    // 실험용 파라미터 둘 — 구독을 만들 때만 쓰므로 생성자에서 한 번만 읽는다 (둘 다 정수)
    this->declare_parameter("work_ms", 0);       // 거리 콜백 안에서 일부러 쉬는 시간 (ms)
    this->declare_parameter("range_depth", 5);   // 거리 구독의 큐 깊이 — SensorDataQoS 의 기본이 5
    work_ms_ = this->get_parameter("work_ms").as_int();
    const auto depth = this->get_parameter("range_depth").as_int();

    cmd_pub_ = this->create_publisher<geometry_msgs::msg::Twist>("/turtle1/cmd_vel", 10);
    // 센서처럼 best effort 로 오는 토픽이다 — 받는 쪽도 센서 데이터용 QoS 로 맞춘다
    range_sub_ = this->create_subscription<sensor_msgs::msg::Range>(
      "/turtle1/front_range", rclcpp::SensorDataQoS().keep_last(depth),
      [this](sensor_msgs::msg::Range::ConstSharedPtr msg) { on_range(msg); });
    enable_srv_ = this->create_service<std_srvs::srv::SetBool>(
      "~/enable",
      [this](const std_srvs::srv::SetBool::Request::SharedPtr req,
             std_srvs::srv::SetBool::Response::SharedPtr res) { on_enable(req, res); });
    pen_client_ = this->create_client<turtlesim::srv::SetPen>("/turtle1/set_pen");
    timer_ = this->create_wall_timer(100ms, [this]() { on_timer(); });
    RCLCPP_INFO(this->get_logger(), "speed = %.2f m/s, wall_margin = %.2f m, work_ms = %ld, range_depth = %ld",
                speed_, wall_margin_, work_ms_, depth);
  }

private:
  // 파라미터의 지금 값을 읽어 멤버에 넣는다 — 생성자에서 한 번, 그 뒤로는 타이머가 부를 때마다
  void read_parameters()
  {
    speed_ = this->get_parameter("speed").as_double();
    wall_margin_ = this->get_parameter("wall_margin").as_double();
  }

  // /turtle1/front_range 가 올 때마다 불린다 — 처리하고 들고 있는다. 처리 시간과 받은 값의 나이를 잰다
  void on_range(sensor_msgs::msg::Range::ConstSharedPtr msg)
  {
    const auto t0 = std::chrono::steady_clock::now();
    // 이 값은 몇 ms 전에 잰 것인가 — 지금 시각에서 메시지에 찍힌 시각을 뺀다
    const double age_ms = (this->now() - rclcpp::Time(msg->header.stamp)).seconds() * 1000.0;

    // 무거운 처리(필터·인식 등)를 흉내 낸다 — work_ms 만큼 쉰다. 기본값 0 이면 안 쉰다
    std::this_thread::sleep_for(std::chrono::milliseconds(work_ms_));
    range_ = msg;

    const auto t1 = std::chrono::steady_clock::now();
    const double took_ms = std::chrono::duration<double, std::milli>(t1 - t0).count();
    ++range_count_;
    // 콜백마다 찍는 자세한 줄은 DEBUG — 평소에는 안 보이고 --log-level 로 켤 때만 보인다
    RCLCPP_DEBUG(this->get_logger(), "거리 %.2f m · 나이 %.1f ms · 처리 %.1f ms", msg->range, age_ms, took_ms);
    // 사람이 읽을 요약은 INFO 로, 1000 ms 에 한 번만
    RCLCPP_INFO_THROTTLE(this->get_logger(), *this->get_clock(), 1000,
                         "받은 거리 %zu개 · 지금 거리 %.2f m · 나이 %.1f ms · 처리 %.1f ms",
                         range_count_, msg->range, age_ms, took_ms);
  }

  // ~/enable 서비스가 불릴 때마다 — 요청의 data 가 true 면 달리고 false 면 선다
  void on_enable(const std_srvs::srv::SetBool::Request::SharedPtr req,
                 std_srvs::srv::SetBool::Response::SharedPtr res)
  {
    enabled_ = req->data;
    res->success = true;
    res->message = enabled_ ? "주행을 켭니다" : "주행을 끕니다";
    RCLCPP_INFO(this->get_logger(), "~/enable 요청: %s", res->message.c_str());
  }

  // 타이머가 0.1초마다 부른다 — 판단하고 명령을 보낸다
  void on_timer()
  {
    if (!range_) {                   // 아직 거리를 한 번도 못 받았다
      return;
    }
    read_parameters();               // 밖에서(ros2 param set) 바뀌었을 수 있으니 판단 전에 다시 읽는다
    const double front = range_->range;   // 앞 벽까지 거리 — front_range 가 재서 보내 준 값
    const bool near_wall = front < wall_margin_;
    const bool stop = near_wall || !enabled_;   // 벽 앞이거나, 주행이 꺼졌으면 선다
    if (stop && !stopped_) {
      RCLCPP_INFO(this->get_logger(), "섭니다 — %s (앞 벽까지 %.2f m)",
                  near_wall ? "벽 앞" : "주행 꺼짐", front);
      change_pen();
    }
    stopped_ = stop;

    geometry_msgs::msg::Twist cmd;   // 여섯 칸이 전부 0 — 이대로 보내면 「서라」
    if (!stop) {
      cmd.linear.x = speed_;
    }
    cmd_pub_->publish(cmd);
  }

  // /turtle1/set_pen 에 다음 펜 색을 요청한다 — 다시 달리기 시작하면 그 색으로 선이 그려진다
  void change_pen()
  {
    if (!pen_client_->service_is_ready()) {   // 서버(turtlesim)가 아직 없으면 이번에는 건너뛴다
      RCLCPP_WARN(this->get_logger(), "/turtle1/set_pen 서비스가 아직 없습니다");
      return;
    }
    const PenColor c = pen_colors_[stop_count_ % pen_colors_.size()];
    ++stop_count_;

    auto req = std::make_shared<turtlesim::srv::SetPen::Request>();
    req->r = c.r;
    req->g = c.g;
    req->b = c.b;
    req->width = 5;                  // 선 굵기 (기본은 3)
    // 보내고 바로 돌아온다. 응답이 오면 spin 이 이 람다를 불러 준다
    pen_client_->async_send_request(
      req, [this, c](rclcpp::Client<turtlesim::srv::SetPen>::SharedFuture) {
        RCLCPP_INFO(this->get_logger(), "펜 색을 (%d, %d, %d) 로 바꿨습니다", c.r, c.g, c.b);
      });
  }

  double speed_ = 0.0;                // 파라미터 speed 에서 읽는다 (m/s)
  double wall_margin_ = 0.0;          // 파라미터 wall_margin 에서 읽는다 (m)
  std::int64_t work_ms_ = 0;          // 파라미터 work_ms 에서 읽는다 (ms)
  std::size_t range_count_ = 0;       // 지금까지 받은 거리 메시지 수
  bool stopped_ = false;
  bool enabled_ = true;               // ~/enable 서비스로 바뀐다. 처음에는 켜져 있다

  struct PenColor { std::uint8_t r; std::uint8_t g; std::uint8_t b; };
  const std::vector<PenColor> pen_colors_ = {{255, 70, 70}, {60, 220, 60}, {255, 210, 0}};   // 빨강 → 초록 → 노랑
  std::size_t stop_count_ = 0;        // 지금까지 선 횟수 — 다음 색을 고르는 데 쓴다

  rclcpp::Publisher<geometry_msgs::msg::Twist>::SharedPtr cmd_pub_;
  rclcpp::Subscription<sensor_msgs::msg::Range>::SharedPtr range_sub_;
  rclcpp::Service<std_srvs::srv::SetBool>::SharedPtr enable_srv_;
  rclcpp::Client<turtlesim::srv::SetPen>::SharedPtr pen_client_;
  rclcpp::TimerBase::SharedPtr timer_;
  sensor_msgs::msg::Range::ConstSharedPtr range_;   // 마지막으로 받은 앞 거리 (처음에는 비어 있다)
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  auto node = std::make_shared<WallStop>();
  rclcpp::spin(node);            // 타이머·구독 콜백은 이 안에서 불린다
  rclcpp::shutdown();
  return 0;
}

// 22회 앞 거리 센서 — front_range v9 (9단계: 거북이 자세로 앞 벽까지 거리를 재서 센서처럼 best effort 로 발행한다)
#include <algorithm>
#include <cmath>
#include <limits>
#include <memory>

#include "rclcpp/rclcpp.hpp"
#include "sensor_msgs/msg/range.hpp"
#include "turtlesim/msg/pose.hpp"

class FrontRange : public rclcpp::Node
{
public:
  FrontRange()
  : Node("front_range")
  {
    // 센서 데이터용 QoS 로 발행한다 — best effort, 깊이 5 (실제 라이다·초음파 드라이버가 대개 이렇게 보낸다)
    range_pub_ = this->create_publisher<sensor_msgs::msg::Range>(
      "/turtle1/front_range", rclcpp::SensorDataQoS());
    pose_sub_ = this->create_subscription<turtlesim::msg::Pose>(
      "/turtle1/pose", 10,
      [this](turtlesim::msg::Pose::ConstSharedPtr msg) { on_pose(msg); });
    RCLCPP_INFO(this->get_logger(), "/turtle1/front_range 를 발행합니다");
  }

private:
  // 자세가 올 때마다(초당 62.5번) 앞 벽까지 거리를 계산해 Range 메시지로 내보낸다
  void on_pose(turtlesim::msg::Pose::ConstSharedPtr msg)
  {
    sensor_msgs::msg::Range r;
    r.header.stamp = this->now();        // 이 값을 잰 시각
    r.header.frame_id = "turtle1";       // 거북이에 붙은 센서라는 뜻
    r.radiation_type = sensor_msgs::msg::Range::ULTRASOUND;
    r.field_of_view = 0.2;               // 앞쪽 0.2 rad(약 11도) 부채꼴
    r.min_range = 0.0;
    r.max_range = 16.0;                  // 창의 대각선(약 15.7 m)보다 조금 길게
    r.range = static_cast<float>(front_distance(*msg));
    range_pub_->publish(r);
  }

  // 지금 바라보는 방향으로 곧장 가면 벽까지 몇 m 남았나 (20회 wall_stop 에서 옮겨 왔다)
  double front_distance(const turtlesim::msg::Pose & p) const
  {
    const double c = std::cos(p.theta);
    const double s = std::sin(p.theta);
    double d = std::numeric_limits<double>::infinity();
    if (c > 1e-6)  { d = std::min(d, (world_size_ - p.x) / c); }   // 오른쪽 벽
    if (c < -1e-6) { d = std::min(d, (0.0 - p.x) / c); }           // 왼쪽 벽
    if (s > 1e-6)  { d = std::min(d, (world_size_ - p.y) / s); }   // 위쪽 벽
    if (s < -1e-6) { d = std::min(d, (0.0 - p.y) / s); }           // 아래쪽 벽
    return d;
  }

  const double world_size_ = 11.0889; // turtlesim 창 한 변의 길이 (m)

  rclcpp::Publisher<sensor_msgs::msg::Range>::SharedPtr range_pub_;
  rclcpp::Subscription<turtlesim::msg::Pose>::SharedPtr pose_sub_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<FrontRange>());
  rclcpp::shutdown();
  return 0;
}

import os

from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():
    params = os.path.join(
        get_package_share_directory('turtle_drive'), 'config', 'wall_stop.yaml')

    return LaunchDescription([
        Node(
            package='turtlesim',
            executable='turtlesim_node',
            name='turtlesim',
        ),
        Node(
            package='turtle_drive',
            executable='front_range',
            name='front_range',
            output='screen',
        ),
        Node(
            package='turtle_drive',
            executable='wall_stop',
            name='wall_stop',
            parameters=[params],
            output='screen',
        ),
    ])

$ ros2 run rqt_plot rqt_plot /turtle1/front_range/range

🆕 이 명령에서 처음 나오는 것

rqt_plot 토픽/필드
토픽 이름 뒤에 /필드를 붙여 숫자 필드 하나를 고르면, 그 값을 받은 시각을 가로축으로 그린다. 창의 Topic 칸에 같은 것을 적고 +를 눌러도 된다. 여기서는 Range의 range 필드를 골랐다.

창이 뜨는 순간에는 아직 다른 노드를 다 찾지 못해 인자로 준 토픽이 빠질 수 있다(18회 rqt_graph와 같은 이유). 그래프에 범례가 안 생기면 Topic 칸에 다시 적고 +를 누른다. rqt_plot은 echo처럼 보내는 쪽 QoS에 맞춰 받으므로 best effort 토픽도 그대로 그려진다. 아래는 rqt_plot을 연 뒤 wall_stop을 띄우고, 선 뒤에 ros2 param set /wall_stop wall_margin 0.5를 친 화면이다.

해석: 이 그림에서 읽을 것은 기울기와 꺾이는 자리다. 기울기가 일정하면 속도가 일정한 것이고, 꺾인 자리의 높이가 서는 거리다. 프로젝트에서 조향값을 그려 보면 이 선이 위아래로 떨리는지가 보이는데, 그것이 튜닝(21회 param set)의 단서가 된다. 그림을 읽고 판단하는 일은 에이전트에게 맡기기 어렵다 — 에이전트는 이 창을 볼 수 없다.

ros2 bag play 이름 --topics 토픽…
bag 안의 토픽 중 적은 것만 재생한다. 여기서는 /turtle1/front_range만 내보냈다. 기록해 둔 cmd_vel까지 재생하면 옛 명령과 지금 wall_stop의 명령이 같은 토픽에 섞인다.

wall_stop은 이것이 녹화인 줄 모른다. 2.47 m에서 「섭니다」 — 새 여유 거리대로 판단했다. 기록을 켰을 때 거북이는 이미 출발해 있어서 첫 값이 3.73 m다. set_pen 경고는 turtlesim이 없어서 나온 것이고, 21회에 service_is_ready()로 먼저 본 덕에 노드는 멈추지 않았다.

⚠️ 재생은 녹화다 — 거북이는 새 판단에 반응하지 않는다

로그를 끝까지 보면 「섭니다」 뒤에도 거리가 2.11 → 1.46 m로 계속 줄어든다. 녹화 속 거북이는 그때 여유 1.5 m로 달렸기 때문이다. 재생은 입력을 되풀이할 뿐, 우리 명령이 로봇을 움직여 다음 입력이 바뀌는 고리는 없다. 그래서 bag으로 확인할 수 있는 것은 「이 입력에서 언제 무엇을 판단하나」까지다. 그 판단으로 로봇이 실제로 어디서 서는지는 다시 로봇 앞에서 본다.

나이 16529.0 ms도 같은 이유다. 메시지의 stamp는 기록할 때의 시각이고 지금은 16.5초 뒤라서, 재생 중에는 나이가 뜻을 잃는다. 재생 시각에 맞추는 방법은 「조금 더 알아두면」에 있다.

24회부터는 라이다 /scan을 이렇게 기록한 파일로 받아 코드를 고치고(24·25·27회), HW6도 로봇 없이 기록 파일 한 프레임으로 한다. 로봇 앞에서 보내는 시간이 짧은 이 과목에서 「한 번 기록하고 여러 번 고친다」가 가장 큰 시간 절약이 된다.

~/bags 폴더에서 /turtle1/front_range 와 /turtle1/cmd_vel 을 wall2 라는 이름으로 ros2 bag record 해 줘. 내가 끝났다고 하면 Ctrl+C 로 멈추고 ros2 bag info 결과에서 토픽별 Count 와 Duration 을 알려 줘. 그다음 재생할 때는 --topics /turtle1/front_range 로 거리만 재생하는 명령을 알려 줘. 재생은 내가 직접 할게.

⑩ rviz2 — Fixed Frame과 Range 표시 🔴 그림은 사람이 읽는다

rqt_plot은 값이 언제 어땠는지를 보여 준다. 그런데 센서 값은 어디의 값이기도 하다. 라이다 점 360개가 로봇 주변 어디에 찍히는지는 시간축으로는 안 보인다. 공간에 그려 보는 도구가 rviz2다(ROS visualization). 메시지의 header.frame_id(17회)를 보고 「그 좌표계에서 이만큼」으로 그린다. 오늘은 시연으로 짧게 보고, 24·27회에서 라이다 점을 띄울 때 제대로 쓴다.

순서rviz2에서 하는 일오늘 고른 것
1rviz2를 띄운다터미널에서 rviz2
2왼쪽 Global Options → Fixed Frame — 화면의 기준이 되는 좌표계turtle1 — 메시지의 frame_id와 같게
3아래 Add → By display type → Range센서 메시지 타입에 맞는 표시를 고른다
4Range → Topic에 토픽 이름, 그 아래 Reliability Policy/turtle1/front_range · Best Effort

4번의 Reliability Policy는 처음에 Reliable로 되어 있다. 그대로 두면 오늘 ⑤절과 똑같은 일이 rviz2에서 일어난다 — 화면에 아무것도 안 그려지고, Range 옆 Status: Ok는 초록색 그대로이며, rviz2를 띄운 터미널에만 이 줄이 남는다.

  5. (4분) launch로 다시 띄우고 rqt_plot /turtle1/front_range/range를 연다. 거북이가 선 뒤 ros2 param set /wall_stop wall_margin 0.5 — 선이 한 번 더 꺾이는지 본다.

turtle_watch/src/wall_watch.cpp
// 22회 연습문제 — wall_watch 원본 (자세가 올 때마다 로그를 찍는다. QoS·처리 시간·throttle 이 없다)
#include <algorithm>
#include <memory>
#include "rclcpp/rclcpp.hpp"
#include "turtlesim/msg/pose.hpp"
class WallWatch : public rclcpp::Node
{
public:
  WallWatch()
  : Node("wall_watch")
  {
    pose_sub_ = this->create_subscription<turtlesim::msg::Pose>(
      "/turtle1/pose", 10,
      [this](turtlesim::msg::Pose::ConstSharedPtr msg) { on_pose(msg); });
  }
private:
  // 자세가 올 때마다 가장 가까운 벽까지 거리를 알린다. warn_distance_ 보다 가까우면 경고로 찍는다
  void on_pose(turtlesim::msg::Pose::ConstSharedPtr msg)
  {
    const double nearest = std::min(std::min(msg->x, world_size_ - msg->x),
                                    std::min(msg->y, world_size_ - msg->y));
    if (nearest < warn_distance_) {
      RCLCPP_WARN(this->get_logger(), "벽이 가깝습니다: %.2f m", nearest);
    } else {
      RCLCPP_INFO(this->get_logger(), "가장 가까운 벽까지 %.2f m", nearest);
    }
  }
  const double warn_distance_ = 1.5;  // 이보다 가까우면 경고 (m)
  const float world_size_ = 11.0889f;  // turtlesim 창 한 변의 길이 (m)
  rclcpp::Subscription<turtlesim::msg::Pose>::SharedPtr pose_sub_;
};
int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  auto node = std::make_shared<WallWatch>();
  rclcpp::spin(node);
  rclcpp::shutdown();
  return 0;
}

bag 재생 시각에 맞추기 — --clock과 use_sim_time

⑨절에서 재생 중 나이가 16,529 ms로 찍혔다. 메시지의 시각은 기록할 때의 시각이고, 노드의 now()는 지금 벽시계라서다. 재생할 때 --clock을 붙이면 bag이 /clock 토픽으로 녹화 속 시각을 내보내고, 노드를 use_sim_time 파라미터(모든 노드에 있다, 21회 param list)를 true로 띄우면 그 노드의 now()가 /clock을 따른다. 

$ ros2 run turtle_drive wall_stop --ros-args -p wall_margin:=2.5 -p use_sim_time:=true
$ ros2 bag play wall1 --topics /turtle1/front_range --clock
[INFO] [1792279384.680919898] [wall_stop]: 받은 거리 3개 · 지금 거리 3.70 m · 나이 -7.0 ms · 처리 0.0 ms
[INFO] [1792279385.704414727] [wall_stop]: 받은 거리 67개 · 지금 거리 2.88 m · 나이 -5.6 ms · 처리 0.0 ms
[INFO] [1792279386.232814630] [wall_stop]: 섭니다 — 벽 앞 (앞 벽까지 2.47 m)

나이가 0 언저리로 돌아왔다. 음수가 나오는 것은 /clock이 띄엄띄엄(값을 안 주면 초당 40번) 오기 때문에 노드의 「지금」이 메시지 시각보다 조금 뒤처져 있어서다. Gazebo 같은 시뮬레이터도 이 방식으로 시간을 준다 — 시뮬레이터를 쓰는 회차에서 use_sim_time을 다시 만난다.

QoS를 밖에서 바꾸기 — qos_overrides

21회 ros2 param list에 qos_overrides./parameter_events.publisher.reliability 같은 줄이 있었다. rclcpp는 발행자·구독자를 만들 때 QoS를 파라미터로 바꿀 수 있게 하는 장치를 갖고 있고, 그 이름이 이 모양이다. 다만 노드 코드에서 그 토픽에 대해 허락해 두어야(QosOverridingOptions) 바뀐다. 남이 만든 노드의 QoS가 안 맞을 때 코드를 안 고치고 맞추는 방법이지만, 이 과목에서는 우리 코드의 구독 QoS를 맞추는 것으로 충분하다.

콜백을 동시에 부르기 — 멀티스레드 실행기

기본 rclcpp::spin은 스레드 하나로 콜백을 하나씩 부른다(단일 스레드 실행기). rclcpp::executors::MultiThreadedExecutor를 쓰고 콜백 그룹을 나누면 느린 콜백이 도는 동안 다른 콜백이 다른 스레드에서 불릴 수 있다. 21회 ⑥절의 교착도 이것으로 피할 수 있다. 대신 두 콜백이 같은 멤버를 동시에 건드리는 문제(경쟁 상태)를 새로 다뤄야 한다. 이 과목의 노드는 콜백을 짧게 쓰고 단일 스레드로 두는 것을 기본으로 한다 — ⑥절의 결론 「처리 시간을 주기보다 짧게」가 먼저다.
