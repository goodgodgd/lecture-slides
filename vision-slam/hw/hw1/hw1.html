이 과제가 묻는 것
  1. 에이전트가 준 로더가 맞다는 것을 무엇을 돌려서 확인했나요?
  2. 규약을 정하지 않고 시작하면 무엇이 조용히 정해지나요?
  3. 통과하지 못한 시험이 있었다면 어디까지 좁혔나요?

왜 이걸 하나요

학기 내내 쓸 첫 모듈입니다. 여기서 만든 로더를 4회 점군 오버레이가 쓰고, 5회 재구성이 쓰고, 12회 첫 완주까지 그대로 씁니다. 여기가 흔들리면 뒤에서 무엇이 틀렸는지 가릴 수 없게 됩니다.

그런데 이 과제의 진짜 목적은 코드가 아닙니다. 파일을 읽는 코드는 에이전트가 몇 분이면 만들어 줍니다. 문제는 그 코드가 맞는지를 어떻게 아느냐이고, 이 과제가 훈련하는 것이 그것입니다.

에이전트에게 시키는 것을 전제로 합니다. 오히려 그렇게 하세요. 대신 무엇을 요구했고, 받은 것에서 무엇을 확인했고, 무엇을 고쳤는지를 적습니다. 점수가 되는 자리가 거기입니다 — 제출 양식의 마지막 칸입니다.

무엇을 내나요 — 셋이 한 묶음입니다

#무엇어디에
1코드 — EurocSource와 tests/의 시험 mvins 저장소에 hw1 태그를 달아 제출
2규약 문서 — config/conventions.md 같은 저장소 안. 이 과제의 절반입니다
3검증 보고 — 아래 양식 (A4 2~3장) PDF로 따로

⚠️ 저장소는 하나만 만들고 학기 내내 씁니다

과제마다 새 폴더를 만들지 않습니다. mvins 저장소 하나에 계속 쌓습니다. 제출은 태그로 합니다 — git tag hw1 && git push origin hw1. 그래야 「HW1의 로더가 HW3에서 그대로 돈다」가 성립하고, 그게 이 과제들을 이렇게 자른 이유입니다.

작업 A — 규약 문서 사람이 한다

config/conventions.md를 만듭니다. 여섯 줄이 다 들어 있어야 합니다. 2회 자료 ⑦절에 그대로 복사해 쓸 수 있는 초안이 있습니다.

#정해야 하는 것안 정하면
①아래첨자 순서 — T_WB가 무슨 뜻인지 파일마다 반대로 곱한다. 궤적이 역방향으로 나온다
②몸체 프레임이 무엇인지 IMU 값을 어디에 붙일지가 안 정해진다
③카메라 축 방향 4회 투영이 통째로 어긋난다
④중력 방향과 크기 10회에서 궤적이 위아래로 휜다
⑤쿼터니언 관례와 파일 입출력 순서 회전이 반대로 합성된다
⑥시각을 어떻게 다루는지 구간마다 다른 오차가 조용히 들어간다

「아직 정하지 않은 것」 절을 반드시 넣으세요

지금 정할 수 없는 것이 있습니다 — perturbation 방향(3회)과 상태 벡터의 구성(10~11회)입니다. 정하지 않았다는 사실을 적어 두면 나중에 그 자리를 찾을 수 있습니다. 적어 두지 않으면 누군가가(대개 에이전트가) 조용히 정해 버리고, 그것이 어디서 정해졌는지 아무도 모르게 됩니다.

작업 B — 로더 구현 맡기되 검사한다

DataSource 인터페이스와 그 EuRoC 구현을 만듭니다. 아래 시그니처는 바꾸지 마세요. 인터페이스가 고정돼 있어야 뒤 회차에서 갈아 끼울 수 있고, 무엇보다 시험을 붙일 자리가 생깁니다. 

using Timestamp = int64_t;                       // 나노초

struct ImuSample  { Timestamp t; Eigen::Vector3d w, a; };
struct ImageFrame { Timestamp t; cv::Mat gray; };

struct NavState {
  Timestamp t;
  Sophus::SE3d    T_WB;
  Eigen::Vector3d v_W, b_g, b_a;
};

class DataSource {
 public:
  virtual ~DataSource() = default;
  virtual bool nextImage(ImageFrame&) = 0;
  virtual bool imuBetween(Timestamp t0, Timestamp t1, std::vector<ImuSample>&) = 0;
  virtual std::optional<NavState> groundTruth(Timestamp t) const = 0;   // 없으면 nullopt
  virtual CameraModel  camera()    const = 0;
  virtual ImuNoise     imuNoise()  const = 0;
  virtual Sophus::SE3d T_BC()      const = 0;
};

🆕 이 헤더에서 눈여겨볼 것

std::optional<NavState> groundTruth(Timestamp)
정답이 없는 시각에는 nullopt을 돌려줍니다. 0으로 채우거나 가장 가까운 값을 주지 않습니다 — 「없다」와 「0이다」는 다릅니다. 정답 궤적이 첫 영상보다 1.040초 늦게 시작하므로 이 경우가 실제로 생깁니다.
groundTruth()가 인터페이스에 있는 이유
평가 스크립트에서만 정답을 쓰면 「어느 모듈이 범인인가」를 못 가릅니다. 정답을 런타임에 꺼내 쓸 수 있어야 4회부터 쓸 검증 사다리 4단이 성립합니다.
Timestamp = int64_t
나노초 정수입니다. 이 자리에 double을 쓰지 않는 것이 작업 A ⑥번에서 정한 규약이고, 작업 C의 시험 하나가 이것을 봅니다.

데이터는 연습판(V1_01_easy의 첫 30초, 약 100 MB)으로 충분합니다. 전체를 받아도 되지만 반복 실행이 10배 느려집니다.

작업 C — 시험 여섯 개 사람이 한다

이 여섯 개가 이 과제의 통과 기준입니다. 전부 검증 사다리 1단(항등식 검사)이고, 통과 기준이 숫자로 정해져 있습니다. 기준을 넘으면 실패로 출력하게 만드세요 — 「오차가 작습니다」라고 찍는 시험은 시험이 아닙니다.

#무엇을 보나통과 기준여기서 걸리는 것
①영상 한 장 사이의 IMU 샘플 수 정확히 10개 — 전 구간에서 경계 조건, 시각 비교 부호
②정답이 없는 앞 구간에서 groundTruth() nullopt — 첫 1.040초 0으로 채웠다, 가장 가까운 값을 줬다
③첫 IMU 샘플의 가속도 크기 9.8104 m/s² ± 0.001 열 순서를 바꿔 읽었다 (각속도가 앞이다)
④읽어 들인 R_BC의 항등식 \(R^\top R = I\), \(\det R = 1\) — 오차 < 1e-12 행 우선/열 우선을 헷갈렸다
⑤R_BC를 축-각으로 바꿨을 때 각이 89.16° ± 0.05°, 축이 z에 가깝다 전치된 채 읽었다
⑥왕복 변환 T_BW(T_WB p) = p 오차 < 1e-12 역변환에서 \(-R^\top t\) 대신 \(-t\)를 썼다
①~③은 「데이터를 제대로 읽었나」이고 ④~⑥은 「코드가 제정신인가」입니다. 둘 다 필요합니다. 항등식만 통과하면 엉뚱한 파일을 읽고도 통과할 수 있고, ①~③만 통과하면 변환이 틀린 채로 넘어갑니다. ⑤번이 특히 값어치가 있습니다 — 숫자 아홉 개짜리 행렬을 사람이 읽을 수 있는 한 줄로 바꿔서 보는 것이라, 전치나 부호 실수를 즉시 잡아냅니다.

🤖 의뢰서 — 1회에서 본 여섯 칸을 그대로 씁니다

1회 🤖절의 여섯 칸(규약 · 인터페이스 · 참조 · 검증 · 함정 · 남긴다)을 채운 것입니다. 그대로 써도 되고, 고쳐 써도 됩니다. 다만 [검증] 칸을 지우지 마세요 — 그 칸이 이 과제에서 보는 자리입니다.

[규약] 첨부한 conventions.md의 표기와 부호 약속을 그대로 따라 줘. 코드 전체에서 그것만 쓴다.

[인터페이스] 아래 헤더의 시그니처를 바꾸지 말고 EuRoC ASL 형식을 읽는 EurocSource를 구현해 줘. (여기에 data_source.hpp 를 붙여 넣는다)

[단위] 시각은 int64_t 나노초로만 다뤄 줘. double 초로 바꾸지 말아 줘. 뺄셈은 정수로 하고, 나눌 때만 실수로 바꿔 줘.

[검증] 아래 여섯 시험을 같이 써 줘. 기준을 넘으면 실패로 출력한다.
① 영상 한 장 사이의 IMU 샘플 수가 전 구간에서 정확히 10개인가
② 첫 영상보다 앞선 시각에서 groundTruth()가 nullopt인가
③ 첫 IMU 샘플의 가속도 크기가 9.8104 ± 0.001 m/s²인가
④ R_BC가 RᵀR = I, det R = 1인가 — 1e-12
⑤ R_BC를 축-각으로 바꿨을 때 각이 89.16° ± 0.05°인가
⑥ T_BW(T_WB p) = p인가 — 1e-12
실패하면 어느 프레임에서 어떤 값이 나왔는지 함께 찍어 줘.

[함정] 압축을 풀면 __MACOSX/와 .DS_Store가 섞여 있다. 정답 궤적은 첫 영상보다 1.040초 늦게 시작한다. sensor.yaml의 T_BS는 행 우선 16개 숫자다 — Eigen의 기본은 열 우선이라 그대로 Map하면 전치된다.

[남긴다] 규약에 없어서 네가 임의로 정한 것이 있으면 코드 맨 위에 목록으로 적어 줘.

받은 코드에서 확인할 것 — 다섯 줄 다 눈으로 확인할 수 있는 것입니다.

□ 시각을 double 로 바꾼 곳이 정말 하나도 없는가        ← grep 한 번이면 된다
□ 요구한 시험 여섯 개가 실제로 있는가, 그리고 돌려 봤는가
□ 실패했을 때 프레임 번호와 값이 찍히는가              ← 안 찍히면 원인을 못 좁힌다
□ groundTruth() 가 없는 구간에서 정말 nullopt 인가, 0 을 채웠는가
□ 임의로 정한 것 목록에 내가 동의하지 않는 항목이 있는가

그리고 시험이 실패했을 때. 「고쳐 줘」라고 하지 않습니다.

영상 한 장 사이의 IMU 개수를 세는 시험이 2 137번 프레임에서 9개로 실패한다. 앞뒤 프레임은 10개다.
원인 후보를 세 개 대고, 각각을 확인할 수 있는 가장 작은 실험을 하나씩 제안해 줘. 코드는 아직 고치지 말아 줘.

⚠️ 함정 넷 — 미리 알려 드립니다

함정무슨 일이 생기나어떤 시험이 잡나
__MACOSX/와 .DS_Store macOS가 압축할 때 넣은 것들입니다. 영상 목록에 섞이면 파일 개수가 두 배가 되거나 읽을 수 없는 파일에서 멈춥니다 ①
정답이 1.040초 늦게 시작 그 구간을 0으로 채우면 첫 프레임부터 아무것도 안 맞습니다. 그런데 발산하지는 않아서 한참 뒤에 알게 됩니다 ②
double 초로 바꾸기 19자리를 15자리에 넣습니다. 위험한 것은 부정확해지는 것이 아니라 구간마다 다르게 부정확해지는 것입니다 — 잡음처럼 보입니다 —
grep으로 직접 봅니다
T_BS의 행 우선 / 열 우선 yaml은 행 우선, Eigen 기본은 열 우선입니다. 그대로 Map하면 전치된 행렬이 들어옵니다. RᵀR = I는 여전히 통과합니다 ⑤
마지막 줄이 이 과제에서 가장 볼 만한 자리입니다. 전치된 회전행렬도 여전히 회전행렬이라 항등식 시험을 전부 통과합니다. 축-각으로 바꿔 봐야만 축의 부호가 뒤집힌 것이 보입니다. 「시험을 어디에 놓느냐」가 시험의 일부라는 것이 이 한 줄에 들어 있습니다.

제출 방법과 채점

무엇어떻게
코드와 규약 저장소에 hw1 태그를 달고 주소를 보고서 맨 위에 적습니다
검증 보고 위 양식을 채워 PDF 한 개로. 파일 이름은 HW1_학번.pdf
